# 心晴情景聊天 V4 测试与交付报告

日期：2026-11-16（Asia/Shanghai）。本轮按功能原型交付，未制作新背景、人物或动画。

## 运行与验收

- **当前可用地址：http://127.0.0.1:5176/**，已保留浏览器页面，停在“妈妈催婚”，可直接继续输入。
- 入口：AI → 情景 → 选择分类、子类和卡片 → 开始练习 → 开始演练。
- 加号菜单：换一句、暂停/继续计时、重来、结束演练；浏览器具备既有 SpeechRecognition 能力时显示语音输入。未增加新的语音服务，未申请麦克风权限。
- 辅助回应仅填入草稿；可以编辑、换一句，必须主动发送。求助是独立方向提示，收起后继续对话。
- 结束演练生成复盘并保存；列表中的“查看记录”完整回放实发消息；刷新或关闭后可从“未完成演练”恢复。
- 本实例是独立端口、独立测试库。浏览器存储按来源隔离，5174 的原记录仍保留在原来源，没有迁移或覆盖。测试途中使用的 63087 实例已清理；其对话证据保存为本报告旁的 JSON 和截图。
- 当前实例已经运行，无需重复启动。日后需要重新启动时，在项目目录执行 `npm run build`、`npm run demo:v4`。默认只监听本机 5176；若端口被占用，不会停止占用端口的进程。可以用进程变量 V4_DEMO_PORT 指定另一个空闲端口。

## 审计后的增量修复

已有八类十卡、白板、人物占位、方案 B 和辅助/求助框架，因此继续复用。完整审计见 `情景聊天V4-审计与实施.md`。

1. **完整情景上下文**：沿用 `/api/ai/chat/completions` 和原 DeepSeek 调用，台词请求显式传 `contextMode: scenario-full`。后端不再按最近 19 条裁掉情景开场和早期消息；按原顺序保留唯一 system 与全部正式对话。其他任务保持原窗口和响应结构。
2. **容量明确失败**：完整模式最多 401 条请求消息、120000 字符，单条最多 6000 字符；超过容量返回 413，不偷偷减轮次。前端仍保留完整本机实发记录。当前输入保持既有 2000 字限制。
3. **旧服务兼容保护**：客户端检查完整模式回执；旧服务未实现时明确提示使用 V4 地址，不能在已丢上下文的情况下显示成功。
4. **取消与恢复**：增加直接“取消请求”按钮，向上游传递取消信号。已发消息保留，重试不重复追加；新输入不被迟到结果覆盖。高风险实发先暂存再进入安全页。
5. **辅助来源隔离**：保存/恢复 lastSuggestion；旧暂存也保守识别生成草稿，防止刷新后把未发送的 AI 建议当成用户意愿。
6. **历史保护**：显示所有已保存的新版记录，移除原有只展示 3 条、只保存/读取 30 条的裁剪；存储容量不足明确反馈，当前演练仍保留。损坏的未完成会话存储不会被新存储静默覆盖。
7. **人物事实边界**：初测发现模型有补充饭菜等生活细节的倾向，增加“已知事实/待确认提议”和开场边界。初测与复测原文分别保留，便于人工比较。

界面仍只投影最新 assistant 台词。用户输入进入正式 messages、模型上下文、暂存、历史和实发引用复盘，不生成用户侧气泡；展开“查看本次对话”时以文字记录展示。

- 初测与最终复测均对 **10 张卡**实际生成开场并完成两轮用户/对方交流；输出均通过角色正文和安全格式检查。
- 辅助回应实际经过生成和忠实度复核，成功换一句；求助和复盘均经真实模型返回。
