# 情景聊天 V4 审计与实施（2026-11-16）

本文件在本轮业务代码修改前建立。当前目录及父目录不含 Git 仓库，`git status --short` 返回 not a git repository；不能声称工作树干净。本轮拟改文件原样保存在 `tmp/scenario-v4-review-baseline/`，已有 V4 代码视为用户现有工作，增量修复。

## 已有功能

- `scenarios.ts`：八类（家庭、职场、亲密关系、朋友、自我、消费、照护、数字），10 张可练卡片；其余子类标记“语料收集中”，不冒充可用情景。
- `practice.ts`：10 张卡独立人物身份、关系、背景、性格、初始情绪、行为倾向、开场规则；共享现有人物 PNG 和白板，支持 side / stacked 两种布局。
- `presentation.ts`：仅投影最新 assistant 台词；正式 messages 数组独立保存全部实发消息，无用户侧聊天气泡；完整文字记录可展开。
- `dialogue.ts`：C-001 方案 B；真实模型开场；人物独立提示，随事件调整情绪，禁止固定轮数动作。辅助单句草稿、求助策略、实发编号引用复盘。
- `assist.ts`：辅助单句校验、真实模型忠实度复核、取消与过期草稿保护；建议必须主动发送。
- `index.ts` / `practice-session.mjs` / `history.mjs`：实发即暂存、未完成会话恢复、完成后复盘与本机历史。复用已有语音识别能力。
- `web/kernel/api.ts` → `/api/ai/chat/completions` → `prepareCompletionMessages` → `deepseekComplete` → 现有 DeepSeek 地址和模型。日常陪伴独立 `/api/chat`。

## 缺口及修复范围

1. 后端最多 19 条历史：第十次发言开场被截，之后丢首轮事实。需在 `completion-messages.mjs` / `server.mjs` 增加显式 `scenario-full` 模式，原接口路径及模型不变，保留全序列、严格容量校验。`api.ts` 和情景调用传入选项，其他请求保持旧行为。该后端改动是完整上下文要求所必需。
2. 暂存未保存 lastSuggestion，刷新后可能把未编辑的 AI 草稿误当用户意愿；在 `practice-session.mjs`、`index.ts` 修正并回归验证。
3. 无直接取消按钮；高风险实发进入安全页前需先持久化。补明确取消和保留/重试状态，保持旧消息。
4. 历史只展示最近 3 条，需提供更多已保存记录入口；存储损坏/容量失败不能静默覆盖。
5. 无本轮真实服务验收证据，需要实际八类开场、连续对话、辅助/求助/复盘、浏览器截图和报告。
