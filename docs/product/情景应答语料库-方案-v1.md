# 情景应答语料库：方案 v1

日期：2026-11-14
用途：解决“AI 替用户说的话很生硬、不专业、不圆滑”的问题

---

## 1. 问题在哪

现在的情景聊天只有：

- 6 个场景
- 一个“替用户回应”的提示词

没有：

- 真实的人会怎么接
- 同一句话有哪几种说法
- 什么场合该软，什么场合该硬
- 哪些话听起来“正确”，但现实里说不出口

所以 AI 只能生成一种“标准答案式”的回应：

> “我知道公司有压力，但我这边项目从 2 个加到 5 个也是事实，我想把加薪这件事摆到桌面上谈。”

这句话没错，但不像一个真实的人在公司里会说的话。太直、太满、太像谈判课。

---

## 2. “圆滑”到底指什么

不是油滑，不是撒谎，不是讨好。

这里定义成五件事：

1. **给对方留面子**：不否定对方的人格、动机和处境。
2. **把自己的意思说到**：不绕到对方听不懂。
3. **留余地**：不把话说死，不逼对方当场表态。
4. **不委屈自己**：不是一味退让，也不是回家生闷气。
5. **能说出口**：短、口语、不需要背稿。

一句话：

> **圆滑不是把话说漂亮，是让双方都能下台，但事情还往前走。**

## 3. 语料库分三层

### 第一层：对方台词库

真实的人在那个场景里会说什么。

```json
{
  "id": "raise-001",
  "scenario": "work-raise",
  "relation": "直属领导",
  "power": "对方权力更高",
  "counterpart_line": "公司现在什么情况你不知道吗？先把手头的事做好。",
  "intent": "压回请求",
  "emotion": "不耐烦",
  "source": "职场沟通案例/影视台词",
  "level": "A"
}
```

### 第二层：应答策略库

同一句对方台词，至少有 3 种接法：

| 策略 | 适合 | 例子 |
|---|---|---|
| 接住+事实+请求 | 对方愿意听 | “我知道公司紧。我这边项目从 2 到 5，想约十分钟对齐一下。” |
| 给面子+边界 | 对方施压 | “您说得对，这时候提不合适。但我不想拖到年底，能不能先定个评估时间？” |
| 延迟+替代 | 对方当场逼 | “今天不方便没关系。那我把材料发您，您哪天方便我再来。” |
| 澄清+反问 | 对方甩锅 | “这部分我不太确定是不是我负责，咱们对一下分工？” |
| 拒绝+替代 | 对方越界 | “这个我接不了。但我可以把手上这部分先收尾。” |
| 自嘲+转场 | 气氛太紧 | “我这次可能有点冒失。不过这事我确实想弄明白。” |

### 第三层：句式零件库

不是整句，是可替换的零件：

- 接住：“我知道您现在也难”“这事儿换谁都不轻松”
- 给面子：“您这个考虑我理解”“您先说”
- 说事实：“我这边的情况是……”“我手上现在有……”
- 提请求：“能不能给我十分钟”“我想跟您对一下”
- 留退路：“您听完再定”“不方便的话我们再找时间”
- 守边界：“这个我接不了”“这句话我不接”
- 收尾：“今天先到这儿”“我按这个先试”

## 4. 运行时怎么用

不要一上来就微调模型。先做检索：

```text
用户输入对方台词
  ↓
按场景 + 意图 + 关键词，检索 3 条最接近的“对方台词”
  ↓
取出对应的 3 种应答策略和例句
  ↓
塞进提示词：只学结构和分寸，不照抄
  ↓
生成 1 句“替用户说的话”
```

提示词里要写：

> 下面是相似场景里真实的人怎么接。只参考结构、分寸和落点，不要照抄原句。

这样比“让模型自由发挥”稳定得多。

## 6. 质量 rubric

每条应答过五关：

| 检查 | 问题 |
|---|---|
| 面子 | 有没有让对方下不来台？ |
| 清楚 | 用户的意思有没有说到？ |
| 余地 | 有没有把话说死？ |
| 自己 | 有没有委屈自己？ |
| 口语 | 用户能不能直接说出口？ |

五条里有一条不过，就不进库。

## 7. 体量计划

先做 3 个场景：

1. 跟领导提加薪
2. 妈妈催婚
3. 伴侣冷暴力

每个场景：

- 20 条对方台词
- 每条 3 种应答
- 共 60 条应答

3 个场景 = **180 条**。

跑通后再扩到 10 个场景、600 条。
