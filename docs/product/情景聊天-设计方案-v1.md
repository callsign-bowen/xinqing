# 情景聊天：功能设计方案 v1

日期：2026-11-14
项目：心晴
状态：MVP v1 已实现（入口在 AI 页右上角，6 个情境，文字演练 + 复盘）

---

## 1. 一句话

**情景聊天是一个“角色反转”的练习场：用户演那个和他发生冲突的人，AI 用用户的立场回一句，让用户听到“我可以怎么接”，再挑哪句最像自己。**

它不是普通聊天，也不是话术生成器。

---

## 2. 目的

- 把“知道该怎么说”练成“真到现场说得出”。
- 给用户一个低风险、可以重来的对话环境。
- 练完把选择还给用户，不让他依赖 AI 替他活。

判断做成的标准不是“聊了多久”，是：

1. 用户敢不敢在现实里试一次。
2. 用户有没有找到一句自己的话。
3. 用户有没有更少反刍、更多行动。

---

## 3. 核心原则

1. **演练和复盘必须分开。**  
   演练时用户演对方，AI 替用户回应；复盘时 AI 跳出替身，变回诺。
2. **不打分、不排名。**  
   不说“你失败了”“你得分 60”。只给“最像你的一句、可以带走的一句、下次可以试什么”。
3. **用户随时能停。**  
   “结束演练”永远可见，不需要理由。
4. **不模拟虐待和创伤现场。**  
   “难缠”是施压、打断、转移话题，不是辱骂、威胁、暴力细节。
5. **不替用户决定。**  
   复盘给选项，不判对错；现实里做不做、怎么做，用户定。
6. **不制造依赖。**  
   不承诺“练完就能搞定”，不把 AI 写成“唯一懂你的人”。

---

## 4. 用户流程

```text
入口
  ↓
情景大厅：选类别 / 选情境
  ↓
场景设置：对方是谁、你想达到什么、难度、时长
  ↓
演练中：用户演对方，AI 替用户回应
  ↓
结束演练：AI 跳出替身
  ↓
复盘：最像你的一句 / 可以带走的一句 / 下次可以试
  ↓
再练一次 / 换个说法 / 保存 / 结束
```

## 5. 页面设计

### 5.1 入口

MVP 不新增第五个底部导航，先放在 AI 页右上角：

```text
[AI 助手 · Nuo]              [情景]
```

首页也可以放一张轻卡片：

```text
明天有难说的话？
先练一遍，再去说。    [去情景]
```

验证后再考虑把“情景”放到底部导航第二个。

### 5.2 情景大厅

```text
┌────────────────────────────┐
│ 情景聊天                    │
│ 先练一遍，再去说。            │
│                            │
│ [职场] [家庭] [亲密关系]      │
│ [朋友] [陌生人] [自定义]      │
│                            │
│ ┌────────────────────────┐ │
│ │ 跟领导提加薪             │ │
│ │ 把“我想要”说出口，不被“再等等”打发 │ │
│ │ 5 分钟 · 真实难度        │ │
│ │              [开始练习]  │ │
│ └────────────────────────┘ │
│                            │
│ 最近练过                    │
│ · 拒绝同事甩锅  昨天         │
└────────────────────────────┘
```

卡片信息：

- 标题
- 一句话目标
- 时长
- 难度
- “开始练习”

不做“热门榜”“连续打卡”“排行榜”。

### 5.3 场景设置

```text
场景：跟领导提加薪

你是谁：在这家公司做了两年
对方：直属领导，忙，习惯先否定
你想达到：把加薪说出口，不被一句“再等等”打发

难度  [温和] [真实] [难缠]
时长  [3 分钟] [5 分钟] [10 分钟]

[开始演练]
```

可编辑：

- 对方身份
- 关系
- 目标
- 难度
- 时长

默认：

- 难度：真实
- 时长：5 分钟
- 目标：说出口

安全提示：

> 这是演练，不是现实。说错了可以重来，随时可以停。

### 5.4 演练中

```text
┌────────────────────────────┐
│ 你演：领导 · AI 替你说 04:32 │
│                      [结束] │
├────────────────────────────┤
│ 你演的领导：现在？我一会儿还有个会。 │
│                            │
│ 替你说的版本：我知道你忙，我就占用五分钟，把加薪这件事说清楚。 │
├────────────────────────────┤
│ [用领导的口气说一句…    ] [→] │
│ [暂停] [重来] [求助]         │
└────────────────────────────┘
```

规则：

- 顶部必须写“你演：XX · AI 替你说”，不能只显示“Nuo”。
- 用户说的话是“对方”的台词；AI 说的是“替用户说的版本”。
- AI 不跳出来给建议，不分析用户。
- 用户说“等一下/你帮我”时，才短暂跳出，给一句提示，再回去。
- 计时到点不强制中断，只问“要结束了吗？”

“求助”不是给答案，是给方向：

> 可以先说结论，再给一个理由。  
> 对方转移话题时，把话拉回你的请求。

### 5.5 结束演练

点击“结束演练”后，先过一个过渡页：

```text
演练结束。

我先从角色里出来。
现在我不是领导，是诺。
```

这个过渡不能省。它能防止用户把“对方”的情绪带到复盘里。

### 5.6 复盘页

```text
演练结束

最像你的一句
“我知道公司有压力，但项目从 2 个到 5 个也是事实。”

可以带走的一句
“我想把加薪这件事摆到桌面上谈。”

下次可以试
“这周五能不能给我十分钟，把时间和幅度定一下？”

[再练一次] [换个说法] [保存] [结束]
```

只给三张卡，不打分。

复盘引用的是 **AI 替用户说的原话**，不是用户演对方的台词。  
不能泛泛说“你表现很好”。

可选加一句：

> 现实里打算什么时候用？

不强迫填。

### 5.7 历史

```text
情景记录

跟领导提加薪
昨天 · 真实难度
[再练一次]

拒绝同事甩锅
3 天前 · 温和难度
[再练一次]
```

历史只存：

- 场景
- 日期
- 难度
- 对话
- 复盘

不存分数、不排名。

## 6. 内容模型

```ts
type Scenario = {
  id: string
  category: 'work' | 'family' | 'intimacy' | 'friend' | 'stranger' | 'custom'
  title: string
  oneLine: string
  relation: string
  counterpartRole: string
  defaultGoal: string
  context: string
  openingLine: string
  difficulties: {
    gentle: { style: string; opening: string }
    realistic: { style: string; opening: string }
    tough: { style: string; opening: string }
  }
  safety: {
    avoid: string[]
    exitLine: string
  }
  debriefFocus: string[]
}
```

### MVP 6 个情境

1. **职场：跟领导提加薪**
2. **职场：拒绝同事甩锅**
3. **家庭：妈妈催婚**
4. **亲密关系：伴侣冷暴力**
5. **朋友：借钱不还，怎么开口要**
6. **亲密关系：想分手，但怕对方难受**

每个情境三档难度：

- **温和**：对方愿意听，最多转移一次话题。
- **真实**：对方会解释、打断一次、给模糊承诺。
- **难缠**：对方会施压、否定、转移责任，但不辱骂、不威胁、不涉及创伤细节。

## 7. 技术设计

### 7.1 前端

新增：

```text
web/features/scenario/
├─ index.ts        // 注册 feature
├─ page.ts         // 页面显示/隐藏、状态机
├─ lobby.ts        // 大厅与情境卡
├─ setup.ts        // 场景设置
├─ roleplay.ts     // 演练对话
├─ debrief.ts      // 复盘
├─ history.ts      // 本地历史
├─ prompts.ts      // 前端展示用的场景文案
└─ scenario.css    // 页面样式
```

`index.html` 新增：

```html
<section class="scenario-page" id="page-scenario" aria-label="情景聊天">
```

`boot.ts` 注册 `scenarioFeature`。

### 7.2 状态机

```ts
type ScenarioState =
  | { stage: 'lobby' }
  | { stage: 'setup'; scenarioId: string }
  | { stage: 'roleplay'; sessionId: string; scenarioId: string; difficulty: string; messages: Message[] }
  | { stage: 'debrief'; sessionId: string; debrief: Debrief }
```

只允许：

```text
lobby → setup → roleplay → debrief → lobby
```

演练中不能直接跳复盘，必须先“结束演练”。

### 7.3 API

建议新增三个接口，不复用普通 `/api/chat` 的 Nuo 人格：

```text
POST /api/scenario/start
  { scenarioId, difficulty, goal, duration }
  → { sessionId, scene, openingMessage }

POST /api/scenario/chat
  { sessionId, message, history }
  → { reply, riskLevel, stage }

POST /api/scenario/debrief
  { sessionId, history }
  → { did, strongestLine, nextTry, safety }
```

### 7.4 两套提示词

**演练提示词**（AI 替用户回应）：

- 用户演 `counterpartRole`，用对方的口气说话。
- AI 用第一人称“我”，替用户回应这个“对方”。
- 先接住一句，再说清立场、边界或请求。
- 每次给一个版本，1–3 句。
- 不攻击、不讨好、不替用户答应事情。
- 不编造用户的经历或现实生活。
- 对方辱骂/威胁时，不跟着吵，可以说“这句话我不接”。
- 不跳出替身，不分析用户，不给建议。

**复盘提示词**（诺）：

- 你已跳出替身，现在是诺。
- 只引用 AI 替用户说的原话，不引用用户演的对方台词。
- 不评分、不判对错。
- 输出三件事：最像你的一句、可以带走的一句、下次可以试什么。
- 三句都要短：前两句各一句，nextTry 只给一个版本。
- 高风险时停止复盘，回到安全流程。

### 7.5 数据存储

MVP 用 `localStorage` 存情景历史，避免动数据库：

```text
nuo.scenario.history.v1
```

只存在本机，提供“删除这条记录”。

后续再考虑服务端存储。

## 8. 安全设计

1. **高风险立即退出角色**  
   出现自伤、他伤、暴力、被控制信号，停止演练，走现有高风险兜底。

2. **不模拟虐待细节**  
   “难缠”只到施压、打断、否定、转移责任。

3. **不鼓励对抗**  
   目标是说清楚、守住边界，不是“吵赢”。

4. **不承诺结果**  
   不说“练完他一定会答应你”。

5. **不制造依赖**  
   不写“只有我懂你”“你只有在这里才安全”。

6. **随时可退出**  
   “结束演练”永远可见，不需要解释。

---

## 10. 怎么判断做成了

不看停留时长，看：

1. 完成率：开始演练 → 走到复盘的比例。
2. 行动率：练完 7 天内，用户自报“我现实里试了一次”的比例。
3. 再练率：同一情境练第二次的比例。
4. 安全：高风险是否正确退出；有没有角色串味。
5. 依赖：有没有出现“只有在这里才安全”的表达。

## 13. MVP v1 实现说明

已实现：

- 入口：AI 页右上角“情景”按钮
- 8 大类 + 子类筛选；没有语料的子类显示“正在收集”
- 6 个情境、3 档难度、3/5/10 分钟
- 大厅、设置、演练、结束过渡、复盘、最近练过
- 角色反转：用户演对方，AI 替用户回应
- 复盘三张卡：最像你的一句 / 可以带走的一句 / 下次可以试
- 历史保存在本机 `localStorage`
- 高风险时停止演练，转到安全卡片

实现方式：

- 前端：`web/features/scenario/`
- 没有新增后端接口，复用现有 `/api/ai/chat/completions`
- 演练和复盘用两套 system prompt，避免角色串味
- 复盘只引用 AI 替用户说的原话，不引用用户演的对方台词

已知缺口：

- 还没有语音
- 还没有自定义情境
- 历史只在本机
- 复盘的三张卡是模型生成，偶尔会不够具体
- **还没有接“情景应答语料库”，AI 替用户说的话仍主要靠提示词生成**
- “难缠”难度还没有人工逐条审过

语料库方案见：[情景应答语料库-方案-v1.md](情景应答语料库-方案-v1.md)  
第一批种子：[职场-提加薪-v1.jsonl](../../语料库/情景应答/职场-提加薪-v1.jsonl)

实测：

- `npm run build` 通过
- `npm test` 72 条通过
- 用无头浏览器跑过：大厅 → 设置 → 演练 → 复盘 → 历史

## 14. C-001 裁决后的待迁移说明（2026-11-14）

> 本节为**追加说明**，不修改上文。第 1–13 节是 MVP v1 的历史设计记录，保留用于对照。
> 本节只登记方向与待办，**没有修改产品代码**。

### 14.1 裁决

产品负责人已对 C-001 正式裁决：**采用方案 B**。

| 项 | 正式方向 |
|---|---|
| 角色 | 用户演现实中的自己，AI 演情景中的另一方 |
| AI 生成依据 | 人物设定 + 情景背景 + 用户实际回应 + 当前情绪 |
| 辅助回应 | 生成一句第一人称、可直接使用的表达，**填入输入框**；可编辑、可重生成，**不得自动发送** |
| 求助 | 只给方向、策略、提示；与辅助回应是两个独立功能 |
| 双模式 | 不采用；原角色反转仅作历史实现与未来示范模式的参考 |

### 14.2 与本文件前文的差异

| 前文（MVP） | 方案 B 下 |
|---|---|
| 第 1 节：“用户演那个和他发生冲突的人，AI 用用户的立场回一句” | 反转为：AI 演对方，用户回自己 |
| 第 3 节第 1 条：“演练时用户演对方，AI 替用户回应” | 改为“演练时 AI 演对方，用户演自己” |
