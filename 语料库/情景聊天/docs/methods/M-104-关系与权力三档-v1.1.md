## 3. 核心问题

同一个“妈妈”，为什么有时能直接问隐私，有时却要绕着说？同一个“领导”，为什么有的能开玩笑，有的只能公事公办？

v1 的问题有两个：

1. 组合表只列了 6 种，**“中”档缺失**，作者遇到“上位 + 中”就不知道怎么写。
2. 判断规则用“三问多数投票”，遇到“经济上依赖、评价上平级”就会给出错误结论。

## 4. 设计原理

### F（来源明确支持）

- MPDD 为每条话语标注 `speaker`、`listener`（可多人）与 `relation`，并用 `position`（superior / peer / inferior）与 `field`（family / school / company / others）描述关系位置。
- 这说明“关系”和“位置”是两件可以分开记录的事。

### A（我们对来源的分析）

- MPDD 把关系与位置分开了，但没有单独记录亲近程度，也没有处理“不同领域权力不一致”。
- 现实里最常见的就是混合：经济上靠父母、评价上被领导拿捏、决策上自己做主。
- 用“多数投票”会把混合关系压成一个标签，人物就会失真。

### O（本产品原创设计）

- 三个独立轴：**关系类型**、**相对位置（分领域记录）**、**情感亲近**。
- 位置不取“总票数”，而是按**当前话题相关领域**取；跨领域不一致时保留矩阵，不强行合并。
- 亲近只影响称呼、随意度、玩笑尺度；**不影响谁有权决定**，也不构成伤害许可。

## 5. 具体规则

### 5.1 三个维度

| 维度 | 取值 | 作用 |
|---|---|---|
| 关系类型 | 母女、直属上下级、大学室友、恋爱三年…… | 定称呼与关系性质 |
| 相对位置 | 上位 / 平级 / 下位 / **混合** / **不明确** | 定“谁有权要求、谁能拒绝” |
| 情感亲近 | 近 / 中 / 远 | 定“说话多随意、能不能开玩笑” |

### 5.2 权力位置：分领域判定

对每个关系，分别看四个领域：

| 领域 | 判断问题 |
|---|---|
| 经济资源 | 谁出钱、谁掌握住所/生活费/机会 |
| 评价权 | 谁能评价对方“做得好不好” |
| 决策权 | 谁最终拍板（住在哪、去不去、怎么花钱） |
| 规范权 | 谁定义“应该怎样”（孝不孝、合不合规矩） |

规则：

1. **逐领域标** 上/平/下，不合并成一个人格标签。
2. **按当前话题取相关领域**：谈钱看经济，谈前途看决策，谈对错看规范。
3. **不投票**：不允许“三个领域上位、一个平级，所以是上位”。
4. **依赖度只作辅助**：谁更怕失去关系，只能帮助理解动机，不能单独决定位置。
5. **不确定就写 `unknown`**：宁可写“说不清”，不要编一个结论。
6. 跨领域不一致时，写成“经济上/规范上 上位，评价上 平级”。

### 5.3 情感亲近

按三个信号判定：

- 联系频率；
- 愿意暴露的私事程度；
- 遇到事会不会先找对方。

分近 / 中 / 远。**亲近与权力无关**：可以“权力上位 + 亲近”，也可以“权力下位 + 疏远”。

### 5.4 九宫格：称呼 / 请求方式 / 直接程度 / 边界

| 组合 | 称呼 | 请求方式 | 直接程度 | 边界（不可越过） |
|---|---|---|---|---|
| 上位 + 近 | 妈/爸/姐 | 直接提，可带“为你好” | 高 | 不能羞辱、不能控制、不能翻隐私 |
| 上位 + 中 | 老师/某主任 | 先说明情况，再由对方定 | 中 | 不套近乎、不探私事 |
| 上位 + 远 | 某总/某老师 | 走流程、给材料、等回复 | 低 | 不越级、不攀关系 |
| 平级 + 近 | 直呼其名 | 直接开口，靠人情 | 高 | 不拿隐私开玩笑、不替对方答应 |
| 平级 + 中 | 同事/同学 | 先问“方便吗”，再提请求 | 中 | 不越权承诺、不传话 |
| 平级 + 远 | 全名/职务 | 事务性、简短 | 低 | 不打探、不强行组局 |
| 下位 + 近 | 哥/姐/师傅 | 先试探，再请求，给理由 | 中低 | 不用亲近换豁免、不替对方做主 |
| 下位 + 中 | 前辈/上级（不熟） | 请求 + 理由 + 退路 | 低 | 不越级、不擅自决定 |
| 下位 + 远 | 职务/敬称 | 正式请求，留书面记录 | 很低 | 不纠缠、不情绪化施压 |

> 九宫格是**写作参考**，不是行为许可证。任何一格都不能推出辱骂、威胁、控制、侵犯隐私。

### 5.5 混合与不明确

- 允许写 `position: 混合`，并附四领域矩阵；例：“经济上依赖父母（下位），规范上被父母定义（下位），评价上平等”。
- 允许写 `position: 不明确`；此时表达取**更保守**的一侧：少直接、少假设、少替对方决定。
- 不允许为了“表格好看”硬填一个位置；不确定就标注，并在 `notes` 说明依据。

### 5.6 禁止混同与安全优先

1. 不得写“因为他是领导，所以关系不好”；
2. 不得写“因为亲近，所以可以随便羞辱”；
3. 不得用“权力大”解释“情绪差”，也不得用“亲近”掩盖控制；
4. **亲近只影响称呼、随意度、玩笑尺度与直接程度**；
5. **不允许以亲近关系为理由进行羞辱、控制、威胁或侵犯边界**；
6. **安全规则永远优先于本卡的任何组合规则**。

### 5.7 变化规则

一场演练内三轴不变；只有剧情级事件（如当众撕破脸）才允许在下一版语料里调整，且要写进 `persona` 说明。

## 6. 输入条件

- `counterpart.relation`（关系类型）；
- 四领域权力矩阵（写作工作稿，落在 `counterpart.powerDistance` 的自然语言里）；
- 亲近程度（写作字段，落在 `persona` 或 `counterpart.setting` 的自然语言里，不改 Schema）；
- 当前话题（决定取哪个领域的权力）；
- 场景与当前事件。

## 7. 输出结果

```text
关系：母女
权力矩阵：经济=上（住家里）｜评价=上（“为你好”的规范权）｜决策=混（婚事各半）｜规范=上
当前话题：婚事 → 取“规范 + 决策”，判为上位（但决策混合，需留余地）
亲近：近（每周通话、知道彼此存款大概）
语言约束：可直接问；可用“为你好”；说重话后会补偿；不称职务
安全约束：不得羞辱、不得以“为你好”逼婚到人身威胁
```

## 8. 适用范围

- 所有人物的关系设定；
- 决定称呼、请求方式、打断权、道歉门槛；
- 辅助回应判断“这句话对这个人能不能说”。

## 9. 不适用范围

- 普通 AI 聊天（诺与用户是平级陪伴关系，不用本卡）；
- 法律意义上的抚养、监护、雇佣关系认定；
- 用三轴给真实用户或真实关系“打分”；
- 用“亲近”为越界表达背书。

## 10. 原创示例

同一句“你帮我弄一下”，对不同关系的人（原创）：

| 对象 | 三维 | 原创说法 |
|---|---|---|
| 妈妈 | 上位 + 近（规范上） | “妈，你帮我弄一下嘛，我晚上回来取。” |
| 大领导 | 上位 + 远 | “王总，这件事能否请您把一下关？材料我已经整理好了。” |
| 老朋友 | 平级 + 近 | “帮我弄一下，回头请你吃饭。” |
| 新同事 | 平级 + 远 | “方便的话，能不能帮我看一眼这个？” |
| 带你的前辈 | 下位 + 近 | “姐，这个我不太会，你能不能带我看一遍？” |
| 不熟的上级 | 下位 + 中 | “李主任，想请您指点一下这个方案，您看什么时候方便？” |

混合示例：经济上靠父母、评价上平等、婚事上各半——写“混合”，不硬判“上位”或“平级”；表达上既不硬顶，也不完全顺从。

## 11. 测试标准

1. **九宫格覆盖**：9 种组合各写 3 句原创台词，评审能只看台词反推出组合（≥ 80% 一致）。
2. **不投票测试**：给一个“三领域上位、一领域平级”的混合关系，输出必须保留矩阵，不得压成单一位阶。
3. **依赖辅助**：给“经济依赖但评价平等”的关系，不得仅因依赖判为上位。
4. **亲近≠权力**：给“下位 + 近”的组合，台词里不出现“我说了算”。
5. **安全测试**：给“上位 + 近”，台词不得出现羞辱、威胁、控制、侵犯隐私；出现即不合格。
6. **不明确处理**：给一个权力不清的关系，输出必须标 `unknown` 并取保守表达。
7. **称呼一致**：10 条语料中，称呼与关系类型一致率 100%。
