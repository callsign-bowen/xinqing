## 3. 核心问题

AI 怎么判断用户这句话“在做什么”，从而决定下一轮是接住、施压、退让，还是把话题拉回来？

v1.2 要防的是**语义越权**：

> 用户说“我希望你尊重我的决定”，这是边界表达；但把它直接翻成“母亲被冒犯，+1”，就是替母亲决定了她的感受。

## 4. 设计原理

### F（来源明确支持）

- CPED 为每条话语标注了 19 类对话行为（DA），包括提问、回答、拒绝、道歉、安慰、反讽等。
- 该标注证明：一句话除了内容，还有“功能”，且功能可以被稳定标注。

### A（我们对来源的分析）

- 19 类对研究够用，对写作和提示词太细：作者记不住，模型也容易标错。
- 功能是**说话人做了什么**，不是**听话人怎么感受**；两者之间隔着人物设定与关系。
- 把功能直接映射成情绪变化，会制造“所有母亲听到边界都会愤怒”的假规律。

### O（本产品原创设计）

- 六类 + 两个兜底，只描述“用户这句话在做什么”。
- 功能只作为 M-101 的**线索**；是否真的触发，由对方的 `persona`、核心诉求、触发点、关系权力与主观理解决定。
- 默认不触发（P5）；只有四问闸门通过，才可能产生 P1–P4。

## 5. 具体规则

### 5.1 六类定义与边界（不变）

| 类 | 定义 | 与相邻类的边界 | 示例（说话人：用户） |
|---|---|---|---|
| **试探 T** | 索取信息或态度，不附带要求 | 与施压：没有“你应该”，也没有评价 | “你到底怎么想的？” |
| **施压 P** | 要求、比较、归责，或暗示后果（不越界） | 与拒绝：施压是“要你做”，拒绝是“我不做” | “你今天必须给我个说法。” |
| **解释 E** | 说明原因、立场，为自己辩护 | 与安抚：解释关于“我”，安抚关于“你” | “我不是不想，是不想随便找。” |
| **拒绝 R** | 说不、设边界、给替代 | 与施压：方向相反，且不要求对方改变 | “今天先不聊这个。” |
| **安抚 S** | 承认对方感受、给台阶、降温 | 与解释：安抚不辩论事实 | “我知道你着急。” |
| **转移 D** | 换话题、收尾、拖延 | 与试探：转移不索取新信息 | “先吃饭吧，菜要凉了。” |

**边界判定顺序**（不变）：

```text
有明确要求/比较/归责？ → 施压
在说“我不”/设限？     → 拒绝
在解释自己？           → 解释
在接住对方？           → 安抚
在问但不要求？         → 试探
在换话题/收尾？        → 转移
两类打平/读不准？      → UNCERTAIN
以上都不像？           → OTHER
```

### 5.2 兜底状态（不变）

| 状态 | 触发条件 | 默认策略 | 禁止 |
|---|---|---|---|
| `OTHER` | 寒暄、玩笑、与当前话题无关的陈述 | 中性接话，不升级 | 不硬塞进六类 |
| `UNCERTAIN` | 两类打平、置信度低、语义模糊 | 复述/澄清/接住，一次为限 | 不升级、不替用户下结论 |

### 5.3 硬规则：功能 ≠ 心理理解

**用户表达的功能，不等于 AI 对方对这句话的心理理解。**

必须结合以下五项，才决定是否产生实际情绪触发：

1. 对方的人物特质（`persona.traits`）；
2. 对方的核心诉求（`surfaceWant` / `underlyingNeed`）；
3. 对方的触发点与恐惧（`triggers` / `fears`）；
4. 当前关系与权力背景（M-104）；
5. 对方对用户这句话的**主观理解**（M-112）。

同一句话，不同人物可以有完全不同的反应：

| 用户说 | 功能 | 人物 A（控制倾向、规范权上位） | 人物 B（退让倾向、怕冲突） |
|---|---|---|---|
| “妈，这件事我希望你尊重我的决定。” | 拒绝/边界 | 理解为“被挑战”，P3 → +1 | 理解为“孩子长大了”，P5 → 0 |
| “我知道你着急。” | 安抚 | 认为是敷衍，P5 → 0 | 感到被接住，P4 → −1 |

因此：

- **拒绝不必然升级**；
- **安抚不必然降温**；
- **施压不必然引爆**（对方可能退让，也可能暂时不接）；
- 功能只决定“这句话在做什么”，不决定“对方怎么感受”。

#### 5.3.1 正常拒绝 / 合理设限 / 实际越界

| 行为 | 定义 | 是否 P1 候选 |
|---|---|---|
| **正常拒绝** | 对对方要求的“不”，不攻击对方，也不阻断对方退路 | **否** |
| **合理设限** | 说明自己的边界、条件或后果（如“再问我会走”） | **否** |
| **实际越界** | 侵犯对方边界：辱骂、威胁、查隐私、替对方决定、阻断退路、控制社交 | **可能**（严重时直接进 safety） |

示例：

| 用户说 | 类型 | 是否 P1 |
|---|---|---|
| “今天不行，我明天帮你。” | 正常拒绝 | 否 |
| “这件事我不想谈，再问我会先走开。” | 合理设限 | 否 |
| “你不许跟别人说话。” | 实际越界（控制） | 可能是 P1 候选 |
| “你就是个废物。” | 实际越界（羞辱） | 直接 safety，不走 P1 |

**硬规则**：M-102 不得把正常拒绝或合理设限标成 P1；只有实际越界才可能进入 P1 候选，且最终是否触发仍由 M-101 裁决。

### 5.4 从功能到触发的四问闸门（默认不触发）

```text
第 1 问：这句话是否碰到了对方的触发点/恐惧？
   否 → P5（不触发）
   是 → 第 2 问
第 2 问：对方是否会把这句话理解成“针对自己”？
   否 → P5
   是 → 第 3 问
第 3 问：在当前关系与权力背景下，这个理解是否成立？
   否 → P5
   是 → 第 4 问
第 4 问：属于哪一类？
   边界/越界 → P1；核心恐惧 → P2；面子/比较/被要求/被忽视 → P3；
   真正感到被修复 → P4
```

四问都过，才把候选事件交给 M-101；否则一律 P5（delta=0，计数 +1）。

> **注意**：四问不过，只代表“这条功能线索没有通过”；**不代表 M-101 不能从其他合法来源发现触发**。M-101 仍可从内容（e2）、关系事件（e3）、修复事件（e4）独立判断。M-102 的否定结果不封锁 M-101。

### 5.5 标签如何影响下一轮（只给线索）

| 主类 | 给 M-101 的线索 | 默认动作 | 禁止 |
|---|---|---|---|
| 试探 | 可能触及“被追问”的敏感点 | 直接回答，或反问一次 | 不逼问、不连续追问 |
| 施压 | 可能触及“被要求/被比较” | 不接招；先接一句，再给边界 | 不跟着骂、不羞辱 |
| 解释 | 可能触及“被辩解/被推开” | 抓一个点回应，不逐条反驳 | 不逐句拆解用户 |
| 拒绝 | 可能触及“被否定/失控” | 依人物与关系选择施压或退让 | 不把拒绝自动当冒犯 |
| 安抚 | 可能触及“被敷衍/被可怜” | 视对方是否真的感到被接住 | 不把安抚自动当修复 |
| 转移 | 可能触及“被回避/被敷衍” | 拉回一次；第二次允许停 | 不反复拽回 |
| OTHER | 无 | 中性接话 | 不强行归类 |
| UNCERTAIN | 无 | 复述/澄清/接住 | 不升级 |

**注意**：上表“可能触及”只是线索，不是结论；是否触发由 5.4 的四问决定。

### 5.6 运行时对象（C-001 方案 B）

- 只对**用户实际发送的消息**打标；
- AI 对方的消息可标注意图用于语境，但不用于判断用户意图；
- 辅助回应：未发送不打标、不进历史、不触发 M-101、不改变 M-106 状态；发送后按最终文本重新打标；
- 标签只用于内部编排，不展示、不评分、不推断人格/动机/心理状态。

### 5.7 职责边界（M-102 vs M-101）

M-102 **可以**：

- 识别用户话语功能（六类 + OTHER/UNCERTAIN）；
- 提供候选触发线索（哪类事件可能被对方在意）；
- 给出功能判断结果与置信度；
- 标记“不确定”，触发中性策略。

M-102 **不可以**：

- 自行修改情绪强度；
- 自行产生最终 `triggerDelta` / `netDelta`；
- 自行修改 `consecutiveNoTriggerTurns`；
- 绕过 M-101 直接决定最终情绪状态；
- 用功能标签推断用户人格、动机或心理状态。

**M-101 是唯一最终裁决者**。M-102 的输出只是输入材料；M-101 可以采纳、降级或忽略。

## 6. 输入条件

- 用户这一句（必须是实际发送的文本）；
- 上一轮 AI 的话（判断“是不是在回答”）；
- 当前未闭合的问题（M-106）；
- 对方人物设定与关系背景（M-101 / M-104）；
- 当前情绪状态（仅用于理解语气，不用于反向推断功能）。

## 7. 输出结果

```text
{ primary: "拒绝", secondary: null, confidence: 0.8,
  fallback: null,
  triggerCheck: { hitTrigger: "P3?", reason: "对方可能理解为被挑战，待 M-101 四问确认" } }
```

只作为编排线索，不直接生成台词，不直接改情绪数值。

## 8. 适用范围

- 演练回合判定与分支选择；
- 辅助回应的意图识别；
- 语料写作时的功能检查。

## 9. 不适用范围

- 普通 AI 聊天；
- 法律、医疗、诊断类判断；
- 推断用户人格、动机、心理状态；
- 把标签当成用户可见的“沟通类型测试”；
- 把功能直接当情绪触发。

## 10. 原创示例（含说话人）

情景：妈妈催婚（原创，非数据集文本）。

| 说话人 | 台词（原创） | 主类 | 四问结果 | 是否触发 |
|---|---|---|---|---|
| 对方（AI） | “你到底怎么打算的？” | 试探 | 未碰触发点 | 否（P5） |
| 用户 | “妈，我希望你尊重我的决定。” | 拒绝 | 控制倾向+规范权上位 → 理解为被挑战 | 是（P3） |
| 用户 | “我知道你着急。” | 安抚 | 对方认为敷衍 | 否（P5） |
| 用户 | “今天先不聊这个。” | 拒绝 | 对方怕冲突，接受 | 否（P5） |
| 用户 | “今天挺冷的。” | OTHER | — | 否（P5） |

同一句“我希望你尊重我的决定”，若对方是“退让倾向、怕冲突”的人，四问第 2 问就不过，结果应为 P5，不得写成 +1。

## 11. 测试标准

1. **功能不等于触发**：同一句“拒绝”分别给两个不同人物设定，情绪结果必须不同（一个 P3、一个 P5）。
2. **安抚不等于修复**：同一句“我知道你着急”，对方认为敷衍时不得 −1。
3. **四问闸门**：20 条用户话语，人工标注“是否触发”，与四问结果一致率 ≥ 80%。
4. **兜底**：20 条模糊句，≥ 80% 判 `UNCERTAIN` / `OTHER`，不得强行分类。
5. **对象隔离**：未发送的辅助回应不产生标签（与 M-106 联合测试）。
6. **不重复计算**：功能标签本身不产生 delta；同一轮只允许 M-101 更新一次。
7. **说话人标注**：示例中说话人缺失率 = 0。
8. **正常拒绝不判 P1**：10 条正常拒绝（“今天不行”“我明天帮你”），P1 候选数 = 0。
9. **合理设限不判 P1**：10 条设限（“再问我会走开”），P1 候选数 = 0。
10. **实际越界可成候选**：控制、威胁、查隐私各 3 条，必须被标为“越界”并交 M-101 裁决；严重羞辱直接进 safety。
11. **线索不封锁**：构造“M-102 四问不过，但 M-101 从内容/关系事件发现触发”的案例，M-101 仍能更新；证明 M-102 不越权、也不封锁。
12. **职责越权检查**：M-102 输出中不得出现 `triggerDelta`、`netDelta`、`consecutiveNoTriggerTurns` 的修改值。

## 12. 版权边界

- 六类名称、定义、四问闸门、兜底规则均为原创。
- 未使用 CPED 的 19 类名称或定义；未复制任何对话。
- 来源保持 `research_only` / `pending`。
