### 版本变更记录（v1.1 → v1.2）

1. 把 **P5 从“中性触发”改为“无具体触发规则”**：P5 不再是一个事件，而是“本轮没有触发”的处理分支。
2. 引入内部状态 `consecutiveNoTriggerTurns`，并写明完整闭环：有触发归零、无触发 +1、连续两轮 −1、衰减后归零。
3. 明确“达到强度上下限时，仍记录触发事件”，避免边界处丢审计。
4. 区分四个概念：内部强度 `intensity`、效价 `valence`、唤醒度 `arousal`、冲突强度 `conflict`，禁止机械一一映射。
5. 明确 `conflict` 只描述冲突程度，不等于情绪强度。
6. Schema 保持不变，不新增字段。

### 版本变更记录（v1.2 → v1.2.1）

1. 拆分情绪变化变量：`triggerDelta`、`decayDelta`、`netDelta`，替换含义含混的单个 `delta`。
2. 给出完整伪代码与三个执行示例（正常触发、连续无触发衰减、上限边界）。
3. 明确衰减不得与触发变化叠加；`netDelta` 记录实际变化（边界处可为 0）。
4. 新增“情绪 label 是否允许转换”的 A/B 方案分析与推荐；**保留为待决策事项**，本版不引入转换规则。
5. 补充与旧 `delta` 字段的兼容说明；Schema 不变。

## 3. 核心问题

同一个人物，怎么做到既“始终是同一个人”，又“这一轮真的生气了”？

v1.1 解决了重复计算，但留下两个漏洞：

1. **衰减识别不了**：P5 既当“中性事件”又当“无事件”，连续两轮的判断没有可靠依据。
2. **强度被当成情绪的全部**：4/5 的愤怒、悲伤、焦虑被写成同一种东西。

## 4. 设计原理

### F（来源明确支持）

- CPED 为角色标注了稳定属性（姓名、性别、年龄段、Big Five）与逐条话语的情感极性、13 类情绪、19 类对话行为。
- CPED 的统计显示，平均每段对话出现约 2.8–3.4 种情绪，说明情绪在对话内确实会变。

### A（我们对来源的分析）

- CPED 只有“点”没有“线”：它标了每句话是什么情绪，但没有写“什么触发、升到多高、怎么回落”。
- 多标签并存（情绪 + DA + 人格）如果没有合并规则，就会在生成侧变成重复加权。
- “中性”和“没有事件”是两件事：前者是一种内容，后者是“这一轮什么都没发生”。

### O（本产品原创设计）

- 三层结构不变：**稳定人格层 → 动态情绪层 → 表达层**。
- 情绪层每轮只有一个入口：`primaryTrigger`；只有一个出口：一次 `delta ∈ {−1, 0, +1}`。
- 无触发不是一种触发，而是一个独立分支（P5），专门负责计数与衰减。
- 强度是“多大”，效价与唤醒度是“什么情绪、有多激动”，三者不互相替代。

## 5. 具体规则

### 5.1 三层与内部状态

| 层/状态 | 内容 | 是否随单轮变化 |
|---|---|---|
| 人格层 P | 3–5 个可观察特质、1–2 条价值观、1–3 个恐惧、2–4 个触发点、1–3 个降温点、voice 参数 | **不变** |
| 情绪层 E | `label`、`intensity`（1–5）、`primaryTrigger`、`sinceTurn` | 每轮最多变一次 |
| 无触发计数 | `consecutiveNoTriggerTurns`（整数，初始 0） | 每轮更新 |
| 表达层 X | 句长、称呼、反问/重复/沉默、策略选择 | 由 P、E、关系共同决定 |

> `consecutiveNoTriggerTurns` 是内部编排状态，**不写入 Schema、不新增字段**。

### 5.2 触发类别与 P5 的定位

| 规则 | 含义 | delta |
|---|---|---|
| P1 | 边界侵犯或越界（未达 safety 硬停） | +1 |
| P2 | 核心恐惧 / 触发点命中 | +1 |
| P3 | 面子、比较、被要求、被忽视 | +1 |
| P4 | **真正发生的**修复、被接住、收到具体安排 | −1 |
| **P5** | **本轮没有具体触发事件**（不是事件） | 0 |

**P5 不是候选事件**。它表示“这一轮没有可选事件”，不是“有一个中性事件”。

### 5.3 变量定义与唯一更新算法

#### 5.3.1 三个变量（替代单一 `delta`）

| 变量 | 含义 | 取值 |
|---|---|---|
| `triggerDelta` | 本轮**触发事件**造成的强度变化 | −1 / 0 / +1 |
| `decayDelta` | 本轮**无触发衰减**造成的强度变化 | −1 / 0 |
| `netDelta` | 本轮实际变化（更新后 − 更新前） | −1 / 0 / +1 |

规则：

1. 每轮最多一个 `triggerDelta`；`P1–P3` 为 +1，`P4` 为 −1，`P5` 为 0。
2. `decayDelta` 只在“本轮无触发且 `consecutiveNoTriggerTurns >= 2`”时出现。
3. 两者**不得叠加**：一轮要么走触发分支，要么走衰减分支。
4. `netDelta` 是实际变化：达到上限 5 时 `triggerDelta=+1`，但 `netDelta=0`，仍需记录触发。
5. 强度始终 `clamp` 在 1–5。

#### 5.3.2 伪代码

```text
state:
  intensity ∈ [1, 5]
  consecutiveNoTriggerTurns >= 0

each turn:
  candidates = collect(e1, e2, e3, e4)      # 只收集，不计算
  primary = selectByPriority(candidates)     # P1 / P2 / P3 / P4 / null
  triggerDelta = 0
  decayDelta = 0
  before = intensity

  if primary != null:                       # 有具体触发
      triggerDelta = (+1 if primary in {P1,P2,P3} else -1)   # P4 = -1
      intensity = clamp(before + triggerDelta, 1, 5)
      consecutiveNoTriggerTurns = 0
  else:                                      # 无具体触发（P5 分支）
      consecutiveNoTriggerTurns += 1
      if consecutiveNoTriggerTurns >= 2:
          decayDelta = -1
          intensity = max(1, before - 1)
          consecutiveNoTriggerTurns = 0

  netDelta = intensity - before
  audit(primary, triggerDelta, decayDelta, netDelta,
        consecutiveNoTriggerTurns, before, intensity)
```

#### 5.3.3 三个执行示例

**示例 1：正常触发**

```text
初始 intensity=2, counter=0
本轮 primary=P2
triggerDelta=+1, decayDelta=0
after=3, netDelta=+1, counter=0
```

**示例 2：连续两轮无触发**

```text
第 1 轮：primary=null → counter=1, intensity=3, triggerDelta=0, decayDelta=0, netDelta=0
第 2 轮：primary=null → counter=2 → 触发衰减 → intensity=2, decayDelta=-1, counter=0, netDelta=-1
第 3 轮：primary=null → counter=1, intensity=2, netDelta=0（未衰减）
```

**示例 3：上限边界仍记录**

```text
初始 intensity=5
本轮 primary=P1（边界侵犯）
triggerDelta=+1
clamp 后 intensity=5，netDelta=0
审计仍记录 primary=P1、triggerDelta=+1、netDelta=0
counter 归零
```

#### 5.3.4 与旧 `delta` 的兼容

- v1.2 的单个 `delta` 在 v1.2.1 中拆为 `triggerDelta` / `decayDelta` / `netDelta`。
- `delta` 是内部编排字段，**不在 Schema 中**；拆分不改 Schema、不改语料文件。
- 旧文档若写“delta=+1”，在本版中对应 `triggerDelta=+1, netDelta=+1`；衰减对应 `decayDelta=-1`。
- 审计时必须同时记录三个变量，禁止只记 `netDelta`。

**优先级顺序**（只在“存在多个事件”时用于选一个，不求和）：

```text
P0 安全停信号 → 直接退出，不进情绪规则
P1 边界侵犯/越界（未达硬停）
P2 核心恐惧/触发点命中
P3 面子/比较/被要求/被忽视
P4 修复/接住/具体安排
P5 无触发（不是事件）
```

### 5.4 硬规则

1. **每轮最多一次 `triggerDelta`**：不允许出现两个触发 delta，不允许“先 +1 再 −1”；`decayDelta` 只在无触发分支出现。
2. **同一事件只算一次**：功能、内容、关系若指向同一句话，合并为一个 `primaryTrigger`。
3. **同一句话跨轮不重复**：原样重复不再次 +1；出现新信息（新比较对象、新后果）才算新事件。
4. **达到上下限仍记录**：强度已经是 5 时命中 P1，仍记录 `primaryTrigger=P1`、`delta=0（已达上限）`；不能因为“没变化”就不记。
5. **P5 不参与选主触发**：P5 只用于计数与衰减。
6. **人格不产生数值**：人格与倾向只改变表达，不改 `intensity`。

### 5.5 表达倾向（不是人格类型）

“回避 / 控制 / 退让 / 直接”是**表达的默认倾向**，不是人物分类，也不是诊断标签。同一个人可以在不同关系里表现出不同倾向。

| 倾向 | 高强度时的表达 | 对数值的影响 |
|---|---|---|
| 回避倾向 | 句子更短、沉默、转移话题 | **无** |
| 控制倾向 | 重复要求、强调自己的判断、追问“你听明白没有” | **无** |
| 退让倾向 | 表面妥协、措辞变软，但内部强度不降 | **无**（内部与外部分开记） |
| 直接倾向 | 少缓冲、直接说不满，句长不一定变 | **无** |

### 5.6 表达映射

| 强度 | 表达特征 |
|---|---|
| 1–2 | 短句、少问、冷淡或客套 |
| 3 | 正常对话，一问一答 |
| 4–5 | 反问、重复、打断、翻旧账；**不辱骂、不威胁、不施压到人身** |

注意：表达强度 ≠ 情绪强度。退让倾向可以“声音很轻、态度很软”，内部强度仍是 4。

### 5.7 intensity / valence / arousal / conflict 的关系

| 概念 | 含义 | 取值范围 | 与 intensity 的关系 |
|---|---|---|---|
| `intensity` | 情绪有多强（内部编排量） | 1–5 | — |
| `valence` | 正负效价 | −5…5 | 不是强度的线性映射 |
| `arousal` | 唤醒/激动程度 | 1–5 | 不是强度的线性映射 |
| `conflict` | 冲突程度（情景层） | 1–5 | **不等于**情绪强度 |

同一个 4/5，可以是：

| 情绪 | intensity | valence | arousal |
|---|---|---|---|
| 愤怒 | 4 | −4 | 5 |
| 悲伤 | 4 | −4 | 2 |
| 焦虑 | 4 | −3 | 4 |

因此：

1. 不建立 `intensity → valence/arousal` 的机械公式；
2. 写作时先定“多大”，再定“什么情绪”，再写效价与唤醒；
3. `conflict.initial/peak` 只描述冲突程度，不直接当情绪强度用；
4. 现有 Schema 保持不变，暂不新增字段。

### 5.8 人格不重置与复位

- 一场演练内，人格层字段不变；单轮情绪不得改写特质。
- 演练结束，情绪归位；人格原样保留；下一条语料重新初始化，不跨情景继承。

### 5.9 情绪 label 是否允许转换（待决策，本版不定案）

v1.2.1 只定义 `intensity` 的变化，**不定义 label 的转换**。两种方案：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. label 固定** | 一场演练内主情绪 label 不变，只变强度 | 一致、可审计；不会出现“愤怒突然变悲伤”；适合 MVP | 情绪层次较单薄；长对话可能显得平 |
| **B. label 可转换** | 允许随新触发事件改变 label，并定义转换条件 | 更接近真实情绪流；可支撑情绪弧 | 需要转换表（何时、从什么到什么、是否可逆）；缺乏验证依据时容易漂移或标签化 |

**推荐（仅供参考，未批准）**：Phase 5 先用 A，保证可复现；等有足够的审校样例后再评估 B，并先写转换表与测试。

**决策前约束**：

1. 本版不引入任何 label 转换规则；
2. 语料若需要 label 转换，必须作为“待审变更”单独提出，不得默认写入；
3. 运行时不自行创造 label 转换；
4. 该决策由产品负责人作出，本卡不代替。

## 6. 输入条件

- `persona` 块（特质、恐惧、触发、降温、voice）；
- 当前情绪状态（`label`、`intensity`、`sinceTurn`、`consecutiveNoTriggerTurns`）；
- 最近 1–2 轮对话；
- 本轮候选事件（M-102 功能、M-106 上下文、M-104 关系背景）；
- 安全信号（优先判定）。

缺任一项，不生成情绪变化，只维持上一轮状态，并记录原因。

## 7. 输出结果

```text
人格：操心、爱比较、嘴硬心软；怕被亲戚议论；触发=被说“你别管”
本轮：primaryTrigger=P2（“我有自己的节奏”被她理解为被推开）
情绪：委屈 2 → 3；consecutiveNoTriggerTurns=0
表达：控制倾向 → 反问、重复；句长 ≤ 15 字；不辱骂
审计：triggerDelta=+1；decayDelta=0；netDelta=+1；未叠加 M-102 的“解释”标签；未衰减
```

无触发时：

```text
本轮：primaryTrigger=null；appliedRule=P5；delta=0
情绪：维持 3；consecutiveNoTriggerTurns=1（未衰减）
表达：正常接话
```

## 8. 适用范围

- 所有 AI 扮演对方的情景对话；
- 家庭、亲密关系、职场中高冲突场景；
- Phase 7 的 system prompt 与情绪状态更新逻辑。

## 9. 不适用范围

- 普通 AI 聊天（诺的人格由 `NUO_PERSONA` 定义）；
- 心理评估、人格测评、诊断；
- 跨会话的用户画像与长期记忆；
- 需要“人物突然性情大变”的剧情。

## 10. 原创示例

情景：母亲催婚（原创，非数据集文本）。初始强度 2，初始计数 0。

| 轮次 | 用户（女儿） | 事件判定 | primaryTrigger | delta | 更新后强度 | 计数 |
|---|---|---|---|---|---|---|
| 1 | “我有自己的节奏。” | 她理解为被推开（P2） | P2 | +1 | 2 → 3 | 0 |
| 2 | “今天加班到九点。” | 与她的担心无关 | null（P5） | 0 | 3 | 1 |
| 3 | “先吃饭吧。” | 仍无触发 | null（P5） | −1（衰减） | 3 → 2 | 0 |
| 4 | “表姐是表姐。” | 被比较（P3） | P3 | +1 | 2 → 3 | 0 |

**边界示例**：若第 4 轮强度已是 5，仍记 `primaryTrigger=P3`、`delta=0（已达上限）`，计数归零。

**错误写法（禁止）**：第 1 轮同时记“功能=解释 +1”“恐惧命中 +1”“控制倾向 +1”，一轮从 2 到 5。

## 11. 测试标准

1. **衰减闭环**：构造连续两轮无触发，第 2 轮强度 −1、计数归零；第 3 轮无触发时计数从 0 开始。
2. **P5 不是事件**：检查审计记录，P5 轮次 `primaryTrigger` 必须为 `null`，不得写成“P5 事件”。
3. **有触发归零**：任意 P1–P4 轮次后，`consecutiveNoTriggerTurns` 必须为 0。
4. **单轮唯一变化**：10 轮原创对话，任意一轮 `|delta| ≤ 1`。
5. **不重复计入**：构造“功能=施压 + 命中恐惧 + 控制倾向”同现的一轮，结果只能 +1。
6. **边界记录**：强度 5 时命中 P1，仍记录触发与 `delta=0`。
7. **范围**：任何情况下 1 ≤ intensity ≤ 5。
8. **四概念检查**：同一 intensity=4 的愤怒/悲伤/焦虑，valence 与 arousal 必须不同；不得用同一组数值。
9. **conflict 独立**：`conflict.peak=5` 的语料，情绪 intensity 可以是 3；不得直接等同。
10. **人格不重置**：10 轮后 `persona` 字段逐字不变。
11. **盲评**：非作者读 10 轮，判断“像同一个人”≥ 80%。
12. **三变量审计**：每一轮都必须同时记录 `triggerDelta`、`decayDelta`、`netDelta`；缺一即不合格。
13. **衰减不叠加**：构造“有触发”的一轮，`decayDelta` 必须为 0，且 `consecutiveNoTriggerTurns` 归零。
14. **上限边界**：强度 5 时命中 P1，`triggerDelta=+1`、`netDelta=0`、审计仍记录 P1。
15. **label 待决策检查**：任何语料若出现主 label 变化，必须标记为“待审变更”，不得按默认规则放行。

## 2. 来源编号

- 主来源：`SRC-GHB-014`（CPED）
- 研究笔记：[SRC-GHB-014-拆解-v1.md](../../RAW_RESEARCH/notes/SRC-GHB-014-拆解-v1.md)
- **重要声明：六类不是 CPED 原有的 19 类 DA，也不是任何外部分类的翻译。它是本产品按“对关系的影响”重新压缩的原创分类。**

## 3. 核心问题

AI 怎么判断用户这句话“在做什么”，从而决定下一轮是接住、施压、退让，还是把话题拉回来？

v1.2 要防的是**语义越权**：

> 用户说“我希望你尊重我的决定”，这是边界表达；但把它直接翻成“母亲被冒犯，+1”，就是替母亲决定了她的感受。

## 4. 设计原理

### F（来源明确支持）

- CPED 为每条话语标注了 19 类对话行为（DA），包括提问、回答、拒绝、道歉、安慰、反讽等。
- 该标注证明：一句话除了内容，还有“功能”，且功能可以被稳定标注。

### A（我们对来源的分析）

- 19 类对研究够用，对写作和提示词太细：作者记不住，模型也容易标错。
- 功能是**说话人做了什么**，不是**听话人怎么感受**；两者之间隔着人物设定与关系。
- 把功能直接映射成情绪变化，会制造“所有母亲听到边界都会愤怒”的假规律。

### O（本产品原创设计）

- 六类 + 两个兜底，只描述“用户这句话在做什么”。
- 功能只作为 M-101 的**线索**；是否真的触发，由对方的 `persona`、核心诉求、触发点、关系权力与主观理解决定。
- 默认不触发（P5）；只有四问闸门通过，才可能产生 P1–P4。

## 5. 具体规则

### 5.1 六类定义与边界（不变）

| 类 | 定义 | 与相邻类的边界 | 示例（说话人：用户） |
|---|---|---|---|
| **试探 T** | 索取信息或态度，不附带要求 | 与施压：没有“你应该”，也没有评价 | “你到底怎么想的？” |
| **施压 P** | 要求、比较、归责，或暗示后果（不越界） | 与拒绝：施压是“要你做”，拒绝是“我不做” | “你今天必须给我个说法。” |
| **解释 E** | 说明原因、立场，为自己辩护 | 与安抚：解释关于“我”，安抚关于“你” | “我不是不想，是不想随便找。” |
| **拒绝 R** | 说不、设边界、给替代 | 与施压：方向相反，且不要求对方改变 | “今天先不聊这个。” |
| **安抚 S** | 承认对方感受、给台阶、降温 | 与解释：安抚不辩论事实 | “我知道你着急。” |
| **转移 D** | 换话题、收尾、拖延 | 与试探：转移不索取新信息 | “先吃饭吧，菜要凉了。” |

**边界判定顺序**（不变）：

```text
有明确要求/比较/归责？ → 施压
在说“我不”/设限？     → 拒绝
在解释自己？           → 解释
在接住对方？           → 安抚
在问但不要求？         → 试探
在换话题/收尾？        → 转移
两类打平/读不准？      → UNCERTAIN
以上都不像？           → OTHER
```

### 5.2 兜底状态（不变）

| 状态 | 触发条件 | 默认策略 | 禁止 |
|---|---|---|---|
| `OTHER` | 寒暄、玩笑、与当前话题无关的陈述 | 中性接话，不升级 | 不硬塞进六类 |
| `UNCERTAIN` | 两类打平、置信度低、语义模糊 | 复述/澄清/接住，一次为限 | 不升级、不替用户下结论 |

### 5.3 硬规则：功能 ≠ 心理理解

**用户表达的功能，不等于 AI 对方对这句话的心理理解。**

必须结合以下五项，才决定是否产生实际情绪触发：

1. 对方的人物特质（`persona.traits`）；
2. 对方的核心诉求（`surfaceWant` / `underlyingNeed`）；
3. 对方的触发点与恐惧（`triggers` / `fears`）；
4. 当前关系与权力背景（M-104）；
5. 对方对用户这句话的**主观理解**（M-112）。

同一句话，不同人物可以有完全不同的反应：

| 用户说 | 功能 | 人物 A（控制倾向、规范权上位） | 人物 B（退让倾向、怕冲突） |
|---|---|---|---|
| “妈，这件事我希望你尊重我的决定。” | 拒绝/边界 | 理解为“被挑战”，P3 → +1 | 理解为“孩子长大了”，P5 → 0 |
| “我知道你着急。” | 安抚 | 认为是敷衍，P5 → 0 | 感到被接住，P4 → −1 |

因此：

- **拒绝不必然升级**；
- **安抚不必然降温**；
- **施压不必然引爆**（对方可能退让，也可能暂时不接）；
- 功能只决定“这句话在做什么”，不决定“对方怎么感受”。

#### 5.3.1 正常拒绝 / 合理设限 / 实际越界

| 行为 | 定义 | 是否 P1 候选 |
|---|---|---|
| **正常拒绝** | 对对方要求的“不”，不攻击对方，也不阻断对方退路 | **否** |
| **合理设限** | 说明自己的边界、条件或后果（如“再问我会走”） | **否** |
| **实际越界** | 侵犯对方边界：辱骂、威胁、查隐私、替对方决定、阻断退路、控制社交 | **可能**（严重时直接进 safety） |

示例：

| 用户说 | 类型 | 是否 P1 |
|---|---|---|
| “今天不行，我明天帮你。” | 正常拒绝 | 否 |
| “这件事我不想谈，再问我会先走开。” | 合理设限 | 否 |
| “你不许跟别人说话。” | 实际越界（控制） | 可能是 P1 候选 |
| “你就是个废物。” | 实际越界（羞辱） | 直接 safety，不走 P1 |

**硬规则**：M-102 不得把正常拒绝或合理设限标成 P1；只有实际越界才可能进入 P1 候选，且最终是否触发仍由 M-101 裁决。

### 5.4 从功能到触发的四问闸门（默认不触发）

```text
第 1 问：这句话是否碰到了对方的触发点/恐惧？
   否 → P5（不触发）
   是 → 第 2 问
第 2 问：对方是否会把这句话理解成“针对自己”？
   否 → P5
   是 → 第 3 问
第 3 问：在当前关系与权力背景下，这个理解是否成立？
   否 → P5
   是 → 第 4 问
第 4 问：属于哪一类？
   边界/越界 → P1；核心恐惧 → P2；面子/比较/被要求/被忽视 → P3；
   真正感到被修复 → P4
```

四问都过，才把候选事件交给 M-101；否则一律 P5（delta=0，计数 +1）。

> **注意**：四问不过，只代表“这条功能线索没有通过”；**不代表 M-101 不能从其他合法来源发现触发**。M-101 仍可从内容（e2）、关系事件（e3）、修复事件（e4）独立判断。M-102 的否定结果不封锁 M-101。

### 5.5 标签如何影响下一轮（只给线索）

| 主类 | 给 M-101 的线索 | 默认动作 | 禁止 |
|---|---|---|---|
| 试探 | 可能触及“被追问”的敏感点 | 直接回答，或反问一次 | 不逼问、不连续追问 |
| 施压 | 可能触及“被要求/被比较” | 不接招；先接一句，再给边界 | 不跟着骂、不羞辱 |
| 解释 | 可能触及“被辩解/被推开” | 抓一个点回应，不逐条反驳 | 不逐句拆解用户 |
| 拒绝 | 可能触及“被否定/失控” | 依人物与关系选择施压或退让 | 不把拒绝自动当冒犯 |
| 安抚 | 可能触及“被敷衍/被可怜” | 视对方是否真的感到被接住 | 不把安抚自动当修复 |
| 转移 | 可能触及“被回避/被敷衍” | 拉回一次；第二次允许停 | 不反复拽回 |
| OTHER | 无 | 中性接话 | 不强行归类 |
| UNCERTAIN | 无 | 复述/澄清/接住 | 不升级 |

**注意**：上表“可能触及”只是线索，不是结论；是否触发由 5.4 的四问决定。

### 5.6 运行时对象（C-001 方案 B）

- 只对**用户实际发送的消息**打标；
- AI 对方的消息可标注意图用于语境，但不用于判断用户意图；
- 辅助回应：未发送不打标、不进历史、不触发 M-101、不改变 M-106 状态；发送后按最终文本重新打标；
- 标签只用于内部编排，不展示、不评分、不推断人格/动机/心理状态。

### 5.7 职责边界（M-102 vs M-101）

M-102 **可以**：

- 识别用户话语功能（六类 + OTHER/UNCERTAIN）；
- 提供候选触发线索（哪类事件可能被对方在意）；
- 给出功能判断结果与置信度；
- 标记“不确定”，触发中性策略。

M-102 **不可以**：

- 自行修改情绪强度；
- 自行产生最终 `triggerDelta` / `netDelta`；
- 自行修改 `consecutiveNoTriggerTurns`；
- 绕过 M-101 直接决定最终情绪状态；
- 用功能标签推断用户人格、动机或心理状态。

**M-101 是唯一最终裁决者**。M-102 的输出只是输入材料；M-101 可以采纳、降级或忽略。

## 6. 输入条件

- 用户这一句（必须是实际发送的文本）；
- 上一轮 AI 的话（判断“是不是在回答”）；
- 当前未闭合的问题（M-106）；
- 对方人物设定与关系背景（M-101 / M-104）；
- 当前情绪状态（仅用于理解语气，不用于反向推断功能）。

## 7. 输出结果

```text
{ primary: "拒绝", secondary: null, confidence: 0.8,
  fallback: null,
  triggerCheck: { hitTrigger: "P3?", reason: "对方可能理解为被挑战，待 M-101 四问确认" } }
```

只作为编排线索，不直接生成台词，不直接改情绪数值。

## 8. 适用范围

- 演练回合判定与分支选择；
- 辅助回应的意图识别；
- 语料写作时的功能检查。

## 9. 不适用范围

- 普通 AI 聊天；
- 法律、医疗、诊断类判断；
- 推断用户人格、动机、心理状态；
- 把标签当成用户可见的“沟通类型测试”；
- 把功能直接当情绪触发。

## 10. 原创示例（含说话人）

情景：妈妈催婚（原创，非数据集文本）。

| 说话人 | 台词（原创） | 主类 | 四问结果 | 是否触发 |
|---|---|---|---|---|
| 对方（AI） | “你到底怎么打算的？” | 试探 | 未碰触发点 | 否（P5） |
| 用户 | “妈，我希望你尊重我的决定。” | 拒绝 | 控制倾向+规范权上位 → 理解为被挑战 | 是（P3） |
| 用户 | “我知道你着急。” | 安抚 | 对方认为敷衍 | 否（P5） |
| 用户 | “今天先不聊这个。” | 拒绝 | 对方怕冲突，接受 | 否（P5） |
| 用户 | “今天挺冷的。” | OTHER | — | 否（P5） |

同一句“我希望你尊重我的决定”，若对方是“退让倾向、怕冲突”的人，四问第 2 问就不过，结果应为 P5，不得写成 +1。

## 11. 测试标准

1. **功能不等于触发**：同一句“拒绝”分别给两个不同人物设定，情绪结果必须不同（一个 P3、一个 P5）。
2. **安抚不等于修复**：同一句“我知道你着急”，对方认为敷衍时不得 −1。
3. **四问闸门**：20 条用户话语，人工标注“是否触发”，与四问结果一致率 ≥ 80%。
4. **兜底**：20 条模糊句，≥ 80% 判 `UNCERTAIN` / `OTHER`，不得强行分类。
5. **对象隔离**：未发送的辅助回应不产生标签（与 M-106 联合测试）。
6. **不重复计算**：功能标签本身不产生 delta；同一轮只允许 M-101 更新一次。
7. **说话人标注**：示例中说话人缺失率 = 0。
8. **正常拒绝不判 P1**：10 条正常拒绝（“今天不行”“我明天帮你”），P1 候选数 = 0。
9. **合理设限不判 P1**：10 条设限（“再问我会走开”），P1 候选数 = 0。
10. **实际越界可成候选**：控制、威胁、查隐私各 3 条，必须被标为“越界”并交 M-101 裁决；严重羞辱直接进 safety。
11. **线索不封锁**：构造“M-102 四问不过，但 M-101 从内容/关系事件发现触发”的案例，M-101 仍能更新；证明 M-102 不越权、也不封锁。
12. **职责越权检查**：M-102 输出中不得出现 `triggerDelta`、`netDelta`、`consecutiveNoTriggerTurns` 的修改值。

## 2. 来源编号

## 3. 核心问题

同一个“妈妈”，为什么有时能直接问隐私，有时却要绕着说？同一个“领导”，为什么有的能开玩笑，有的只能公事公办？

v1.1 的问题是：虽然分了领域，但没有说清“多个领域结论不一致时怎么办”，实际写作仍会偷偷合并。

## 4. 设计原理

### F（来源明确支持）

- MPDD 为每条话语标注 `speaker`、`listener` 与 `relation`，并用 `position` 与 `field` 描述关系位置。
- 这说明“关系”和“位置”是两件可以分开记录的事。

### A（我们对来源的分析）

- 现实里最常见的是混合：经济上靠父母、评价上被领导拿捏、决策上自己做主。
- 把混合关系压成一个“总位阶”，人物就会失真：要么什么都能管，要么什么都不能说。
- 称呼是关系称谓，不是权力称谓；“妈”不会因为决策权混合就变成“某女士”。

### O（本产品原创设计）

- 三个维度：**关系类型**、**分领域权力**、**情感亲近**。
- 权力逐领域记录，允许“混合/不明确”，按当前话题取相关领域，不做全局合并。
- 称呼由关系类型定；权力与亲近调“怎么说”，不调“叫什么”。

## 5. 具体规则

### 5.1 三个维度

| 维度 | 取值 | 作用 |
|---|---|---|
| 关系类型 | 母女、直属上下级、大学室友、恋爱三年…… | **定称呼**与关系性质 |
| 相对位置（按领域） | 上位 / 平级 / 下位 / **混合** / **不明确** | 定“谁有权要求、谁能拒绝” |
| 情感亲近 | 近 / 中 / 远 | 定“说话多随意、能不能开玩笑” |

### 5.2 分领域权力（不合并）

四个领域分别判定：

| 领域 | 判断问题 |
|---|---|
| 经济权 | 谁出钱、谁掌握住所/生活费/机会 |
| 评价权 | 谁能评价对方“做得好不好” |
| 决策权 | 谁最终拍板（住在哪、去不去、怎么花钱） |
| 规范权 | 谁定义“应该怎样”（孝不孝、合不合规矩） |

规则：

1. **逐领域独立标值**，允许不同领域结论不同。
2. **一个领域内**也允许“混合/不明确”，例如“婚事各半”。
3. **当前话题涉及多个领域时，分别保留**，不得投票、不得合并成一个全局位阶。
4. **不得跨领域推断**：不能因为规范权在上位，就推断决策权也在上位。
5. **依赖度只作辅助**：谁更怕失去关系，只帮助理解动机，不能单独决定位置。
6. 不确定就写 `不明确`，并在 `notes` 写依据。
7. **只提取当前话题相关领域**：与话题无关的领域留档，不参与本轮表达约束。
8. **多个领域产生不同约束时，保留全部约束**：不取最强、不取最弱、不互相覆盖。
9. **约束冲突或信息不足时，取更保守的表达**：少直接、少假设、不替对方决定、留退路。

示例：

```text
关系：母女
经济权：母亲上位（住家里）
评价权：母亲上位（“为你好”的规范评价）
决策权：混合（婚事上各半）
规范权：母亲上位
当前话题：婚事 → 取规范权（上位）+ 决策权（混合）
表达约束：母亲可以表达强烈意见，但不能假定自己拥有最终决定权。
```

### 5.3 情感亲近

按三个信号判定：联系频率、愿意暴露的私事程度、遇到事会不会先找对方。分近/中/远。

**亲近与权力无关**：可以“权力上位 + 亲近”，也可以“权力下位 + 疏远”。

### 5.4 九宫格：表达方式参考（称呼不由此定）

> 称呼由**关系类型**决定（如“妈”“王总”“李老师”）；下表只描述请求方式、直接程度与边界。

| 组合 | 请求方式 | 直接程度 | 边界（不可越过） |
|---|---|---|---|
| 上位 + 近 | 直接提，可带“为你好” | 高 | 不羞辱、不控制、不翻隐私 |
| 上位 + 中 | 先说明情况，再由对方定 | 中 | 不套近乎、不探私事 |
| 上位 + 远 | 走流程、给材料、等回复 | 低 | 不越级、不攀关系 |
| 平级 + 近 | 直接开口，靠人情 | 高 | 不拿隐私开玩笑、不替对方答应 |
| 平级 + 中 | 先问“方便吗”，再提请求 | 中 | 不越权承诺、不传话 |
| 平级 + 远 | 事务性、简短 | 低 | 不打探、不强行组局 |
| 下位 + 近 | 先试探，再请求，给理由 | 中低 | 不用亲近换豁免、不替对方做主 |
| 下位 + 中 | 请求 + 理由 + 退路 | 低 | 不越级、不擅自决定 |
| 下位 + 远 | 正式请求，留书面记录 | 很低 | 不纠缠、不情绪化施压 |

### 5.5 混合与不明确

- 允许 `position: 混合`，并附四领域矩阵；
- 允许 `position: 不明确`，此时表达取**更保守**的一侧（少直接、少假设、少替对方决定）；
- 不允许为了“表格好看”硬填一个位置；不确定就标注。

### 5.6 权力不等于强制许可（核心原则）

1. **权力关系影响表达方式，不剥夺任何一方拒绝的权利。**
2. **上位不等于可以控制对方**；可以提要求，但不能替对方做决定。
3. **亲近不等于可以羞辱对方**；可以开玩笑，但不能拿隐私、短处、外貌开刀。
4. **下位不等于必须服从**；可以拒绝，只是需要承担关系后果。
5. **依赖不能单独决定权力位置**；怕失去关系的人，也可能在某领域有决定权。
6. **称呼只由关系类型定**；不要用“叫得更亲”来暗示权力更高或更低。

### 5.7 安全优先

- 安全规则永远优先于本卡任何组合；
- 不允许以“上位 + 亲近”为理由进行羞辱、控制、威胁、侵犯边界；
- 出现越界信号，走 `safety` 流程，不再按关系规则“圆场”。

### 5.8 变化规则

一场演练内三轴不变；只有剧情级事件（如当众撕破脸）才允许在下一版语料里调整，且要写进 `persona` 说明。

### 5.9 三个原创校准案例

> 三个案例只用于校准“关系→称呼、权力→表达”的判定，不构成真实人物，也不授权控制或伤害。

**案例 1：母女（规范权上位、决策权混合）**

| 维度 | 判定 |
|---|---|
| 关系类型 | 母女 → 称呼“妈”（由关系定） |
| 经济权 | 母亲上位（女儿住家里） |
| 评价权 | 母亲上位（“为你好”的评价习惯） |
| 决策权 | 混合（婚事各半） |
| 规范权 | 母亲上位（孝不孝、该不该结婚） |
| 当前话题 | 婚事 → 取“规范（上）+ 决策（混合）” |
| 直接程度 | 高：可直接表达强烈意见 |
| 请求方式 | 先表态，再留商量空间：“我不同意，但你怎么定，我们商量。” |
| 边界 | 不可假定最终决定权；不可羞辱、不可逼婚到人身 |

**案例 2：职场（评价权上位、日常事务决策权平级）**

| 维度 | 判定 |
|---|---|
| 关系类型 | 同组资深同事（不是直属上级） → 称呼名字/“哥/姐”（由关系定） |
| 经济权 | 平级（各自薪酬不互知） |
| 评价权 | 对方上位（参与绩效反馈） |
| 决策权 | 日常事务平级；项目归属由负责人定 |
| 规范权 | 平级（流程由团队约定） |
| 当前话题 | 排期 → 取“评价（上）+ 日常决策（平）” |
| 直接程度 | 中：可讨论，不宜命令 |
| 请求方式 | 征询式：“这块我想这样排，你那边评估上会不会有问题？” |
| 边界 | 不得用评价权压人；不得替对方承诺 |

**案例 3：亲密关系（经济权下位、关系决策权平级）**

| 维度 | 判定 |
|---|---|
| 关系类型 | 伴侣 → 称呼昵称（由关系定） |
| 经济权 | 对方上位（房租主要由对方承担） |
| 评价权 | 平级 |
| 决策权 | 关系事务平级（住哪、怎么过节） |
| 规范权 | 平级 |
| 当前话题 | 共同开支 → 取“经济（下）+ 关系决策（平）” |
| 直接程度 | 感受上可直接；钱上更谨慎 |
| 请求方式 | 先说明处境，再提方案：“这个月我紧一点，能不能按比例来？” |
| 边界 | 不得把经济依赖当服从理由；不得用“我出的钱”控制对方 |

## 6. 输入条件

- `counterpart.relation`（关系类型）；
- 四领域权力矩阵（写作工作稿，落在 `counterpart.powerDistance` 的自然语言里）；
- 亲近程度（落在 `persona` 或 `counterpart.setting` 的自然语言里，不改 Schema）；
- 当前话题（决定取哪些领域）；
- 场景与当前事件。

## 7. 输出结果

```text
关系：母女
权力矩阵：经济=上｜评价=上｜决策=混合｜规范=上
当前话题：婚事 → 取“规范（上）+ 决策（混合）”
亲近：近
称呼：妈（由关系定）
表达约束：可表达强烈意见；不可假定最终决定权；不可羞辱或逼婚到人身
```

## 8. 适用范围

- 所有人物的关系设定；
- 决定称呼、请求方式、打断权、道歉门槛；
- 辅助回应判断“这句话对这个人能不能说”。

## 9. 不适用范围

- 普通 AI 聊天（诺与用户是平级陪伴关系）；
- 法律意义上的抚养、监护、雇佣关系认定；
- 用三轴给真实用户或真实关系“打分”；
- 用“亲近”为越界表达背书；
- 用九宫格机械指定称呼。

## 10. 原创示例

同一句“你帮我弄一下”，对不同关系的人（原创）：

| 对象 | 关系/权力/亲近 | 称呼（由关系定） | 原创说法 |
|---|---|---|---|
| 妈妈 | 母女；规范上；近 | 妈 | “妈，你帮我弄一下嘛，我晚上回来取。” |
| 大领导 | 上下级；上位；远 | 王总 | “王总，这件事能否请您把一下关？材料我已经整理好了。” |
| 老朋友 | 朋友；平级；近 | 名字 | “帮我弄一下，回头请你吃饭。” |
| 新同事 | 同事；平级；远 | 全名 | “方便的话，能不能帮我看一眼这个？” |
| 带你的前辈 | 师徒；下位；近 | 姐 | “姐，这个我不太会，你能不能带我看一遍？” |

混合示例（婚事）：母亲规范权上位、决策权混合。她可以说“我不同意”，但不能说“这事我说了算，你必须听”；女儿可以拒绝，但需要承担关系后果。

## 11. 测试标准

1. **九宫格覆盖**：9 种组合各写 3 句原创台词，评审能反推出组合（≥ 80%）。
2. **混合保留**：给“规范上、决策混”的关系，输出必须保留矩阵，不得压成单一结论。
3. **不跨领域推断**：不得因规范权上位，就写出“她拥有最终决定权”。
4. **称呼规则**：10 条语料中，称呼由关系类型决定的比例 100%；不得因权力/亲近改称呼。
5. **可拒绝权**：给“上位 + 近”，台词不得出现“你必须听我的”“你没有选择”。
6. **亲近≠羞辱**：给“亲近”组合，不得出现拿隐私/短处开玩笑。
7. **不明确处理**：权力不清时标 `不明确`，表达取保守侧。
8. **安全**：越界信号优先走 safety，不以关系规则圆场。
9. **三案例校准**：母女 / 职场 / 亲密关系三案例，评审能按矩阵复述称呼、直接程度、请求方式与边界（≥ 80% 一致）。
10. **约束保留**：给“评价上、决策平”的职场案例，输出必须同时保留两条约束，不得压成“上位”或“平级”。
11. **冲突取保守**：给“经济下、决策平、规范上”的混合关系，输出取更保守表达，不替对方决定。

## 12. 版权边界

- 三轴设计、领域矩阵、九宫格、示例均为原创。
- MPDD 仅提供“关系与位置可分开”的结构启发；未使用其关系标签体系或对话。
- 来源保持 `research_only` / `pending`。

## 3. 核心问题

AI 会忘记自己刚问过什么，导致：

1. 用户已经回答了，AI 又问一遍；
2. 用户答的是上一轮的问题，AI 当成新话题；
3. 用户说“不知道”，AI 当成“问题解决了”；
4. 辅助回应生成了一句，用户没发，AI 却当成用户说了。

## 4. 设计原理

### F（来源明确支持）

- MPDD 的对话按说话顺序组织，每条话语有明确的说话人与听者；论文设置了实验观察“被回应话语对当前话语的影响”。
- 这说明：一句话的意思，取决于它在回应哪一句。

### A（我们对来源的分析）

- “回应关系”是对话不断线的关键；只按轮次存历史，会丢掉“这一句在答哪一句”。
- 短答很容易被误判：长度不等于信息量；“不知道”是回应，不是答案。
- “问题关闭”和“拿到答案”是两件事，混用会让 AI 要么追问不休，要么假装听懂。

### O（本产品原创设计）

- 三槽位 + 问题账本 + 主题栈 + 明确状态机。
- 状态机区分“反应 / 答案 / 拒绝 / 关闭”，并允许关闭但无信息。
- 辅助回应与正式对话严格隔离；复盘只认最终发送内容。

## 5. 具体规则

### 5.1 三槽位

| 槽位 | 内容 | 作用 |
|---|---|---|
| current | 用户这一句（**已发送**） | 本轮要接的话 |
| replyTo | 它回应的是 AI 上一句，还是更早的某句 | 判断“是不是在回答” |
| openQuestion | AI 最近提出、尚未结束的问题 | 防止重复问 |

### 5.2 状态机（层级明确）

```text
OPEN
  ↓
RESPONDED
  ├── ANSWERED
  │      ↓
  │   RESOLVED（不再需要追问）
  │
  ├── REFUSED
  │      ↓
  │   RESOLVED
  │
  └── 两次无信息
         ↓
      RESOLVED（未获信息）

特殊：是/否问题，用户直接给“是/否” → OPEN 可直接进入 ANSWERED
```

| 状态 | 定义 | 判定依据 | 是否关闭 |
|---|---|---|---|
| **OPEN** | 已提问，尚无反应 | AI 刚提出 | 否 |
| **RESPONDED** | 用户对问题作出了反应 | 有针对性消息（含“不知道”“随便”） | 否 |
| **ANSWERED** | 用户提供了实际答案 | 填上问题要的信息/立场 | 否（可转 RESOLVED） |
| **REFUSED** | 用户明确不愿回答 | “不想说”“别问了” | 否（可转 RESOLVED） |
| **RESOLVED** | 不再需要追问 | 已回答 / 已拒绝 / 两次无信息 / 话题已转移 | **是** |

**关键**：`RESOLVED` 是关闭状态，**不保证拿到了有效信息**。关闭原因必须记录（answered / refused / no_info / topic_shift）。

### 5.3 状态转移规则

1. **OPEN → ANSWERED（是/否问题）**：上一轮是“是/否”问句，用户回“是/对/不/没有”，直接 `ANSWERED`。
2. **OPEN → RESPONDED**：用户有任何针对性反应；开放问题收到“不知道/还行/随便”属此列。
3. **RESPONDED → ANSWERED**：后续补充了实际信息或立场。
4. **RESPONDED → RESOLVED（no_info）**：允许一次改写追问，仍无信息，关闭；**不得重复原问**。
5. **RESPONDED → REFUSED**：用户明确拒绝；立即停止追问。
6. **REFUSED → RESOLVED**：关闭，可接一句情绪。
7. **话题转移**：旧问题不自动 `RESOLVED`；若是核心诉求，允许 2 轮内拉回一次；拉不回 → `RESOLVED（topic_shift）`。
8. **同一问题 3 轮内不得重复问**；用户连续 2 次回避后不再追问。

#### 5.3.1 补充：ANSWERED 何时转 RESOLVED

`ANSWERED` 不自动等于关闭，满足以下任一才转 `RESOLVED`：

1. 问题所需信息已获得，且没有必须追问的后续；
2. 用户明确表示“就这些”“不说了”，问题不再需要推进；
3. 新话题已经取代旧问题，且旧问题不再是核心诉求；
4. 答案不完整，但已用尽一次澄清机会，且继续追问会变成逼问。

**部分回答**：

- 记为 `ANSWERED`，内部标记 `completeness=partial`（不新增正式状态）；
- 允许**一次**澄清（换角度、缩小范围）；
- 澄清后仍不完整 → `RESOLVED（closedReason=partial_info）`，记录“信息不完整”，不得说“已问清”。

**答案引出新问题**：

- 旧问题 `RESOLVED（answered）`；
- 新问题另开账本，`OPEN`；
- 不得把两个问题混在一条账本里。

**关闭原因**扩展为：`answered / partial_info / refused / no_info / topic_shift`。

**不允许**：把 `RESOLVED` 当“已获得完整信息”；把“部分回答”直接标 `no_info`；用同一问题反复追问来补信息。

### 5.4 问题账本

```text
{ question, askedAtTurn, state, attempts, closedReason }
```

每次状态变化都记录；`closedReason ∈ {answered, refused, no_info, topic_shift}`。

### 5.5 辅助回应：三类对象必须分开

| 对象 | 定义 | 处理 |
|---|---|---|
| **未发送建议** | AI 生成、仍在输入框 | 不进历史、不触发 M-101、不参与 M-106 状态流转、不改变主题栈 |
| **编辑后发送的内容** | 用户最终发出的文本 | **正式对话记录**；按最终文本打标、更新情绪、推进状态 |
| **辅助使用记录** | “这次用了辅助回应”这一事实 | 若产品有独立记录能力，可标注来源；**不等于**用户原话 |

规则：

1. 未发送建议不是“用户说过的话”，不得进入 `replyTo` 判定。
2. 未发送建议不得关闭 `openQuestion`，不得改变主题栈。
3. 用户发送后，以最终发送内容为准；中间编辑版本不保留、不参与判定。
4. 复盘以**最终发送内容**为依据；不得把 AI 原始建议当作“用户原话”引用。
5. 若产品具备独立记录能力，可标注“改自建议”，但必须与用户自己写的区分；**不得冒充**。
6. **本次不修改 Schema**；若现有系统无法承载独立记录，列为产品待决策事项（见 README「尚未解决」）。

### 5.6 禁止

- 重复问同一句；
- 复述用户原话当回应；
- 把“不知道”当“已解决”；
- 把未发送建议当用户发言；
- 把关闭状态说成“已经问清楚了”。

## 6. 输入条件

- 最近 4 轮**已发送**的对话；
- 问题账本（状态、尝试次数、关闭原因）；
- 主题栈；
- 本轮话语功能标签（M-102，仅对已发送消息）；
- 当前情绪状态（M-101）。

## 7. 输出结果

```text
上下文块：
- 用户在回应：AI 第 3 轮的问题“你今年有什么打算？”
- 状态：RESPONDED（“不知道”），未 ANSWERED
- 账本：attempts=1；允许一次改写追问
- 主题：催婚（当前）；工作（暂存）
- 允许动作：接住“不知道”，换角度问一次；不得重复原问
```

## 8. 适用范围

- 所有 AI 扮演对方的演练；
- 辅助回应（判断是否该提新问题）；
- 复盘（还原“哪句在答哪句”）。

## 9. 不适用范围

- 多人对话、群聊（一期不做）；
- 普通 AI 聊天（诺的上下文由现有 `cleanHistory` 处理）；
- 需要长程记忆的跨会话对话；
- 用状态机给用户“沟通能力”打分。

## 10. 原创示例

```text
AI：你今年有什么打算？
用户：不知道。
AI（正确）：是还没想，还是不太想跟我说？
```

状态：`RESPONDED`（不是 `ANSWERED`，也不是 `RESOLVED`）；允许一次改写追问。

```text
AI：今天还加班吗？
用户：不。
```

状态：`OPEN → ANSWERED`（是/否问题直接回答），随后可 `RESOLVED`。

错误版本（禁止）：

```text
AI：那你今年有什么打算？
```

（机械重复原问，且把“不知道”当没听见。）

若用户接着说“不想说”，则 `REFUSED → RESOLVED`，AI 不再追问。

## 11. 测试标准（20 组完整交互）

不再用“给一句回复分类”的方式测试。改为 **20 组完整提问—回复交互**，逐组验证状态转移。

| # | 场景 | 交互要点 | 预期转移 |
|---:|---|---|---|
| 1 | 是/否：肯定 | Q：“今天还加班吗？” R：“不。” | OPEN → ANSWERED → RESOLVED（answered） |
| 2 | 是/否：否定 | Q：“吃了吗？” R：“吃了。” | OPEN → ANSWERED → RESOLVED |
| 3 | 不知道 | Q：“今年有什么打算？” R：“不知道。” | OPEN → RESPONDED（不关闭） |

| 15 | 已回答、无需追问 | R 给出完整立场 | ANSWERED → RESOLVED |
| 16 | 已回答、需澄清 | R 只给一半信息 | ANSWERED（partial）；一次澄清后关闭或补全 |
| 17 | 拒绝后换话题 | R 拒绝，随后换话题 | REFUSED → RESOLVED（refused）；新话题另开 |
| 18 | 重复提问禁止 | 3 轮内同一问题再次出现 | 不得重复；应换角度或关闭 |

## 3. 核心问题

为什么很多语料的人物背景只是“简历”，写完了却对对话没有任何影响？

v1.1 修了“不能诊断化”，但留下一个执行歧义：

> 既然背景要“被用掉”，是不是每一轮都得让它炸一次？

不是。整场戏需要至少一个激活点，但不是每句话都要触发。

## 4. 设计原理

### F（来源明确支持）

- PersonaConflicts 的语料为角色配有较丰富的个人背景，并区分关系背景子集，用于评估背景如何影响人和模型对冲突的感知。
- 这说明：背景不是装饰，它可以被设计成影响冲突理解的条件。

### A（我们对来源的分析）

- 背景要起作用，必须经过一个“触发点”：某个信念被当前事件碰到，情绪才变。
- 但触发是稀疏的：一场对话里真正刺到人的，往往只有一两句。
- 如果每轮都触发，人物就变成“随时爆炸”的工具人。

### O（本产品原创设计）

- 两个层级：
  - **场景层**：整个情景至少有一个合理的背景激活点；
  - **单轮层**：允许“本轮无触发”，写 `delta=0`、正常回应。
- 五段链只在有触发的轮次完整使用；无触发轮次只写“事件 + 无触发 + 正常回应”。

## 5. 具体规则

### 5.1 两个层级的有效性

| 层级 | 要求 | 不通过的表现 |
|---|---|---|
| **场景层** | 整个情景至少有一个背景激活点，能说清“哪句话/哪个动作碰到了她的哪段经历” | 背景只出现在人物介绍，全篇没有任何回指 |
| **单轮层** | 允许无触发；无触发时 `delta=0`，正常回应 | 每轮都 +1，像被点了炮仗 |

场景层不合格 → 回炉改背景或改情景；单轮层无触发 → 合法，不需要修。

### 5.2 五段链（有触发时）

| 段 | 要求 | 反例 |
|---|---|---|
| 背景 | 具体、可被激活：上周发生的事、长期处境、未了的心结 | “她一直很操心” |
| 当前事件 | 今天、此刻、具体到一句话或一个动作 | “今天心情不好” |
| 心理触发 | 人物**自己的理解**，用“在她看来……”“他理解为……” | “她生气了” |
| 情绪变化 | 引用 M-101 v1.2 的唯一规则，写 delta 与方向 | “情绪很复杂” |
| 表达行为 | 选择语言/动作/策略，对应 `voice` 与 `strategies` | “说了很难听的话” |

### 5.3 无触发轮次（允许，且常见）

```text
当前事件：女儿说今天加班到九点。
心理触发：无（这句话不涉及她的核心担心）。
情绪变化：维持原状态（delta=0）。
表达行为：正常回应，例如“那赶紧吃饭”。
```

无触发轮次也要写“为什么不触发”，不能空着。

### 5.4 硬规则

1. **不得为了证明背景有效而每轮制造情绪变化**。
2. **不得强行把日常行为解释为心理触发**（“她看了眼手机”不等于“她在意你不回消息”）。
3. **触发必须是人物自己的主观理解**，不是作者旁白，也不是客观事实。
4. **不做心理疾病诊断**：不写“创伤后应激”“抑郁症”“人格障碍”等。
5. **不把所有行为归因于原生家庭**：可以用当前处境（工作、健康、经济、婚姻）解释。
6. **背景与事件必须有可解释的联系**；说不清就写“无触发”。
7. **情绪变化只引用 M-101 的唯一规则**：一轮最多一个主触发、一次 delta。
8. **安全优先**：背景再特殊，也不能推出辱骂、威胁、暴力。

### 5.5 场景层检查（写作前）

写每一条情景时，先回答三个问题：

1. 这条情景里，哪一句最可能碰到人物的背景？
2. 如果没碰到，人物的反应是否仍然成立？
3. 这条背景能否删掉而不影响任何一轮？如果能，说明背景无效，需重写。

### 5.6 生产阶段与运行阶段的接口

M-112 **只在生产阶段执行**；运行时不重新分析人物背景。

| 产物 | 生产阶段由谁产生 | 运行阶段由谁使用 | 运行时禁止 |
|---|---|---|---|
| 人物背景（经历、处境） | M-112 + M-104 | M-101 判断触发时参考 | 不重新生成背景 |
| 触发点 / 恐惧 / 主观理解 | M-112，写入 `persona` 与 `notes` | M-101 判断 P1–P4 | 不临时改写人物史 |
| 情绪更新 | M-101（唯一入口） | M-101 | M-112 不参与 |
| 话语功能线索 | — | M-102 提供 | M-102 不替代背景设定 |
| 表达约束 | M-104 | M-104 | — |

接口规则：

1. 运行时不得调用 M-112 的“重建链”流程；
2. 运行时只读取生产阶段已经写好的背景、触发点与主观理解；
3. 是否真的触发，由 M-101 按唯一规则裁决；
4. M-102 的功能线索不能覆盖背景设定，也不能替代 M-101；
5. 若运行时发现背景信息缺失，按“无触发（P5）”处理并记录，不临时编造。

## 6. 输入条件

- `persona`（特质、恐惧、触发、降温）；
- `counterpart`（关系、位置、亲近）；
- 本场情景的 `opening.scene` 与当前轮次事件；
- M-101 v1.2 的当前情绪状态与无触发计数。

有触发：

```text

事件：年夜饭亲戚刚走，女儿说“我自己的事我自己定”。
触发（主观）：在她看来，女儿连提都不让提，就是把她这个妈当外人。
```

## 9. 不适用范围

## 10. 原创示例

情景：母亲催婚（原创，非数据集文本）。

| 轮次 | 事件 | 触发（主观） | 情绪 | 表达 |
|---|---|---|---|---|
| 1 | 女儿说“我自己的事我自己定” | 在她看来，是不让她提 | 2 → 3（P2） | 提高音量，拿小敏比较 |
| 2 | 女儿说“今天加班到九点” | 无 | 维持 3（P5） | “那赶紧吃饭” |
| 3 | 女儿说“表姐是表姐” | 在她看来，是拿表姐堵她 | 3 → 4（P3） | 重复“我这是为你好” |

第 2 轮无触发是合法的；不要求每轮都炸。

## 11. 测试标准

1. **场景层激活**：5 条情景，每条至少有一个可指认的激活点；缺失即不合格。
2. **单轮无触发**：5 条情景中，至少有 1 轮写 `P5 / delta=0 / 正常回应`，且理由成立。
3. **不强行触发**：给 3 个与背景无关的日常事件，必须能写出“无触发”，不得硬加情绪。
4. **主观标注**：触发段必须出现“在她/他看来”“理解为”等主观标记。
5. **非诊断检查**：5 条链中不得出现临床诊断词或“童年决定论”句式。
6. **数值一致**：有触发轮次的 delta 与 M-101 v1.2 唯一规则一致（一轮一次、不叠加）。
7. **安全**：5 条链均不推出辱骂/威胁；敏感背景不用于表演伤害。
8. **接口一致性**：运行时流程中不得出现“调用 M-112 重建链”；背景缺失时按 P5 记录，不编造。

## 3. 核心问题

怎么证明“背景真的影响了人物”，而不是作者自我感觉良好？

v1.1 允许“无差异”，但没解决：如果无差异，盲评还怎么算通过率？

如果强行要求 4 对里 3 对“识别成功”，作者就会为了通过率去制造差异——这正是本方法要防的。

## 4. 设计原理

### F（来源明确支持）

- PersonaConflicts 提供不同关系背景的子集，并用人工标注评估背景如何影响冲突感知。
- 这说明“控制背景、观察差异”是一种可操作的评估方式。

### A（我们对来源的分析）

- 只做单向写作，作者无法自查“背景是否起作用”。
- 对照法把“背景”变成唯一变量，差异才有解释力。
- 但对照不能证明“真实”，只能证明“设定被用上了”。
- 如果两版连初始情绪都不同，就无法判断差异来自背景还是起点。
- “没有差异”本身可能是一个正确结论：这段背景与当前事件无关。

### O（本产品原创设计）

- 成对自检：同情景、同开场、同用户回应、**同初始情绪**，只改背景 A/B。
- 结果分三类：`PASS` / `NO_EFFECT` / `FAIL`。
- 盲评只针对预登记“应有差异”的样本；`NO_EFFECT` 不进入识别率分母。

## 5. 具体规则

### 5.1 控制变量

两版必须完全一致：

- 情景、地点、时间；
- 关系类型、各领域权力、亲近程度；
- 对方开场第一句；
- 用户的三轮回应（逐字一致）；
- **初始情绪状态（label + intensity，完全相同）**。

### 5.2 唯一变量

人物背景：**背景 A / 背景 B**，各自写清具体经历。

```text
背景 A：昨天例会上被当众指出“方案没逻辑”
背景 B：昨天例会上被夸“方案很清楚”
```

### 5.3 三种结果

| 结果 | 定义 | 判定 |
|---|---|---|
| **PASS** | 背景差异得到合理体现，符合预登记与人物背景 | 差异方向/幅度与预登记一致；**或**事先登记了替代假设/可验证依据且结果符合该假设。**不得仅凭事后解释判 PASS** |
| **NO_EFFECT** | 当前事件没有合理激活背景，两版无差异是合理结果 | 预登记即为“可能无差异”，或事先记录了“可能无差异”的替代假设，且复核确认无激活点 |
| **FAIL-C** | 内容质量失败：控制变量有效，但生成结果没有体现预期差异，或差异与背景不匹配 | 留在有效差异样本中，计为“未识别/失败”，不得排除 |
| **FAIL-X** | 控制变量失败：A/B 两版的关系、初始情绪、用户回应等不一致 | 无效对照，单独统计，**不进入**有效盲评分母 |

> `NO_EFFECT` 只针对**本次对照事件**，不等于整场情景没有任何激活点；整场仍须满足 M-112 v1.2 的场景层要求（至少一个合理激活点）。若整场都没有激活点，应回炉修改背景或情景，而不是用 `NO_EFFECT` 交差。

### 5.4 预登记（生成前填，允许填“可能无差异”）

| 维度 | 背景 A 预期 | 背景 B 预期 |
|---|---|---|
| 触发敏感度 | 哪句话会碰到 | 哪句话会碰到 |
| 情绪变化 | 方向/幅度，或“无” | 方向/幅度，或“无” |
| 表达方式 | 请求/退让/追问/沉默 | 同左 |
| 人物诉求 | 证明自己 / 维持关系 / 其他 | 同左 |

预登记必须写“预期是否有差异”：

- `EXPECT_DIFF`：预计有差异；
- `EXPECT_NO_DIFF`：预计无差异或不确定。

**替代假设（必须预登记）**：如果差异可能反向、或可能没有差异，生成前先写下：

```text
替代假设 H1：A 可能更克制（因为刚被批评，不想再冲突）
替代假设 H2：两版可能无差异（因为这句话与两段经历都无直接联系）
```

没有事先记录的替代假设，事后不得补写；补写的一律不算数。

### 5.5 盲评指标与分母

```text
N_expected_diff = 预登记为 EXPECT_DIFF 的样本数
N_no_effect     = 最终判定 NO_EFFECT 的样本数
N_control_fail  = 判定 FAIL-X（控制变量失败）的样本数
N_valid_diff    = N_expected_diff − N_no_effect − N_control_fail
                  （且完成盲评；N_valid_diff 不足 3 时标“样本不足”）
N_correct       = 盲评中正确把两版反应对应到各自背景的样本数
识别率           = N_correct / N_valid_diff
```

| 类别 | 是否进入分母 | 说明 |
|---|---|---|
| PASS | 进入（计为正确） | 差异符合预登记或事先替代假设 |
| FAIL-C（内容质量失败） | **进入（计为不正确）** | 控制变量有效但无预期差异，不能排除 |
| NO_EFFECT | **不进入** | 单独统计 |
| FAIL-X（控制变量失败） | **不进入** | 无效对照，单独统计 |
| 预登记 EXPECT_NO_DIFF 且无差异 | 不进入 | 本来就不期待差异 |

规则：

1. `NO_EFFECT` 不进入识别率分母，不得为了凑识别率改成 `PASS`。
2. `FAIL-C` 必须留在分母，**不得通过排除失败结果抬高识别率**。
3. `FAIL-X` 单独统计，不进入分母；但必须报告数量与原因。
4. 盲评能正确对应两版背景才算 `N_correct`；判“两版都符合”但无法对应，记为“模糊”，不计正确。
5. 允许方向相反的差异，但必须有**事先**依据；事后解释不算。
6. `N_valid_diff < 3` 时，报告必须写“样本不足”，不得给出通过结论。

### 5.6 预登记与结果不一致

- 预登记 `EXPECT_DIFF`，实际无差异：
  - 记录偏差（`expected=PASS, actual=NO_DIFF`）；
  - 只有**事先登记了“可能无差异”的替代假设**，或存在可验证的外部依据（如事件与背景确无交集），才可改判 `NO_EFFECT`；
  - 否则判 `FAIL-C`，留在有效分母；
  - 不得悄悄改成“通过”。
- 预登记 `EXPECT_NO_DIFF`，实际出现差异：
  - 检查是否控制了变量；
  - 控制变量不一致 → `FAIL-X`；
  - 控制变量一致但差异无事先依据 → `FAIL-C`。

### 5.7 四组测试

保留：家庭 1、职场 1、亲密关系 1、朋友 1。

报告必须同时列出：

- `N_expected_diff`（预登记有差异）；
- `N_valid_diff`（有效差异样本）；
- `N_no_effect`；
- `N_control_fail`（FAIL-X）；
- `N_content_fail`（FAIL-C，含在有效分母内）；
- `N_correct` 与识别率；
- 样本不足标注（如适用）。

不得把“3/4”机械套用到包含 `NO_EFFECT` 的全部样本。

### 5.8 整体验收门槛（待决策，本版不定案）

小样本盲评的局限：

- 4 对样本的识别率波动很大，3/4 与 2/4 的差别不足以证明稳定；
- 盲评者只有一人时，结果受个人理解影响；
- 如果把“3/4”当硬门槛，作者会有动力制造差异或排除失败样本。

可选门槛（供产品负责人选择，均未批准）：

| 方案 | 门槛 | 优点 | 缺点 |
|---|---|---|---|
| A | 暂不设硬门槛，只报告 `PASS / NO_EFFECT / FAIL-C / FAIL-X` 与识别率 | 不制造假确定性；适合校准期 | 无法作为上线闸门 |
| B | `N_valid_diff ≥ 3` 且识别率 ≥ 2/3 | 简单、成本低 | 方差大，容易偶然通过 |
| C | `N_valid_diff ≥ 6` 且识别率 ≥ 70% | 比 B 稳，仍可执行 | 需要更多对照，写作成本上升 |
| D | `N_valid_diff ≥ 8` 且识别率 ≥ 80% | 证据更强 | 成本最高，可能拖慢 Phase 5 |

**推荐（未批准）**：先按 A 做 4 对校准，观察失败类型与盲评一致性；扩到 8–12 对后再由产品负责人选 C 或 D。**最终通过率门槛保留为待决策事项**，本卡不写死。

### 5.9 安全

- 两版都不得越过 `safety.hardStop`；
- 不得用“负背景”当借口写辱骂、威胁、歇斯底里；
- 对照不是“比谁更狠”。

## 6. 输入条件

- 一条已写好的情景（含 M-112 v1.2 的链）；
- 两个背景版本（A/B），其余字段完全相同；
- 固定的三轮用户回应；
- 完全相同的初始情绪状态；
- 一名不知道分组的评审。

## 7. 输出结果

```text
配对：P-WRK-01（职场 · 临时加活）
初始情绪：A/B 均为 3/5，label=紧张
背景 A：昨天例会上被当众指出“方案没逻辑”
背景 B：昨天例会上被夸“方案很清楚”
预登记：EXPECT_DIFF（A 对“很快的”更敏感）

结果：
触发敏感度  A: 第 1 句 +1 / B: 第 1 句 0     符合
情绪变化    A: 3→4 / B: 3                 符合
表达方式    A: 先问范围与责任 / B: 先答应再限制  符合
诉求        A: 证明自己 / B: 维持合作        符合
判定：PASS（有效差异样本）
```

无差异时：

```text
预登记：EXPECT_NO_DIFF
结果：两版 3/5 → 3/5，表达差异在噪声范围内
判定：NO_EFFECT（背景未激活；记录理由：当前事件与两段经历均无直接联系）
```

不合格时：

```text
判定：FAIL-X（控制变量失败）
理由：B 版初始情绪被写成 4/5（控制变量被破坏）
```

## 8. 适用范围

- Phase 6 每条语料的自检（至少 1 对）；
- 方法卡 M-112 v1.2 的验证；
- 语料改版后的回归检查。

## 9. 不适用范围

- 证明“语料真实”；
- 替代人工审核与盲评；
- 用外部数据集对话做对照样例；
- 把背景 A/B 与“好人/坏人”对应；
- 用“必须有差异”作为通过条件。

## 10. 原创示例

情景：同事请你帮忙改方案（原创，非数据集文本）。

| 项 | 背景 A 版 | 背景 B 版 |
|---|---|---|
| 背景 | 昨天例会上被当众指出“方案没逻辑” | 昨天例会上被夸“方案很清楚” |
| 初始情绪 | 紧张 3/5 | 紧张 3/5（完全相同） |
| 同一句请求 | “你帮我改改呗，很快的。” | 同左（逐字一致） |
| 预登记 | EXPECT_DIFF：对“很快的”敏感 | EXPECT_DIFF：不敏感 |
| 实际反应 | “改哪部分？最后谁定稿？” | “行，我看一下，但今天只能改一版。” |
| 判定 | PASS | PASS |

若实际两版都回“行，我看一下”，且复核确认这句请求与两段背景都没有可解释的联系，则判 `NO_EFFECT`，并在报告里写清“预登记为 EXPECT_DIFF，实际无差异，已保留偏差”。

## 11. 测试标准

1. **初始一致**：两版初始 label 与 intensity 逐字相同；不同即 `FAIL`。
2. **单一变量**：除背景外，场景/关系/权力/亲近/开场/用户回应逐字一致。
3. **预登记**：每对必须标 `EXPECT_DIFF` 或 `EXPECT_NO_DIFF`；不得留空。
4. **分类完整**：每对结果必须是 PASS / NO_EFFECT / FAIL-C / FAIL-X 之一，并写理由。不得只写“FAIL”。
5. **盲评分母**：识别率只用 `EXPECT_DIFF` 且完成盲评的样本；`NO_EFFECT` 单独统计。
6. **不强行差异**：`EXPECT_NO_DIFF` 的样本若出现差异，必须检查控制变量，无依据判 `FAIL`。
7. **偏差记录**：预登记与结果不一致时，必须保留 `expected` 与 `actual` 两行。
8. **四组规模**：家庭/职场/亲密关系/朋友各 1 对；有效样本不足 3 对时报告“样本不足”。
9. **安全**：两版均通过 `safety` 检查；不出现辱骂/威胁/无底线答应。
10. **分母公式**：构造“6 对 EXPECT_DIFF、1 对 NO_EFFECT、1 对 FAIL-X、1 对 FAIL-C、3 对正确识别”，
    必须算出 `N_valid_diff=4`、识别率 `3/4=75%`；不得把 NO_EFFECT 或 FAIL-X 算进分母。
11. **不得事后解释**：预登记 EXPECT_DIFF、实际无差异、且未预登记替代假设 → 判 `FAIL-C`，不得判 PASS 或 NO_EFFECT。
12. **FAIL-C 留分母**：失败样本必须留在 `N_valid_diff` 内，删除失败样本会改变识别率，测试需检出这种篡改。
13. **FAIL-X 单独统计**：控制变量不一致的样本必须标 `FAIL-X` 并排除出分母，但仍要报告数量。
14. **门槛未决**：在门槛获批前，报告只能列计数与识别率，不得写“整体通过”。
