4. 要求生成前**预登记**可能差异；比较重点改为触发敏感度、情绪变化、表达方式、人物诉求。

## 3. 核心问题

怎么证明“背景真的影响了人物”，而不是作者自我感觉良好？

单看一条语料，很难判断：人物反应是因为背景，还是因为作者就想让他这么反应。

## 4. 设计原理

### F（来源明确支持）

- PersonaConflicts 提供不同关系背景的子集，并用人工标注评估背景如何影响冲突感知。
- 这说明“控制背景、观察差异”是一种可操作的评估方式。

### A（我们对来源的分析）

- 只做单向写作，作者无法自查“背景是否起作用”。
- 对照法把“背景”变成唯一变量，差异才有解释力。
- 但对照不能证明“真实”，只能证明“设定被用上了”。
- 如果两版连初始情绪都不同，就无法判断差异来自背景还是来自起点——这是 v1 的漏洞。

### O（本产品原创设计）

- 成对自检：同一情景、同一开场、同一用户回应序列、**同一初始情绪**，只改人物背景（A/B 两版）。
- 生成前先写“预期差异表”，允许写“预计无差异”。
- 盲评只看“这版反应是否符合它的背景”，不评判好坏。

## 5. 具体规则

**R1 控制变量**（两版必须完全一致）：

- 情景、地点、时间；
- 关系类型、权力位置、亲近程度；
- 对方开场第一句；
- 用户的三轮回应（逐字一致）；
- **初始情绪状态（label + intensity，完全相同）**。

**R2 唯一变量**：人物背景（经历 A / 经历 B），不改变性格特质与表达倾向。

**R3 命名与记录**：

- 不再用“正/负”，改为**背景 A / 背景 B**；
- 分别写清具体经历，例：
  - 背景 A：昨天例会上被当众指出“方案没逻辑”；
  - 背景 B：昨天例会上被夸“方案很清楚”。

**R4 预登记差异**（生成前填，允许填“无差异”）：

| 维度 | 背景 A 预期 | 背景 B 预期 |
|---|---|---|
| 触发敏感度（哪句话会碰到） | 例：对“很快的”这类轻描淡写更敏感 | 例：不构成触发 |
| 情绪变化（方向/幅度） | 例：+1；或“不确定” | 例：0；或“不确定” |
| 表达方式 | 例：先问范围与责任 | 例：先答应，再给限制 |
| 人物诉求 | 例：想确认自己不是被否定 | 例：想维持合作 |

**R5 不预设方向**：

- 不写“背景 A 一定更愤怒”；
- 允许“背景 A 更克制、背景 B 更急”；
- 允许“两版几乎无差异”，只要写清为什么。

**R6 不强行制造差异**：

- 如果背景与当前事件没有可解释联系，就不要为了通过测试而加情绪、加台词；
- “无差异”是合法结果，记录为“背景未影响本轮”。

**R7 比较重点**：

1. 触发敏感度：同一句话在哪一版构成触发；
2. 情绪变化：delta 与方向（引用 M-101 v1.1）；
3. 表达方式：句长、称呼、追问/退让、是否翻旧账；
4. 人物诉求：更想证明自己，还是更想维持关系。

**R8 盲评**：

- 评审不知道哪版是 A、哪版是 B；
- 判断“这版反应是否分别符合 A/B 的背景”，而不是“哪版更好/更坏”；
- 允许评审判“两版都符合”或“两版都不符合”。

## 6. 输入条件

- 一条已写好的情景（含 M-112 v1.1 的链）；
- 两个背景版本（A/B），其余字段完全相同；
- 固定的三轮用户回应；
- 完全相同的初始情绪状态；
- 一名不知道分组的评审。

## 7. 输出结果

一张对照表 + 判定：

```text
配对：P-WRK-01（职场 · 临时加活）
初始情绪：两版均为 3/5，label=紧张
背景 A：昨天例会上被当众指出“方案没逻辑”
背景 B：昨天例会上被夸“方案很清楚”
同一请求：“你帮我改改呗，很快的。”

维度        预登记（A / B）        实际（A / B）              判定
触发敏感度  对“很快的”更敏感 / 不敏感   第 1 句即 +1 / 第 1 句 0     符合
情绪变化    +1 / 0                4 / 3                       符合
表达方式    先问范围与责任 / 先答应再限制  同左                      符合
诉求        证明自己 / 维持合作        同左                      符合
结论：背景影响了本轮（4/4）；未发现强行制造差异
```

也允许：

```text
结论：两版无显著差异（3/4 维度一致）；原因为当前事件与两段背景均无直接联系，判定“本轮背景未生效”，不改写。
```

## 8. 适用范围

- Phase 6 每条语料的自检（至少 1 对）；
- 方法卡 M-112 v1.1 的验证；
- 语料改版后的回归检查。

## 9. 不适用范围

- 证明“语料真实”（只能证明设定被用上）；
- 替代人工审核与盲评；
- 用外部数据集对话做对照样例（明确禁止）；
- 把背景 A/B 与“好人/坏人”对应；
- 用“必须有差异”作为通过条件。

## 10. 原创示例

情景：同事请你帮忙改方案（原创，非数据集文本）。

| 项 | 背景 A 版 | 背景 B 版 |
|---|---|---|
| 背景 | 昨天例会上被当众指出“方案没逻辑” | 昨天例会上被夸“方案很清楚” |
| 初始情绪 | 紧张 3/5 | 紧张 3/5（完全相同） |
| 同一句请求 | “你帮我改改呗，很快的。” | 同左（逐字一致） |
| 预登记差异 | 对“很快的”敏感；先问范围与责任 | 不敏感；先答应，再给限制 |
| 预期反应 | “改哪部分？最后谁定稿？” | “行，我看一下，但今天只能改一版。” |
| 禁止 | 不能写成“你还有脸找我” | 不能写成“没问题，全包我身上” |

两版都不是“好人/坏人”，只是经历不同，触发点与边界松紧不同。若实际写成两版完全一样，也要如实记录，不得为了“看起来有差异”硬改。

## 11. 测试标准

1. **初始一致**：两版初始 `label` 与 `intensity` 完全相同，逐字核对（v1 的“4/3”即不合格）。
2. **单一变量**：除背景外，场景、关系、权力、亲近、开场、用户三轮回应逐字一致。
3. **预登记**：生成前必须有预期差异表；允许“不确定/无差异”，但不得留空。
4. **不强行差异**：4 对中，若某对预登记为“无差异”，实际也必须如实记录，不得硬造。
5. **方向自由**：不要求“A 一定更愤怒”；允许反向或无差异，只要与预登记一致或有清楚解释。
6. **盲评**：4 对中 ≥ 3 对，评审能正确说出“这版反应更符合哪个背景”（不是判好坏）。
7. **四组规模**：家庭 1、职场 1、亲密关系 1、朋友 1。
8. **反漫画化**：两版都不出现辱骂、威胁、人身攻击；B 版不出现“无底线答应”。
9. **安全**：两版均通过 `safety` 字段检查。
