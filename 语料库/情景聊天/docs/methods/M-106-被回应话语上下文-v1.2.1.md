## 3. 核心问题

AI 会忘记自己刚问过什么，导致：

1. 用户已经回答了，AI 又问一遍；
2. 用户答的是上一轮的问题，AI 当成新话题；
3. 用户说“不知道”，AI 当成“问题解决了”；
4. 辅助回应生成了一句，用户没发，AI 却当成用户说了。

## 4. 设计原理

### F（来源明确支持）

- MPDD 的对话按说话顺序组织，每条话语有明确的说话人与听者；论文设置了实验观察“被回应话语对当前话语的影响”。
- 这说明：一句话的意思，取决于它在回应哪一句。

### A（我们对来源的分析）

- “回应关系”是对话不断线的关键；只按轮次存历史，会丢掉“这一句在答哪一句”。
- 短答很容易被误判：长度不等于信息量；“不知道”是回应，不是答案。
- “问题关闭”和“拿到答案”是两件事，混用会让 AI 要么追问不休，要么假装听懂。

### O（本产品原创设计）

- 三槽位 + 问题账本 + 主题栈 + 明确状态机。
- 状态机区分“反应 / 答案 / 拒绝 / 关闭”，并允许关闭但无信息。
- 辅助回应与正式对话严格隔离；复盘只认最终发送内容。

## 5. 具体规则

### 5.1 三槽位

| 槽位 | 内容 | 作用 |
|---|---|---|
| current | 用户这一句（**已发送**） | 本轮要接的话 |
| replyTo | 它回应的是 AI 上一句，还是更早的某句 | 判断“是不是在回答” |
| openQuestion | AI 最近提出、尚未结束的问题 | 防止重复问 |

### 5.2 状态机（层级明确）

```text
OPEN
  ↓
RESPONDED
  ├── ANSWERED
  │      ↓
  │   RESOLVED（不再需要追问）
  │
  ├── REFUSED
  │      ↓
  │   RESOLVED
  │
  └── 两次无信息
         ↓
      RESOLVED（未获信息）

特殊：是/否问题，用户直接给“是/否” → OPEN 可直接进入 ANSWERED
```

| 状态 | 定义 | 判定依据 | 是否关闭 |
|---|---|---|---|
| **OPEN** | 已提问，尚无反应 | AI 刚提出 | 否 |
| **RESPONDED** | 用户对问题作出了反应 | 有针对性消息（含“不知道”“随便”） | 否 |
| **ANSWERED** | 用户提供了实际答案 | 填上问题要的信息/立场 | 否（可转 RESOLVED） |
| **REFUSED** | 用户明确不愿回答 | “不想说”“别问了” | 否（可转 RESOLVED） |
| **RESOLVED** | 不再需要追问 | 已回答 / 已拒绝 / 两次无信息 / 话题已转移 | **是** |

**关键**：`RESOLVED` 是关闭状态，**不保证拿到了有效信息**。关闭原因必须记录（answered / refused / no_info / topic_shift）。

### 5.3 状态转移规则

1. **OPEN → ANSWERED（是/否问题）**：上一轮是“是/否”问句，用户回“是/对/不/没有”，直接 `ANSWERED`。
2. **OPEN → RESPONDED**：用户有任何针对性反应；开放问题收到“不知道/还行/随便”属此列。
3. **RESPONDED → ANSWERED**：后续补充了实际信息或立场。
4. **RESPONDED → RESOLVED（no_info）**：允许一次改写追问，仍无信息，关闭；**不得重复原问**。
5. **RESPONDED → REFUSED**：用户明确拒绝；立即停止追问。
6. **REFUSED → RESOLVED**：关闭，可接一句情绪。
7. **话题转移**：旧问题不自动 `RESOLVED`；若是核心诉求，允许 2 轮内拉回一次；拉不回 → `RESOLVED（topic_shift）`。
8. **同一问题 3 轮内不得重复问**；用户连续 2 次回避后不再追问。

#### 5.3.1 补充：ANSWERED 何时转 RESOLVED

`ANSWERED` 不自动等于关闭，满足以下任一才转 `RESOLVED`：

1. 问题所需信息已获得，且没有必须追问的后续；
2. 用户明确表示“就这些”“不说了”，问题不再需要推进；
3. 新话题已经取代旧问题，且旧问题不再是核心诉求；
4. 答案不完整，但已用尽一次澄清机会，且继续追问会变成逼问。

**部分回答**：

- 记为 `ANSWERED`，内部标记 `completeness=partial`（不新增正式状态）；
- 允许**一次**澄清（换角度、缩小范围）；
- 澄清后仍不完整 → `RESOLVED（closedReason=partial_info）`，记录“信息不完整”，不得说“已问清”。

**答案引出新问题**：

- 旧问题 `RESOLVED（answered）`；
- 新问题另开账本，`OPEN`；
- 不得把两个问题混在一条账本里。

**关闭原因**扩展为：`answered / partial_info / refused / no_info / topic_shift`。

**不允许**：把 `RESOLVED` 当“已获得完整信息”；把“部分回答”直接标 `no_info`；用同一问题反复追问来补信息。

### 5.4 问题账本

```text
{ question, askedAtTurn, state, attempts, closedReason }
```

每次状态变化都记录；`closedReason ∈ {answered, refused, no_info, topic_shift}`。

### 5.5 辅助回应：三类对象必须分开

| 对象 | 定义 | 处理 |
|---|---|---|
| **未发送建议** | AI 生成、仍在输入框 | 不进历史、不触发 M-101、不参与 M-106 状态流转、不改变主题栈 |
| **编辑后发送的内容** | 用户最终发出的文本 | **正式对话记录**；按最终文本打标、更新情绪、推进状态 |
| **辅助使用记录** | “这次用了辅助回应”这一事实 | 若产品有独立记录能力，可标注来源；**不等于**用户原话 |

规则：

1. 未发送建议不是“用户说过的话”，不得进入 `replyTo` 判定。
2. 未发送建议不得关闭 `openQuestion`，不得改变主题栈。
3. 用户发送后，以最终发送内容为准；中间编辑版本不保留、不参与判定。
4. 复盘以**最终发送内容**为依据；不得把 AI 原始建议当作“用户原话”引用。
5. 若产品具备独立记录能力，可标注“改自建议”，但必须与用户自己写的区分；**不得冒充**。
6. **本次不修改 Schema**；若现有系统无法承载独立记录，列为产品待决策事项（见 README「尚未解决」）。

### 5.6 禁止

- 重复问同一句；
- 复述用户原话当回应；
- 把“不知道”当“已解决”；
- 把未发送建议当用户发言；
- 把关闭状态说成“已经问清楚了”。

## 6. 输入条件

- 最近 4 轮**已发送**的对话；
- 问题账本（状态、尝试次数、关闭原因）；
- 主题栈；
- 本轮话语功能标签（M-102，仅对已发送消息）；
- 当前情绪状态（M-101）。

## 7. 输出结果

```text
上下文块：
- 用户在回应：AI 第 3 轮的问题“你今年有什么打算？”
- 状态：RESPONDED（“不知道”），未 ANSWERED
- 账本：attempts=1；允许一次改写追问
- 主题：催婚（当前）；工作（暂存）
- 允许动作：接住“不知道”，换角度问一次；不得重复原问
```

## 8. 适用范围

- 所有 AI 扮演对方的演练；
- 辅助回应（判断是否该提新问题）；
- 复盘（还原“哪句在答哪句”）。

## 9. 不适用范围

- 多人对话、群聊（一期不做）；
- 普通 AI 聊天（诺的上下文由现有 `cleanHistory` 处理）；
- 需要长程记忆的跨会话对话；
- 用状态机给用户“沟通能力”打分。

## 10. 原创示例

```text
AI：你今年有什么打算？
用户：不知道。
AI（正确）：是还没想，还是不太想跟我说？
```

状态：`RESPONDED`（不是 `ANSWERED`，也不是 `RESOLVED`）；允许一次改写追问。

```text
AI：今天还加班吗？
用户：不。
```

状态：`OPEN → ANSWERED`（是/否问题直接回答），随后可 `RESOLVED`。

错误版本（禁止）：

```text
AI：那你今年有什么打算？
```

（机械重复原问，且把“不知道”当没听见。）

若用户接着说“不想说”，则 `REFUSED → RESOLVED`，AI 不再追问。

## 11. 测试标准（20 组完整交互）

不再用“给一句回复分类”的方式测试。改为 **20 组完整提问—回复交互**，逐组验证状态转移。

| # | 场景 | 交互要点 | 预期转移 |
|---:|---|---|---|
| 1 | 是/否：肯定 | Q：“今天还加班吗？” R：“不。” | OPEN → ANSWERED → RESOLVED（answered） |
| 2 | 是/否：否定 | Q：“吃了吗？” R：“吃了。” | OPEN → ANSWERED → RESOLVED |
| 3 | 不知道 | Q：“今年有什么打算？” R：“不知道。” | OPEN → RESPONDED（不关闭） |
| 4 | 模糊回答 | R：“还行吧。” | RESPONDED；最多一次澄清 |
| 5 | 部分回答 | R：“先攒钱，别的没想。” | ANSWERED（partial）；一次澄清 |
| 6 | 完整回答 | R：“明年换工作，先考证。” | ANSWERED → RESOLVED（answered） |
| 7 | 明确拒绝 | R：“不想说。” | REFUSED → RESOLVED（refused） |
| 8 | 两次无信息 | R1：“不知道。” R2：“随便。” | RESPONDED → RESPONDED → RESOLVED（no_info） |
| 9 | 话题转移、不拉回 | R 换到“先吃饭吧”，旧问题非核心 | 旧问题 RESOLVED（topic_shift） |
| 10 | 话题转移、拉回一次 | R 换话题，AI 拉回一次后回答 | 旧问题继续，随后 ANSWERED |
| 11 | 辅助未发送 | 生成建议但未发送 | 历史/账本/情绪均不变 |
| 12 | 辅助编辑后发送 | 建议被改写后发送 | 以最终文本更新状态 |
| 13 | 短答 yes/no | Q 是/否，R：“嗯。” | ANSWERED（不判 RESPONDED 卡住） |
| 14 | 答案引新问题 | R 回答后又提到新问题 | 旧 RESOLVED（answered），新 OPEN |
| 15 | 已回答、无需追问 | R 给出完整立场 | ANSWERED → RESOLVED |
| 16 | 已回答、需澄清 | R 只给一半信息 | ANSWERED（partial）；一次澄清后关闭或补全 |
| 17 | 拒绝后换话题 | R 拒绝，随后换话题 | REFUSED → RESOLVED（refused）；新话题另开 |
| 18 | 重复提问禁止 | 3 轮内同一问题再次出现 | 不得重复；应换角度或关闭 |
| 19 | 两次回避 | 用户两次不接同一问题 | 不再追问；RESOLVED（no_info） |
| 20 | 关闭后新问题 | 旧问题已关闭，AI 提新问题 | 新 OPEN；旧保持 RESOLVED |

判定：

1. 20/20 组的状态转移与上表一致才算通过；任一组不一致必须记录并复测。
2. 第 11 组必须验证“未发送建议不改变任何状态”。
3. 第 12 组必须验证“以最终发送文本为准”。
4. 若因文案歧义导致判定分歧，先修文案再复测，不得直接改预期。
5. 本测试是**设计级测试**；在有运行环境前只能做桌演，不得声称已运行通过。
