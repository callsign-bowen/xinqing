## 六张方法卡的整体协作架构

先分清两个阶段：**语料生产阶段**（写之前）与**实际运行阶段**（对话中）。
M-112 与 M-114 只属于生产阶段，**不是每轮对话都要跑的分析流程**。

### A. 语料生产阶段

```text
M-104 确定人物关系和权力背景（分领域矩阵，不合并）
   ↓
M-112 建立人物背景与触发链（场景层至少一个激活点；单轮允许无触发）
   ↓
M-101 确定稳定人格与情绪规则（触发/衰减/净变化三变量、唯一更新入口）
   ↓
原创情景对话设计（按 C-001 方案 B：用户演自己，AI 演对方）
   ↓
M-114 背景 A/B 对照验证（PASS / NO_EFFECT / FAIL-C / FAIL-X）
   ↓
人工审核与安全审核（五关 + 非作者签字）
```

### B. 实际运行阶段

```text
用户输入
   ↓
第一道安全检查（输入侧，最高优先级）
   ↓
M-106 识别上下文与被回应话语（OPEN→RESPONDED→ANSWERED/REFUSED→RESOLVED）
   ↓
M-102 识别用户话语功能（六类 + OTHER/UNCERTAIN，仅线索）
   ↓
M-101 判断实际情绪触发并更新状态（唯一入口；triggerDelta/decayDelta/netDelta）
   ↓
M-104 约束人物表达方式（称呼由关系定；权力/亲近调直接程度）
   ↓
DeepSeek 生成 AI 对方回应
   ↓
第二道安全检查（输出侧，拦截越界内容）
   ↓
向用户展示
```

### 协作要点

- **M-101 是唯一情绪数值更新入口**：其余卡只提供线索/约束，不得各自加数值。
- **M-102 只提供线索**：功能不等于对方理解；线索未过四问，不封锁 M-101 从内容/关系/修复事件发现触发。
- **M-104 只约束表达**：决定“怎么说”，不决定“想不想说”，也不授权伤害。
- **M-106 只管理上下文**：状态机与账本，不直接生成台词。
- **M-112 是写作链**：生产期建立背景与触发链；运行时不重建，只读取产物。
- **M-114 是质量门**：生产期验证 M-112；运行时不存在这个模块。
- **辅助回应隔离**：未发送建议不进历史、不触发 M-101、不改 M-106 状态。
- 上面两条流程是**逻辑编排建议**，不要求每轮机械执行全部模块；简单回合可只走 M-106 → M-102 → M-101。

## 安全检查流程

| 位置 | 职责 | 规则 |
|---|---|---|
| **输入侧（第一道）** | 用户消息进入编排前 | 命中 `safety.stopSignals` / 高风险表达 → 停止演练、走 `high_risk_protocol`；不进入 M-106/M-102/M-101 |
| **输出侧（第二道）** | DeepSeek 生成后、展示前 | 拦截辱骂、威胁、羞辱、越界施压、诊断性断言；命中则替换为安全回应或退出 |
| **辅助回应** | 生成建议时 | 同样过输出侧检查；只填入输入框，不发送 |

- 两道检查都优先于任何方法卡规则；方法卡与 safety 冲突时，以 safety 为准。
- 输出侧检查不依赖语料，不能因为“人物设定如此”而放行。

## 使用规则

1. 方法卡只描述“怎么写、怎么判”，不提供可直接发送的台词模板。
2. 任何方法卡都不能覆盖 `safety` 字段与高风险流程。
3. 不新增 Schema 字段；输入/输出用自然语言映射到现有字段。
4. 引用来源仅作结构启发，不复制对话、不下载数据；来源保持 `research_only` / `pending`。
5. 未经第四轮审核，不得把任何一张卡标为 `approved`，也不得据其批量生产语料。
