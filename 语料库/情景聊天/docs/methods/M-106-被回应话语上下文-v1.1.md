## 3. 核心问题

AI 会忘记自己刚问过什么，导致三种常见故障：

1. 用户已经回答了，AI 又问一遍；
2. 用户答的是上一轮的问题，AI 当成新话题；
3. 用户说“不知道”，AI 当成“问题解决了”，直接换话题。

v1.1 要解决的还有第四种：

4. 辅助回应生成了一句，用户没发，AI 却当成用户说了。

## 4. 设计原理

### F（来源明确支持）

- MPDD 的对话按说话顺序组织，每条话语有明确的说话人与听者；论文设置了实验观察“被回应话语对当前话语的影响”。
- 这说明：一句话的意思，取决于它在回应哪一句。

### A（我们对来源的分析）

- “回应关系”不只是一个研究变量，它是对话不断线的关键。
- 现有逐轮交替的对话系统，常把历史当成一袋文本，丢掉了“这一句在答哪一句”的结构。
- 短答很容易被误判：长度不等于信息量，“不知道”是回应，不是答案。

### O（本产品原创设计）

- 三槽位：当前话语、被回应话语、未闭合问题；加“问题账本”和“主题栈”。
- 问题状态机：`OPEN → RESPONDED → ANSWERED / REFUSED → RESOLVED`。
- 辅助回应与正式对话**状态隔离**：只有发送后才进入对话状态。

## 5. 具体规则

### 5.1 三槽位

| 槽位 | 内容 | 作用 |
|---|---|---|
| current | 用户这一句（**已发送**） | 本轮要接的话 |
| replyTo | 它回应的是 AI 上一句，还是更早的某句 | 判断“是不是在回答” |
| openQuestion | AI 最近提出、尚未结束的问题 | 防止重复问 |

### 5.2 四个状态（必须分清）

| 状态 | 定义 | 判定依据 | 下一步 |
|---|---|---|---|
| **已回应 RESPONDED** | 用户对问题作出了反应 | 有任何针对该问题的消息（含“不知道”“随便”） | 可接话；不重复原问 |
| **已回答 ANSWERED** | 用户提供了实际答案 | 消息填上了问题要的信息/立场 | 可推进；不必再问 |
| **已解决 RESOLVED** | 该问题不再需要追问 | 已回答 / 已拒绝 / 两次无信息后关闭 | 移出账本 |
| **已拒绝 REFUSED** | 用户明确不愿回答 | “不想说”“别问了”“跟你没关系” | 停止追问；可接情绪 |

关键区分：

- **已回应 ≠ 已回答**：“不知道”是回应，但没有提供答案。
- **已回答 ≠ 已解决**：答案可能引出新问题；是否解决看“还需不需要追问”。
- **已解决 ≠ 已获得信息**：两次无信息后关闭，也算解决（不再追问），但要记录“未获信息”。

### 5.3 回答识别规则

1. **只对已发送的消息判定**；未发送的辅助回应不参与。
2. **短答**（≤ 6 字，或“嗯/对/是/还行/没有/不知道”）先判 `RESPONDED`，再判断是否 `ANSWERED`：
   - 上一轮是“是/否”问题，“嗯/对”可判 `ANSWERED`；
   - 上一轮是开放问题，“不知道/还行”判 `RESPONDED`，不是 `ANSWERED`。
3. **允许自然复述/确认/换说法**：“你是说，你还没想好？”——这是确认，不是机械重复。
4. **禁止机械重复用户原句**：不得把用户的话原样再问一遍（“你说你不知道？”）。
5. **一次改写追问**：`RESPONDED` 但未 `ANSWERED` 时，允许换一个角度问一次；仍无信息 → 标 `RESOLVED`（原因：未获信息），不再追问。
6. **已拒绝立即停止**：判 `REFUSED` 后不再问同一问题，可接一句情绪。
7. **换话题不等于必须回原题**：用户转移话题时，旧问题压栈；若是核心诉求，允许 2 轮内拉回一次，拉不回就 `RESOLVED`（原因：已转移）。

### 5.4 问题账本

每个问题记录：

```text
{ question, askedAtTurn, state, attempts, lastReason }
```

状态流转：

```text
AI 提问 → OPEN
用户有反应 → RESPONDED（attempts +1）
提供信息/立场 → ANSWERED → 可标 RESOLVED
明确拒绝 → REFUSED → RESOLVED
两次无信息 → RESOLVED（未获信息）
话题转移且未拉回 → RESOLVED（已转移）
```

同一问题 3 轮内不得重复问；用户连续 2 次回避后不再追问。

### 5.5 辅助回应状态隔离（硬规则）

1. 辅助回应生成后，**只进入输入框**。
2. **未发送**的辅助回应**不能**被视为用户真实表达。
3. **未发送**的建议**不能**改变正式对话历史。
4. **未发送**的建议**不能**触发 M-101 的情绪更新。
5. 用户**真正发送后**，才用实际发送的内容（可能已被编辑）进行 M-102 打标、M-101 更新与 M-106 状态流转。

补充：未发送的建议也不进入 `replyTo` 判定，不关闭 `openQuestion`，不改变主题栈。辅助回应是否记入历史与复盘（Q2）仍未裁决，本卡不预设。

### 5.6 禁止

- 不重复问同一句；
- 不复述用户原话当回应；
- 不在用户已回答后假装没听见；
- 不把“不知道”当“问题解决”；
- 不把未发送的辅助回应当用户发言。

## 6. 输入条件

- 最近 4 轮**已发送**的对话（用户 + AI 对方）；
- 问题账本（每个问题的状态、尝试次数、原因）；
- 主题栈；
- 本轮话语功能标签（M-102，仅对已发送消息）；
- 当前情绪状态（M-101）。

## 7. 输出结果

```text
上下文块：
- 用户在回应：AI 第 3 轮的问题“你今年有什么打算？”
- 状态：RESPONDED（“不知道”），未 ANSWERED
- 账本：attempts=1；允许一次改写追问
- 主题：催婚（当前）；工作（暂存）
- 允许动作：接住“不知道”，换角度问一次；不得重复原问
```

## 8. 适用范围

- 所有 AI 扮演对方的演练；
- 辅助回应（判断用户是否在回答、是否该提新问题）；
- 复盘（还原“哪句在答哪句”）。

## 9. 不适用范围

- 多人对话、群聊（一期不做，听者集合见 M-105，未批准）；
- 普通 AI 聊天（诺的上下文由现有 `cleanHistory` 处理，不套用）；
- 需要长程记忆的跨会话对话；
- 用状态机给用户“沟通能力”打分。

## 10. 原创示例

原创对话（非数据集文本）：

```text
AI：你今年有什么打算？
用户：不知道。
AI（正确）：是还没想，还是不太想跟我说？
```

判定：`RESPONDED`，不是 `ANSWERED`，也不是 `RESOLVED`；允许一次改写追问。

错误版本（禁止）：

```text
AI：那你今年有什么打算？
```

（机械重复原问，且把“不知道”当成没听见。）

若用户接着回“不想说”，则判 `REFUSED` → `RESOLVED`，AI 不再追问，只接一句：“行，那先不聊这个。”

## 11. 测试标准

1. **四状态判定**：20 条用户回复，分别归入 RESPONDED / ANSWERED / RESOLVED / REFUSED，人工一致率 ≥ 85%。
2. **“不知道”测试**：开放问题 + “不知道” → 必须判 RESPONDED，不得直接 RESOLVED；允许一次改写追问。
3. **短答回落**：是/否问题 + “嗯” → 可判 ANSWERED；开放问题 + “还行” → RESPONDED。
4. **重复提问率**：10 段原创对话（每段 8 轮），同一问题重复率 = 0。
5. **两次回避**：连续两次无信息后，AI 不再追问（人工检查 5 例）。
6. **话题转移**：用户换话题后，AI 拉回次数 ≤ 1；拉不回则关闭问题。
7. **辅助回应隔离**：生成但不发送时，历史不变、情绪不变、账本不变；发送后才更新（5 项逐条检查）。
8. **不机械复述**：10 段对话中，AI 原样重复用户整句的次数 = 0。
