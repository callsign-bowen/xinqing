## 3. 核心问题

同一个人物，怎么做到既“始终是同一个人”，又“这一轮真的生气了”？

v1.1 解决了重复计算，但留下两个漏洞：

1. **衰减识别不了**：P5 既当“中性事件”又当“无事件”，连续两轮的判断没有可靠依据。
2. **强度被当成情绪的全部**：4/5 的愤怒、悲伤、焦虑被写成同一种东西。

## 4. 设计原理

### F（来源明确支持）

- CPED 为角色标注了稳定属性（姓名、性别、年龄段、Big Five）与逐条话语的情感极性、13 类情绪、19 类对话行为。
- CPED 的统计显示，平均每段对话出现约 2.8–3.4 种情绪，说明情绪在对话内确实会变。

### A（我们对来源的分析）

- CPED 只有“点”没有“线”：它标了每句话是什么情绪，但没有写“什么触发、升到多高、怎么回落”。
- 多标签并存（情绪 + DA + 人格）如果没有合并规则，就会在生成侧变成重复加权。
- “中性”和“没有事件”是两件事：前者是一种内容，后者是“这一轮什么都没发生”。

### O（本产品原创设计）

- 三层结构不变：**稳定人格层 → 动态情绪层 → 表达层**。
- 情绪层每轮只有一个入口：`primaryTrigger`；只有一个出口：一次 `delta ∈ {−1, 0, +1}`。
- 无触发不是一种触发，而是一个独立分支（P5），专门负责计数与衰减。
- 强度是“多大”，效价与唤醒度是“什么情绪、有多激动”，三者不互相替代。

## 5. 具体规则

### 5.1 三层与内部状态

| 层/状态 | 内容 | 是否随单轮变化 |
|---|---|---|
| 人格层 P | 3–5 个可观察特质、1–2 条价值观、1–3 个恐惧、2–4 个触发点、1–3 个降温点、voice 参数 | **不变** |
| 情绪层 E | `label`、`intensity`（1–5）、`primaryTrigger`、`sinceTurn` | 每轮最多变一次 |
| 无触发计数 | `consecutiveNoTriggerTurns`（整数，初始 0） | 每轮更新 |
| 表达层 X | 句长、称呼、反问/重复/沉默、策略选择 | 由 P、E、关系共同决定 |

> `consecutiveNoTriggerTurns` 是内部编排状态，**不写入 Schema、不新增字段**。

### 5.2 触发类别与 P5 的定位

| 规则 | 含义 | delta |
|---|---|---|
| P1 | 边界侵犯或越界（未达 safety 硬停） | +1 |
| P2 | 核心恐惧 / 触发点命中 | +1 |
| P3 | 面子、比较、被要求、被忽视 | +1 |
| P4 | **真正发生的**修复、被接住、收到具体安排 | −1 |
| **P5** | **本轮没有具体触发事件**（不是事件） | 0 |

**P5 不是候选事件**。它表示“这一轮没有可选事件”，不是“有一个中性事件”。

### 5.3 变量定义与唯一更新算法

#### 5.3.1 三个变量（替代单一 `delta`）

| 变量 | 含义 | 取值 |
|---|---|---|
| `triggerDelta` | 本轮**触发事件**造成的强度变化 | −1 / 0 / +1 |
| `decayDelta` | 本轮**无触发衰减**造成的强度变化 | −1 / 0 |
| `netDelta` | 本轮实际变化（更新后 − 更新前） | −1 / 0 / +1 |

规则：

1. 每轮最多一个 `triggerDelta`；`P1–P3` 为 +1，`P4` 为 −1，`P5` 为 0。
2. `decayDelta` 只在“本轮无触发且 `consecutiveNoTriggerTurns >= 2`”时出现。
3. 两者**不得叠加**：一轮要么走触发分支，要么走衰减分支。
4. `netDelta` 是实际变化：达到上限 5 时 `triggerDelta=+1`，但 `netDelta=0`，仍需记录触发。
5. 强度始终 `clamp` 在 1–5。

#### 5.3.2 伪代码

```text
state:
  intensity ∈ [1, 5]
  consecutiveNoTriggerTurns >= 0

each turn:
  candidates = collect(e1, e2, e3, e4)      # 只收集，不计算
  primary = selectByPriority(candidates)     # P1 / P2 / P3 / P4 / null
  triggerDelta = 0
  decayDelta = 0
  before = intensity

  if primary != null:                       # 有具体触发
      triggerDelta = (+1 if primary in {P1,P2,P3} else -1)   # P4 = -1
      intensity = clamp(before + triggerDelta, 1, 5)
      consecutiveNoTriggerTurns = 0
  else:                                      # 无具体触发（P5 分支）
      consecutiveNoTriggerTurns += 1
      if consecutiveNoTriggerTurns >= 2:
          decayDelta = -1
          intensity = max(1, before - 1)
          consecutiveNoTriggerTurns = 0

  netDelta = intensity - before
  audit(primary, triggerDelta, decayDelta, netDelta,
        consecutiveNoTriggerTurns, before, intensity)
```

#### 5.3.3 三个执行示例

**示例 1：正常触发**

```text
初始 intensity=2, counter=0
本轮 primary=P2
triggerDelta=+1, decayDelta=0
after=3, netDelta=+1, counter=0
```

**示例 2：连续两轮无触发**

```text
第 1 轮：primary=null → counter=1, intensity=3, triggerDelta=0, decayDelta=0, netDelta=0
第 2 轮：primary=null → counter=2 → 触发衰减 → intensity=2, decayDelta=-1, counter=0, netDelta=-1
第 3 轮：primary=null → counter=1, intensity=2, netDelta=0（未衰减）
```

**示例 3：上限边界仍记录**

```text
初始 intensity=5
本轮 primary=P1（边界侵犯）
triggerDelta=+1
clamp 后 intensity=5，netDelta=0
审计仍记录 primary=P1、triggerDelta=+1、netDelta=0
counter 归零
```

#### 5.3.4 与旧 `delta` 的兼容

- v1.2 的单个 `delta` 在 v1.2.1 中拆为 `triggerDelta` / `decayDelta` / `netDelta`。
- `delta` 是内部编排字段，**不在 Schema 中**；拆分不改 Schema、不改语料文件。
- 旧文档若写“delta=+1”，在本版中对应 `triggerDelta=+1, netDelta=+1`；衰减对应 `decayDelta=-1`。
- 审计时必须同时记录三个变量，禁止只记 `netDelta`。

**优先级顺序**（只在“存在多个事件”时用于选一个，不求和）：

```text
P0 安全停信号 → 直接退出，不进情绪规则
P1 边界侵犯/越界（未达硬停）
P2 核心恐惧/触发点命中
P3 面子/比较/被要求/被忽视
P4 修复/接住/具体安排
P5 无触发（不是事件）
```

### 5.4 硬规则

1. **每轮最多一次 `triggerDelta`**：不允许出现两个触发 delta，不允许“先 +1 再 −1”；`decayDelta` 只在无触发分支出现。
2. **同一事件只算一次**：功能、内容、关系若指向同一句话，合并为一个 `primaryTrigger`。
3. **同一句话跨轮不重复**：原样重复不再次 +1；出现新信息（新比较对象、新后果）才算新事件。
4. **达到上下限仍记录**：强度已经是 5 时命中 P1，仍记录 `primaryTrigger=P1`、`delta=0（已达上限）`；不能因为“没变化”就不记。
5. **P5 不参与选主触发**：P5 只用于计数与衰减。
6. **人格不产生数值**：人格与倾向只改变表达，不改 `intensity`。

### 5.5 表达倾向（不是人格类型）

“回避 / 控制 / 退让 / 直接”是**表达的默认倾向**，不是人物分类，也不是诊断标签。同一个人可以在不同关系里表现出不同倾向。

| 倾向 | 高强度时的表达 | 对数值的影响 |
|---|---|---|
| 回避倾向 | 句子更短、沉默、转移话题 | **无** |
| 控制倾向 | 重复要求、强调自己的判断、追问“你听明白没有” | **无** |
| 退让倾向 | 表面妥协、措辞变软，但内部强度不降 | **无**（内部与外部分开记） |
| 直接倾向 | 少缓冲、直接说不满，句长不一定变 | **无** |

### 5.6 表达映射

| 强度 | 表达特征 |
|---|---|
| 1–2 | 短句、少问、冷淡或客套 |
| 3 | 正常对话，一问一答 |
| 4–5 | 反问、重复、打断、翻旧账；**不辱骂、不威胁、不施压到人身** |

注意：表达强度 ≠ 情绪强度。退让倾向可以“声音很轻、态度很软”，内部强度仍是 4。

### 5.7 intensity / valence / arousal / conflict 的关系

| 概念 | 含义 | 取值范围 | 与 intensity 的关系 |
|---|---|---|---|
| `intensity` | 情绪有多强（内部编排量） | 1–5 | — |
| `valence` | 正负效价 | −5…5 | 不是强度的线性映射 |
| `arousal` | 唤醒/激动程度 | 1–5 | 不是强度的线性映射 |
| `conflict` | 冲突程度（情景层） | 1–5 | **不等于**情绪强度 |

同一个 4/5，可以是：

| 情绪 | intensity | valence | arousal |
|---|---|---|---|
| 愤怒 | 4 | −4 | 5 |
| 悲伤 | 4 | −4 | 2 |
| 焦虑 | 4 | −3 | 4 |

因此：

1. 不建立 `intensity → valence/arousal` 的机械公式；
2. 写作时先定“多大”，再定“什么情绪”，再写效价与唤醒；
3. `conflict.initial/peak` 只描述冲突程度，不直接当情绪强度用；
4. 现有 Schema 保持不变，暂不新增字段。

### 5.8 人格不重置与复位

- 一场演练内，人格层字段不变；单轮情绪不得改写特质。
- 演练结束，情绪归位；人格原样保留；下一条语料重新初始化，不跨情景继承。

### 5.9 情绪 label 是否允许转换（待决策，本版不定案）

v1.2.1 只定义 `intensity` 的变化，**不定义 label 的转换**。两种方案：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. label 固定** | 一场演练内主情绪 label 不变，只变强度 | 一致、可审计；不会出现“愤怒突然变悲伤”；适合 MVP | 情绪层次较单薄；长对话可能显得平 |
| **B. label 可转换** | 允许随新触发事件改变 label，并定义转换条件 | 更接近真实情绪流；可支撑情绪弧 | 需要转换表（何时、从什么到什么、是否可逆）；缺乏验证依据时容易漂移或标签化 |

**推荐（仅供参考，未批准）**：Phase 5 先用 A，保证可复现；等有足够的审校样例后再评估 B，并先写转换表与测试。

**决策前约束**：

1. 本版不引入任何 label 转换规则；
2. 语料若需要 label 转换，必须作为“待审变更”单独提出，不得默认写入；
3. 运行时不自行创造 label 转换；
4. 该决策由产品负责人作出，本卡不代替。

## 6. 输入条件

- `persona` 块（特质、恐惧、触发、降温、voice）；
- 当前情绪状态（`label`、`intensity`、`sinceTurn`、`consecutiveNoTriggerTurns`）；
- 最近 1–2 轮对话；
- 本轮候选事件（M-102 功能、M-106 上下文、M-104 关系背景）；
- 安全信号（优先判定）。

缺任一项，不生成情绪变化，只维持上一轮状态，并记录原因。

## 7. 输出结果

```text
人格：操心、爱比较、嘴硬心软；怕被亲戚议论；触发=被说“你别管”
本轮：primaryTrigger=P2（“我有自己的节奏”被她理解为被推开）
情绪：委屈 2 → 3；consecutiveNoTriggerTurns=0
表达：控制倾向 → 反问、重复；句长 ≤ 15 字；不辱骂
审计：triggerDelta=+1；decayDelta=0；netDelta=+1；未叠加 M-102 的“解释”标签；未衰减
```

无触发时：

```text
本轮：primaryTrigger=null；appliedRule=P5；delta=0
情绪：维持 3；consecutiveNoTriggerTurns=1（未衰减）
表达：正常接话
```

## 8. 适用范围

- 所有 AI 扮演对方的情景对话；
- 家庭、亲密关系、职场中高冲突场景；
- Phase 7 的 system prompt 与情绪状态更新逻辑。

## 9. 不适用范围

- 普通 AI 聊天（诺的人格由 `NUO_PERSONA` 定义）；
- 心理评估、人格测评、诊断；
- 跨会话的用户画像与长期记忆；
- 需要“人物突然性情大变”的剧情。

## 10. 原创示例

情景：母亲催婚（原创，非数据集文本）。初始强度 2，初始计数 0。

| 轮次 | 用户（女儿） | 事件判定 | primaryTrigger | delta | 更新后强度 | 计数 |
|---|---|---|---|---|---|---|
| 1 | “我有自己的节奏。” | 她理解为被推开（P2） | P2 | +1 | 2 → 3 | 0 |
| 2 | “今天加班到九点。” | 与她的担心无关 | null（P5） | 0 | 3 | 1 |
| 3 | “先吃饭吧。” | 仍无触发 | null（P5） | −1（衰减） | 3 → 2 | 0 |
| 4 | “表姐是表姐。” | 被比较（P3） | P3 | +1 | 2 → 3 | 0 |

**边界示例**：若第 4 轮强度已是 5，仍记 `primaryTrigger=P3`、`delta=0（已达上限）`，计数归零。

**错误写法（禁止）**：第 1 轮同时记“功能=解释 +1”“恐惧命中 +1”“控制倾向 +1”，一轮从 2 到 5。

## 11. 测试标准

1. **衰减闭环**：构造连续两轮无触发，第 2 轮强度 −1、计数归零；第 3 轮无触发时计数从 0 开始。
2. **P5 不是事件**：检查审计记录，P5 轮次 `primaryTrigger` 必须为 `null`，不得写成“P5 事件”。
3. **有触发归零**：任意 P1–P4 轮次后，`consecutiveNoTriggerTurns` 必须为 0。
4. **单轮唯一变化**：10 轮原创对话，任意一轮 `|delta| ≤ 1`。
5. **不重复计入**：构造“功能=施压 + 命中恐惧 + 控制倾向”同现的一轮，结果只能 +1。
6. **边界记录**：强度 5 时命中 P1，仍记录触发与 `delta=0`。
7. **范围**：任何情况下 1 ≤ intensity ≤ 5。
8. **四概念检查**：同一 intensity=4 的愤怒/悲伤/焦虑，valence 与 arousal 必须不同；不得用同一组数值。
9. **conflict 独立**：`conflict.peak=5` 的语料，情绪 intensity 可以是 3；不得直接等同。
10. **人格不重置**：10 轮后 `persona` 字段逐字不变。
11. **盲评**：非作者读 10 轮，判断“像同一个人”≥ 80%。
12. **三变量审计**：每一轮都必须同时记录 `triggerDelta`、`decayDelta`、`netDelta`；缺一即不合格。
13. **衰减不叠加**：构造“有触发”的一轮，`decayDelta` 必须为 0，且 `consecutiveNoTriggerTurns` 归零。
14. **上限边界**：强度 5 时命中 P1，`triggerDelta=+1`、`netDelta=0`、审计仍记录 P1。
15. **label 待决策检查**：任何语料若出现主 label 变化，必须标记为“待审变更”，不得按默认规则放行。
