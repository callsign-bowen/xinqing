# 数据来源与许可 v1

Schema：`schemas/source-registry.schema.json`
模板：`templates/data-source-entry-template-v1.json`
三桶：`REFERENCE_LIBRARY/sources-{commercial-ok,research-only,restricted}-v1.jsonl`

---

## 1. 一句话原则

> **研究资料不等于商业可用资料。默认桶是 `research_only`，升级必须留证据。**

“网上能搜到”“公开可见”“别人也在用”都不是授权。看不到明确许可证，就按 `restricted` 处理。

## 2. 三个桶

| 桶 | `licenseClass` | 典型许可证 | 能做什么 | 不能做什么 |
|---|---|---|---|---|
| `sources-commercial-ok-v1.jsonl` | `commercial_ok` | `internal-owned`、`CC0-1.0`、`CC-BY-4.0`、`public-domain` | 改写、商用、进正式库 | — |
| `sources-research-only-v1.jsonl` | `research_only` | `CC-BY-NC-4.0`、`论文授权仅研究`、`unknown-pending-verification` | 只读、提炼结构、做研究 | 整段复制、商用、进正式库 |
| `sources-restricted-v1.jsonl` | `restricted` | `copyright-all`、影视/歌词/小说、平台条款禁止衍生 | 只看节奏与结构 | 复制、训练、衍生商用 |

一个资源只能在一个桶里。跨桶意味着“同一作品的不同部分授权不同”，拆成两条记录，各自登记。

## 3. 每条记录要写清 13 项

| 你要登记 | 字段 | 说明 |
|---|---|---|
| 资源名称 | `name` | 正式标题，不写“某篇文章” |
| 原始网址 | `url` | 可空，但空着就要在 `notes` 说明原因 |
| 作者 | `author` | 个人或机构 |
| 来源平台 | `platform` | 报纸网站 / 豆瓣小组 / 客户访谈 |
| 语言 | `language` | `zh-CN`、`en`、`ko（中文字幕）` |
| 数据规模 | `scale` | `1 篇` / `12 万字` / `40 条对话` |
| 数据类型 | `dataType` | 访谈 / 报道 / 影视字幕 / 书籍 / 论文 / 论坛帖 / 客服记录 / 平台话术 / 原创 / 其他 |
| 许可证 | `license` | 具体名称，不写“免费” |
| 上游来源 | `upstream` | 转载链、译本、二次加工，没有就空字符串 |
| 是否允许商业使用 | `commercialUse` | 布尔，不确定写 `false` |
| 是否允许修改 | `modification` | 布尔，不确定写 `false` |
| 采集时间 | `collectedAt` | `YYYY-MM-DD` |
| 研究价值 | `researchValue` | 具体到“能提供什么”，不写“有参考价值” |
| 当前使用状态 | `usageStatus` | `reference_only` / `draft_cited` / `approved_derived` / `excluded` |

另有 `verification`（核对状态、核对日期、备注）和 `notes`。

## 4. 判定顺序

```text
1. 有明确许可证吗？
   没有 → restricted（copyright-all / unknown 一律按最严处理）
2. 许可证写着“仅研究 / 非商业 / NC”？
   是 → research_only
3. 许可证是 CC0 / CC BY / public domain / 项目自有？
   是 → commercial_ok，但仍要登记证据
4. 是影视、歌词、小说、字幕？
   是 → restricted（只许看结构，不许复制）
5. 是用户访谈？
   有书面同意且约定了用途 → 按约定；没约定 → research_only
```

## 5. 升级路径

`research_only` → `commercial_ok` 必须满足全部：

1. 拿到可指认的许可证文本或书面授权（截图、邮件、条款链接）；
2. 在 `verification` 里写清核对方式与日期，`status: verified`；
3. 经由许可审核（`role: license_reviewer`）签字；
4. 在 `notes` 追加变更记录，不覆盖旧判断。

缺一条就留在原桶。**不允许因为“已经用了一段时间”就默认升级。**

## 6. 引用规则

- 语料的 `sources.sourceIds` 必须能查到；查不到 → 校验失败。
- `research_only` / `restricted` 的原文不得整段出现在 `ORIGINAL_CORPUS` 或 `PRODUCTION_APPROVED`。
- 改写要求：不保留原文的连续 8 字以上片段；不照搬专有名词组合；只借用结构与分寸。
- 引用影视/书籍时，`attribution` 必须写明作品名，即使只是“参考了节奏”。

## 8. 安全红线

- **API Key 不进语料库。** 密钥只放在 `account-service/.env`（已被 `.gitignore` 的 `.env` 规则覆盖），不得写进任何 JSON、JSONL、Markdown、日志或提交记录。
- 校验脚本会扫描整个语料目录，出现 `sk-` 形态的长串或 `AI_API_KEY=` 赋值即报错。
- 访谈材料必须去标识化后再进 `RAW_RESEARCH`。
- 不把原始聊天记录、用户昵称、图片 Base64 写进语料库。
