## 1. 这是什么

这是一套**独立于运行时**的情景语料库：它描述“一个具体的人、在一个具体场景里、会怎么施压、用户可以怎么接”，而不是一句孤立的金句。

它服务于现有的情景聊天模块：MVP 是「角色反转」（用户演对方、AI 替用户回应），但 C-001 已裁决正式方向为「**用户演自己、AI 演对方**」，迁移评估见 `docs/11`。**当前阶段不接入**任何运行时逻辑。

```text
语料库（本目录）  ——只读数据，人工审核——
        │
        │  第二阶段：适配层 / 检索
        ▼
情景聊天（web/features/scenario/）  ——提示词 + 模型——
```

## 2. 四层语料，各管一段

项目里已经有三种语料，本库是第四种，不是替代关系。

| 层 | 位置 | 管什么 | 例子 |
|---|---|---|---|
| 人格层 | `account-service/server.mjs` 的 `NUO_PERSONA` / `COMPANION_STANCE` | 诺怎么说话 | “先停半拍，再用短句接住” |
| 风格层 | `特征词库/` | 温柔、直接、幽默、倾听、清醒 | “这个我不接。换个话题。” |
| 台词层 | `语料库/情景应答/` | 一句对方台词 → 三种接法 | 催婚的 7 条应答 |
| **情景层（本库）** | `语料库/情景聊天/` | 完整的人、关系、分支、情绪、安全退出 | FAM-001 父母催婚 |

台词层回答“这句怎么接”，情景层回答“这个人是谁、她为什么这么说、说到哪一步该停”。两者通过 `sourceIds` 与子类对齐，不重复存储同一句话。

## 4. 一条语料的一生

```text
reserved   只占编号
   ↓
outline    有标题、目标、风险等级
   ↓
draft      完整结构，作者自检（FAM-001 现在在这里）
   ↓
in_review  提交，非作者复核
   ↓
approved   五关全过 → 移入 PRODUCTION_APPROVED/
```

任何一步都可以退：`rejected`（不采用）、`blocked`（高风险，需安全评审）、`deprecated`（上线后下线）。

- 没有删除或覆盖任何现有文件
