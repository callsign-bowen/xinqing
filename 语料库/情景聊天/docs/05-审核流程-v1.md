# 审核流程 v1

配套：`templates/review-checklist-v1.md`（可打印的审核单）

---

## 1. 角色

| 角色 | 负责 | 谁能当 |
|---|---|---|
| 作者 | 写内容、语言、真实感 | 项目成员 |
| 安全审核 | 自伤/他伤/暴力边界 | 非作者，最好有心理或危机干预背景 |
| 许可审核 | 来源与授权 | 非作者，能读许可证 |
| 产品审核 | 与产品口径一致（不评分、不制造依赖） | 非作者 |

**最少两人**：作者 + 一位非作者审核人。高风险类（`CARE`、`DIG` 的 blocked 编号）必须加安全审核。

## 2. 状态机

```text
reserved → outline → draft → in_review → approved
                                 │
                                 ├→ rejected（不采用）
                                 └→ blocked（高风险，需安全评审）
approved → deprecated（过期/被替换）
```

规则：

- `draft → in_review`：作者自检五项（至少 safety / license 为 `pass`）。
- `in_review → approved`：五项全 `pass`，非作者签字。
- `in_review → draft`：任一项 `fail`，退回改，不带着 `fail` 上线。
- `approved → deprecated`：内容过期、出现事故、被新版本替换。

## 3. 五关（摘要）

| 关 | 一句话 | 一票否决的典型 |
|---|---|---|
| 安全 | 不越过施压线，退出有去处 | 出现辱骂/威胁/暴力细节 |
| 许可 | 来源可查，商用有据 | 整段搬用影视台词 |
| 语言 | 像这个人说的，能直接说出口 | 心理咨询腔、谈判课金句 |
| 真实感 | 对方是具体的人，不是反派 | 对方只为被说服而存在 |
| 偏见 | 不刻板、不美化控制、不制造依赖 | “忍一忍就过去了”“只有我懂你” |

完整标准见审核单第 1 节。

## 4. 上线门槛

`PRODUCTION_APPROVED/` 只接受同时满足以下条件的文件：

1. `review.status == "approved"` 且与 `INDEX.json` 一致；
2. 五项 `pass`；
3. 至少一位 `role != author` 的审核人；
4. `licenseClass == commercial_ok`（或 `origin == original` 且自有版权）；
5. `sources.sourceIds` 全部可解析；
6. `validate-corpus.mjs` 通过。

任何一条不满足，留在 `ORIGINAL_CORPUS/`。

## 5. 高风险类的额外流程

`blocked` 的 8 个编号（丧亲、照顾者耗竭、宠物离世、朋友自杀、开盒、诈骗、造谣、网友见面）开写前必须：

1. 安全审核给出书面边界（写进 `safety.hardStop` 与 `route`）；
2. 明确“只练什么、不演什么”（例如只练“怎么问医生”，不演“临终告别”）；
3. 产品审核确认不会造成二次伤害；
4. 上线后 30 天内回看一次用户反馈。

## 6. 复审与下线

| 触发 | 时限 | 动作 |
|---|---|---|
| 上线满 6 个月 | 30 天内 | 复审，确认口径未变 |
| 新增外部来源 | 即时 | 重过许可 |
| 用户反馈“说不出口/不像” | 2 周内 | 退回 `draft` 改语言 |
| 安全事故 | 立即 | `deprecated`，全量排查同类 |

下线不是删除：文件移回 `ORIGINAL_CORPUS/`，状态改 `deprecated`，`notes` 写原因。

## 7. 常见退回原因（写给作者）

1. 替身一开口就是三句以上的解释——现实里没人这么说话。
2. 对方被写成纯反派，用户练完只想吵。
3. 只有一种“正确答案”，没有 `avoid`。
4. 安全退出只写“退出演练”，没写退出后去哪。
5. 引用了 `research_only` 的资料，却标 `commercial_ok`。

## 8. 审核记录放哪

- 结构化部分：文件内 `review` 块（必须）。
- 过程记录：`templates/review-checklist-v1.md` 的副本，命名 `审核单-FAM-001-v1-YYYYMMDD.md`，建议与语料同目录，不进 `PRODUCTION_APPROVED`。

## 9. 不做的事

- 不跳过非作者复核。
- 不用“先上线再补审核”。
- 不因为赶进度把 `blocked` 改成 `reserved` 直接开写。
