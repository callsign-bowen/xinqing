## 1. 这一阶段做什么、不做什么

| 做 | 不做 |
|---|---|
| 发现、登记、判定许可、写研究笔记、评分排序 | 不做大规模原创语料 |
| 记录“能借鉴什么机制” | 不复制原文、不搬运角色卡正文 |
| 把资源分进三个桶 | 不把 `research_only` 升级成 `commercial_ok` |
| 给产品负责人一份可选清单 | 不自行决定“这个可以用” |

**产物只有两种**：一条来源登记（JSONL）+ 一份研究笔记（Markdown，可选但有价值）。

## 2. 收集方向与检索词

六类方向，全部要覆盖到；不局限于心理陪伴产品。

### A. AI 陪伴 / 情感对话

| 英文检索 | 中文检索 | 研究什么 |
|---|---|---|
| `AI companion`、`emotional companion`、`AI friendship`、`conversational agent` | AI 陪伴、情感陪伴、虚拟伴侣、聊天机器人 | 长期关系的语气、记忆使用、依赖防范 |
| `empathetic chatbot`、`social chatbot` | 共情机器人、社交机器人 | 共情话术的结构与失败案例 |

### B. 人物角色卡

| 英文检索 | 中文检索 | 研究什么 |
|---|---|---|
| `character card`、`character card v2`、`persona prompt` | 角色卡、人设、人物设定 | 字段设计（性格、语气、示例对话）、一致性维护 |
| `character definition`、`personality prompt` | 性格提示词、人格设定 | 如何把“人”写成一个可执行的约束 |

### C. 情景角色扮演

| 英文检索 | 中文检索 | 研究什么 |
|---|---|---|
| `roleplay prompt`、`scenario simulation`、`NPC dialogue` | 情景扮演、角色扮演提示词、NPC 对话 | 开场、分叉、结束、防止出戏 |
| `interactive storytelling`、`social simulation` | 互动叙事、社交模拟 | 多轮推进与分支管理 |

### D. 多轮对话数据集

| 英文检索 | 中文检索 | 研究什么 |
|---|---|---|
| `multi-turn dialogue dataset`、`emotional dialogue dataset` | 多轮对话数据集、情感对话 | 轮次结构、情绪标注、真实口语分布 |
| `roleplay dataset`、`social dialogue corpus` | 角色扮演数据集、社交对话语料 | 数据规模、许可、可否商用 |

### E. 人际沟通案例

| 方向 | 检索 | 研究什么 |
|---|---|---|
| 家庭 | 催婚 对话、亲子沟通 案例、原生家庭 冲突 | 代际话术、愧疚机制 |
| 职场 | 谈薪 对话、拒绝加班 话术、向上沟通 | 权力差、模糊承诺 |
| 亲密关系 | 冷暴力 对话、提分手 沟通、边界 表达 | 情绪拉扯、边界句式 |
| 朋友 | 拒绝借钱 话术、室友 边界 | 关系成本 |
| 自我 | 不会拒绝、表达需求、讨好型 | 无对手方的自我对话 |
| 日常社交 | 客服 投诉 对话、邻里 沟通 | 陌生人规则话术 |

### F. 情绪识别与动态回应

| 英文检索 | 中文检索 | 研究什么 |
|---|---|---|
| `emotion recognition dialogue`、`emotional state tracking` | 情绪识别、情绪状态跟踪 | 如何判断强度、如何降级 |
| `empathetic response generation`、`context-aware dialogue` | 共情回应生成、上下文感知对话 | 回应与情绪的匹配规则 |

> 检索词是起点，不是边界。发现高价值资源后，允许顺着引用链继续找，但要逐条登记，不能“打包记一条”。

## 3. 资源单元（RES 包）

一个资源 = 一条登记 + 一份笔记 + 最多 3 段短摘录。

```text
SRC-GHB-001
├─ 登记：REFERENCE_LIBRARY/sources-<桶>-v1.jsonl 里的一行
├─ 笔记：RAW_RESEARCH/notes/SRC-GHB-001.md（Phase 1 开始时建目录）
└─ 摘录：≤ 200 字/段，只放“能说明机制”的片段，不放大段正文
```

## 4. 七步工作流

| 步 | 动作 | 负责人 | 产出 | 检查点 |
|---|---|---|---|---|
| S1 | 接任务单：主题、目标编号（如 FAM-001）、边界 | 产品负责人 → ChatGPT | 任务单 | 有明确产出格式 |
| S2 | 发现：按第 2 节检索，记录候选标题 + 链接 | ChatGPT | 候选清单 | 每条可点开 |
| S3 | 初筛：相关性、可访问性、是否重复 | ChatGPT | 保留 30–50% | 去重（同源转载算一条） |
| S4 | 登记：按第 5 节字段写入对应桶，`verification: pending` | IDE | JSONL 一行 | 跑校验器，无 schema 错误 |
| S5 | 许可核查：找许可证原文或条款，写证据 | IDE（存疑报产品负责人） | `verified` / 保持 `pending` / 改桶 | 证据可点开 |
| S6 | 研究笔记：写“能借鉴什么、风险是什么” | ChatGPT | `RAW_RESEARCH/notes/<ID>.md` | 有“不适用”判断 |
| S7 | 评分与周报：按第 8 节打分，汇总候选 | IDE | 周报 | 分数可复核 |
| S8 | 产品负责人选“深研” | 产品负责人 | 选中清单 | 明确范围，交 Phase 3 |

**S4 之前不许先写笔记再补来源**；没有登记的观察只能算草稿，不进候选。

## 5. 字段映射（不改现有 Schema）

Schema 已固定，本流程**不得修改**。任务书要求的 14 项这样落位：

| 任务书字段 | 落到 Schema 的位置 | 备注 |
|---|---|---|
| 资源编号 | `id` | `^SRC-[A-Z]{3}-\d{3}$` |
| 资源名称 | `name` | 正式标题 |
| 作者/发布者 | `author` | 机构或个人 |
| 原始链接 | `url` | 可空，但要在 `verification.note` 说明 |
| 来源平台 | `platform` | GitHub / HF / 论文库 / 社区 |
| 资源类型 | `dataType` | 受枚举限制，见 5.1 |
| 获取时间 | `collectedAt` | `YYYY-MM-DD` |
| 内容简介 | `researchValue` + 笔记文件 | 没有独立“简介”字段，简介写进 `researchValue` 开头一句 |
| 研究价值 | `researchValue` | 具体到“能提供什么机制” |
| 许可类型 | `license` | 具体名称，不写“免费” |
| 许可证据 | `verification.note` + `notes` | 存证据链接/截图位置 + 核对方式 |
| 是否允许改编 | `modification` | 不确定写 `false` |
| 是否允许商用 | `commercialUse` | 不确定写 `false` |
| 其他使用限制 | `notes` | 如“需署名”“禁止再分发” |

### 5.1 `dataType` 的取舍

枚举只有：访谈 / 报道 / 影视字幕 / 书籍 / 论文 / 论坛帖 / 客服记录 / 平台话术 / 原创 / 其他。

- GitHub 提示词库、角色卡 → `其他`（在 `notes` 写“提示词库/角色卡”）；
- Hugging Face 数据集 → `其他`（`notes` 写“数据集，N 条”）；
- 论文 → `论文`；公开报道 → `报道`；访谈稿 → `访谈`。

### 5.2 编号段（3 个大写字母）

| 段 | 用途 | 默认桶 |
|---|---|---|
| `OWN` | 项目自有 | commercial_ok |
| `RES` | 报道、一般研究材料 | research_only |
| `RST` | 影视、书籍、版权受限 | restricted |
| `GHB` | GitHub 仓库 | research_only |
| `HGF` | Hugging Face 模型/数据集 | research_only |
| `PRM` | 提示词库、提示词集合 | research_only |
| `CHR` | 角色卡社区 | research_only |
| `DAT` | 对话数据集 | research_only |
| `ACA` | 学术论文 | research_only |
| `COM` | 沟通案例、教育材料 | research_only |

段内三位序号从 `001` 起，**永不复用**。

## 6. 分桶判定（快速版）

```text
许可证写明 CC0 / CC BY / 自有？
  → commercial_ok（仍需证据 + verified）

写明 NC / 仅研究 / 论文默认？
  → research_only

没写许可 / 写着 All rights reserved / 影视书籍歌词？
  → restricted（只看结构，不复制）

拿不准
  → 先 research_only + verification: pending，报产品负责人
```

完整判定树与升级路径见 `docs/04`，此处不重复。

## 7. 采集纪律

1. **不绕过访问限制**：不登录墙外抓、不破解、不使用他人账号。
2. **遵守站点条款与 robots**：明确禁止抓取的站点，只手工记录元数据。
3. **不批量下载**：本阶段只登记，不把数据集拉进仓库；确需样本，≤ 20 条并注明用途。
4. **不获取私人数据**：真实聊天记录、私人帖子、可识别个人的内容一律不收。
5. **摘录上限 200 字/段，最多 3 段**，且只摘“机制”而非“剧情”。
6. **不复制角色卡正文**：登记字段 + 自己写的机制总结即可。
7. **不伪造**：作者、链接、许可任何一项没核实，就写 `pending`，不写“已确认”。
8. **速率**：同一站点连续请求间隔 ≥ 2 秒，失败即停，不重试轰炸。

## 8. 候选评分

每条资源按四项打分，写进周报：

| 维度 | 分值 | 判断 |
|---|---|---|
| 相关性 R | 0–3 | 3 = 直接对应某个编号；0 = 只是泛泛相关 |
| 方法可迁移 M | 0–3 | 3 = 能提炼出跨情景复用的机制 |
| 许可可用 L | 0–2 | 2 = commercial_ok；1 = research_only；0 = restricted |
| 风险 P | -2–0 | -2 = 含暴力/自伤细节或强依赖诱导；0 = 无 |

`总分 = R + M + L + P`。**进入 Phase 3 的门槛：总分 ≥ 5 且 L ≥ 1**（restricted 只能做背景阅读，不进拆解队列）。

## 10. 周报模板

| 编号 | 名称 | 平台 | 桶 | R | M | L | P | 总分 | 建议 |
|---|---|---|---|---|---|---|---|---|---|
| SRC-GHB-001 | … | GitHub | research_only | 3 | 2 | 1 | 0 | 6 | 进入拆解 |

周报末尾固定三行：

- 本周新增 N 条，累计 M 条；三桶分布：…
- 许可存疑 K 条（列出，等产品负责人确认）；
- 下周计划覆盖的方向（A–F 中未覆盖的）。

## 11. 质量自检（登记后立刻做）

```powershell
node "语料库\情景聊天\scripts\validate-corpus.mjs"
```

必须满足：

- 0 个 schema 错误；
- `pending` 警告可接受，但**每条 pending 都要有“待补什么”的说明**；
- 同一资源不重复登记（先按名称/URL 查重）；
- 每条都能回答“它对应哪个编号”。

## 12. 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 先写笔记，后补来源 | 来源对不上，无法追溯 | 先登记再深读 |
| 把 GitHub 上的提示词直接当语料 | 版权与质量问题 | 只提炼机制，重写 |
| 许可写“公开可用” | 无法判定 | 写具体许可证名或 `unknown-pending-verification` |
| 一条记录塞多个资源 | 无法逐条判定 | 一资源一记录 |
| 把 restricted 的原文贴进笔记 | 侵权风险 | 只写机制总结，摘录 ≤ 200 字 |
| 自行升级到 commercial_ok | 违反流程 | 报产品负责人 + 补证据 |
