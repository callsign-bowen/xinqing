## 1. 这份文档是什么

这是本项目的**总纲**：定义目标、分层、角色、阶段、门禁与冲突处理规则。

它**不是**：

- 不是情景语料（语料在 `ORIGINAL_CORPUS/`）；
- 不是数据格式说明（见 `docs/02`）；
- 不是来源许可细则（见 `docs/04`）；
- 不是审核单（见 `templates/review-checklist-v1.md`）。

**效力顺序**：产品负责人的书面确认 > 本总纲 > 各分册工作流 > 单条语料的作者判断。
发现冲突时按第 8 节处理，**不擅自覆盖**。

## 2. 产品目标

### 2.1 一句话

> 让用户在低风险的环境里，把“现实里说不出口的那句话”练到能说出口，并且练完敢去现实里试一次。

### 2.2 目标形态（据 2026-11-14 产品负责人任务书）

```text
用户选情景（如 家庭 / 催婚 / 父母催婚）
  ↓
AI 扮演情景中的另一方（如妈妈），带着固定的人物设定、情绪和边界
  ↓
用户用自己的话回应；卡住时点「辅助回应」
  ↓
AI 给一句自然、贴合语境、可直接发出去的建议，填进输入框
  ↓
用户可反复「换一句」，直到满意，再发送
  ↓
AI 按人物设定继续回应（情绪、强度、分支随对话变化）
  ↓
用户可随时退出；可选复盘
```

### 2.3 成功标准

| 维度 | 指标 | 说明 |
|---|---|---|
| 敢用 | 练完 7 天内自报“现实里试了一次”的比例 | 核心指标，不是停留时长 |
| 说得出 | 用户自评“这句我愿意说”的比例 ≥ 60% | 辅助回应的关键指标 |
| 像真的 | 用户认为“对方像真人”的比例 | 人物设定与语言风格的质量 |
| 不串味 | 演练里出现 AI 助手口吻的比例 < 5% | 人格隔离 |
| 安全 | 高风险正确退出率 | 一票否决 |

### 2.4 明确不做

- 不做“标准答案生成器”，不承诺“练完就能解决”；
- 不做评分、排名、连续打卡；
- 不模拟虐待、暴力、自伤现场；
- 不替代心理治疗，不做诊断、不用药建议；
- 不制造依赖（“只有我懂你”这类表达一律禁止）。

## 3. 系统分层

```text
┌─────────────────────────────────────────────┐
│ 产品层  情景大厅 / 演练 / 辅助回应 / 复盘     │  web/features/scenario/
├─────────────────────────────────────────────┤
│ 方法层  人物卡 / 语言风格 / 情绪机制 / 策略   │  待建：docs 09–10 产出方法卡
├─────────────────────────────────────────────┤
│ 语料层  64 个情景单元（JSON）+ 来源登记       │  语料库/情景聊天/
├─────────────────────────────────────────────┤
│ 安全层  风险词表 / 退出流程 / 求助渠道        │  server.mjs riskOf + safety 字段
└─────────────────────────────────────────────┘
```

三层关系：

- **方法层可跨情景复用**（一次写“如何设计一个嘴硬心软的长辈”，用在多个家庭情景）；
- **语料层是方法层的实例**（FAM-001 是方法的一次具体落地）；
- **安全层永远在最上面**：语料和方法都不能覆盖安全规则。

## 4. 三方分工与决策权

### 4.1 角色

| 角色 | 是谁 | 负责 | 不负责 |
|---|---|---|---|
| 产品负责人 | 用户 | 需求、优先级、验收、上线决定 | 不写语料、不做技术实现 |
| 研究协作者 | ChatGPT | 搜索、拆解、蒸馏、提出设计、质量评估 | 不改仓库、不批准上线 |
| 执行协作者 | IDE DeepSeek | 建目录、登记、结构化、写作辅助、校验、版本记录 | 不定方向、不改架构、不批准自己的产出 |

### 4.2 决策权（RACI）

R = 执行，A = 最终负责，C = 提供意见，I = 被告知。

| 事项 | 产品负责人 | ChatGPT | IDE DeepSeek |
|---|---|---|---|
| 产品方向 / 优先级 | **A** | C | I |
| 外部资源是否值得研究 | **A** | R | I |
| 资源许可判定 | I | C | **R**（存疑即报 A） |
| 方法卡是否采纳 | **A** | R | C |
| 单条语料初稿 | I | C | **R** |
| 语料独立审核 | **A** | **R**（真实性/自然度/安全） | C（结构/校验） |
| 标记 `approved` | **A**（签字） | C | I（不自行标记） |
| 修改 Schema / 校验器 | **A** | I | R（需先报批） |
| 产品代码接入 | **A** | I | R（Phase 7） |

### 4.3 三条铁律

1. **作者不得批准自己的语料。** IDE 写的语料，必须由 ChatGPT 或产品负责人独立审。
2. **研究判断不等于事实。** ChatGPT 的拆解必须标注“资料支持 / 分析判断 / 原创改进”三类（见 `docs/10`）。
3. **执行者不改方向。** IDE 发现方向问题只能登记冲突、提出方案，不能直接改产品代码或语料定位。

### 4.4 交接协议（Handoff）

每一棒都要交“可验收的包”，不能只交一段聊天：

| 从 → 到 | 交付物 | 验收标准 |
|---|---|---|
| 产品负责人 → ChatGPT | 研究任务单（主题 + 目标编号 + 边界） | 有明确产出格式 |
| ChatGPT → 产品负责人 | 候选资源清单（含许可初判） | 每条可点开、可判断 |
| 产品负责人 → ChatGPT | 选中的资源 | 明确“深研”范围 |
| ChatGPT → IDE | 拆解报告（8 维度 + F/A/O 标注） | 有来源编号，能对应到 `SRC-*` |
| IDE → 产品负责人 | 登记 + 方法卡 + 语料初稿 | 校验通过、状态为 `draft` |
| 产品负责人 / ChatGPT → IDE | 审核意见 | 逐项可执行 |
| IDE → 产品负责人 | 修订版 + 校验输出 | 状态可追踪 |

## 8. 冲突登记与处理

### 8.1 规则

1. 发现冲突 → **先记录、先报告**，不覆盖、不“顺手改掉”。
2. 冲突分级：`C-1` 影响产品方向（必须产品负责人裁决）；`C-2` 影响流程（IDE 提方案，负责人确认）；`C-3` 措辞/编号（IDE 可自行统一并记录）。
3. 裁决结果写入本文件第 8.3 节，并注明日期。

### 8.2 冲突登记与裁决记录

#### C-001（C-1，**已裁决：方案 B**）：角色分配与「辅助回应」的定位

| 维度 | 现有实现（`docs/product/情景聊天-设计方案-v1.md` + `web/features/scenario/`） | 本次任务书描述 |
|---|---|---|
| 谁演对方 | **用户**演对方，AI 替用户回应 | **AI** 演对方，用户回应 |
| 用户输入是什么 | 用户写“对方的台词” | 用户写“自己的回应” |
| 辅助功能 | 「求助」给方向提示，不填输入框 | 「辅助回应」生成一句话**填入输入框**，可换 |
| 演练的收获 | 听到“我可以怎么接” | 练“我自己怎么说” |

影响面：

- 提示词：`standInPrompt`（替身）与目标形态的“扮演对方”提示词是两套逻辑；
- 语料：`dialogue.turns` 的 `speaker` 语义、`strategies` 的用途都会变（但 Schema 本身两者都支持）；
- 产品代码：输入区、求助按钮、复盘引用对象；
- 安全：角色反转时用户可能在“扮演施害者”，与 AI 扮演对方时的安全边界不同。

**登记时的处理**：不动代码、不动 FAM-001、不改产品设计文档原章节；只登记冲突并给三个可执行方案。裁决后，产品设计文档仅**追加**第 14 节待迁移说明，原第 1–13 节保留。

- 方案 A（沿用现有 MVP）：保持角色反转，先跑通语料与复盘；
- 方案 B（按任务书）：AI 演对方 + 辅助回应，需重写 `standInPrompt` 为 `counterpartPrompt`，并新增建议接口；
- 方案 C（并存）：两种模式，由用户在设置里选，成本最高。

**正式裁决（2026-11-14，产品负责人）：采用方案 B。**

| 裁决项 | 内容 |
|---|---|
| 正式模式 | 用户演现实中的自己；AI 演情景中的另一方，按人物设定、背景、用户实际回应、当前情绪动态生成 |
| 辅助回应 | 生成一句第一人称、可直接使用的表达，**填入输入框**；可编辑、可重新生成，**不得自动发送** |
| 求助 | 只给沟通方向、策略、提示；与辅助回应**不是同一个功能的两个名字** |
| 双模式 | 不采用。原角色反转 MVP 仅作历史实现与未来可能的示范模式参考，不得作为默认方向；再启用须重新批准 |
| 数据影响 | Schema 与 FAM-001 **不需要改**；需要改的是提示词、角色映射、UI、历史记录与风险检测对象 |
| 本阶段动作 | 只更新文档与任务单，不改 Schema、不改语料、不改产品代码 |

影响评估与迁移建议（MIG-01 ~ MIG-08）见 [docs/11-C001数据语义与迁移影响评估-v1.md](11-C001数据语义与迁移影响评估-v1.md)。
第一轮执行任务见 [docs/12-第一轮外部资源研究任务单-v1.md](12-第一轮外部资源研究任务单-v1.md)。

## 9. 版本与变更管理

| 对象 | 规则 |
|---|---|
| 文档 | 文件名带 `-v1`；实质性修改升 `v2`，旧版保留，不覆盖 |
