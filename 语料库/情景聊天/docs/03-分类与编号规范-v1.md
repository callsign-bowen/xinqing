# 分类与编号规范 v1

配套：`INDEX.json`（机器可读）、`schemas/corpus-index.schema.json`
上游：`docs/product/情景分类体系-v1.md`（8 大类 + 子类的来源）

---

## 1. 8 × 8 = 64

第一期固定 64 个编号位，每类 8 个。**编号是座位，不是内容**：先占位，再按优先级写。

| 类目 | 代码 | 编号段 | 定位 |
|---|---|---|---|
| 家庭 | `FAM` | FAM-001 ~ 008 | 原生家庭、代际期待、亲戚、过年 |
| 职场 | `WRK` | WRK-001 ~ 008 | 谈薪、边界、责任、权力差 |
| 亲密关系 | `REL` | REL-001 ~ 008 | 冷战、边界、分手、钱 |
| 朋友 | `FRD` | FRD-001 ~ 008 | 借钱、份子、室友、关系成本 |
| 自我 | `SELF` | SELF-001 ~ 008 | 拒绝、表达、比较、自责 |
| 消费 | `CNS` | CNS-001 ~ 008 | 退款、押金、推销、维权 |
| 照护 | `CARE` | CARE-001 ~ 008 | 陪诊、分工、丧亲、耗竭（高风险） |
| 数字生活 | `DIG` | DIG-001 ~ 008 | 网暴、隐私、诈骗、AI 依赖 |

> **为什么消费用 `CNS` 而不是 `CON`**：`CON` 是 Windows 保留设备名（和 PRN / AUX / NUL 一样），建目录能建，但复制、删除、打包时常被系统拒绝。实测已踩过，因此固定用 `CNS`（consumer）。

## 2. 编号规则

```text
FAM-001
└┬─┘ └┬┘
 │    └── 三位序号，001–008，补零
 └────── 3–4 个大写字母类目代码，固定 8 个（FAM / WRK / REL / FRD / SELF / CNS / CARE / DIG）
```

- 序号**不复用**：删掉 FAM-004 后，新情景用 FAM-009（下一期扩位），不顶替。
- 编号与子类绑定：FAM-001 永远是“催婚”，不能改成“催生”。
- 子类可以细化，但不能跨类：`FAM-001` 不能变成“职场催婚”。

## 3. 文件与路径

```text
ORIGINAL_CORPUS/FAM/FAM-001-父母催婚-v1.json
PRODUCTION_APPROVED/FAM/FAM-001-父母催婚-v1.json
```

- 目录名 = 类目代码（大写）。
- 文件名 = `<编号>-<标题>-v<主版本>`。
- 标题改动不换文件名；结构大改才 `-v2`，且旧文件标 `deprecated`。
- 一个编号一个文件。不要 `家庭合集.json`。

## 4. 状态

| 状态 | 含义 | 允许出现在 |
|---|---|---|
| `reserved` | 只占编号，无内容 | 只在 `INDEX.json` |
| `outline` | 有标题、目标、风险等级 | `INDEX.json`（可选草稿文件） |
| `draft` | 完整结构，未过审 | `ORIGINAL_CORPUS/` |
| `in_review` | 已提交，等非作者复核 | `ORIGINAL_CORPUS/` |
| `approved` | 五关全过 | **只在** `PRODUCTION_APPROVED/` |
| `blocked` | 高风险，需安全评审后才能开写 | `INDEX.json` / `ORIGINAL_CORPUS/` |
| `rejected` | 明确不采用 | `ORIGINAL_CORPUS/`（保留记录） |
| `deprecated` | 曾上线，已下线 | `ORIGINAL_CORPUS/` |

`INDEX.json` 的 `status` 必须与文件内 `review.status` 一致；没有文件时只能是 `reserved` / `outline` / `blocked`。

## 5. 优先级

| 级别 | 含义 | 当前分布 |
|---|---|---|
| `P0` | 第一期先写，用户最常遇到 | 20 个 |
| `P1` | 第二批 | 22 个 |
| `P2` | 有余力再写 | 22 个 |

`blocked` 的 8 个编号全部是高风险类（丧亲、照护耗竭、朋友自杀、开盒、诈骗、造谣、网友见面）——**它们不是 P2 的借口，是必须先过安全评审的门。**

## 7. 和 `docs/product/情景分类体系-v1.md` 的关系

那份文档是**子类清单**（每类 12–14 个子类，用于页面筛选），本规范是**编号座位**（每类 8 个，用于语料管理）。

- 子类可以多于 8 个：没占编号的子类，在 `INDEX.json` 里先不建位，等下一期扩到 64 以外再分配。
- 前端 `SUBCATEGORY_LABELS` 仍然以那份文档为准，不在这次改动范围内。

## 8. 新增一个编号（第二期）

1. 在 `INDEX.json` 对应类目追加 slot，`seq` 顺延，`status: reserved`。
2. 同步改 `corpus-index.schema.json` 的 `maxItems` 和 `totalSlots`。
3. 跑校验脚本。
4. 这一步属于结构变更，需要单独提交，不夹在内容写作里。
