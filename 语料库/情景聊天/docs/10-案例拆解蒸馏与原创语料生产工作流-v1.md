## 1. 总原则：三类内容必须分开写

任何一句分析，都要能标出它属于哪一类：

| 标记 | 含义 | 写法要求 |
|---|---|---|
| **F**（Fact） | 原始资料明确支持 | 必须能指到 `SRC-*` 和位置；不加形容词 |
| **A**（Analysis） | 我们对资料的分析判断 | 写“我认为/可以推断”，允许被推翻 |
| **O**（Original） | 我们提出的原创方法 | 写清“如果这样做，会怎样”，并给验证方式 |

一条拆解笔记里，F 与 A 必须分行；O 只能出现在“可复用方法”一节。
**没有 F 支撑的 A，要标“假设”，不能当结论用。**

## 2. Stage A：案例拆解（8 个维度）

对每个进入深研队列的资源，按下面 8 维拆。每维只回答列出的问题，不写泛泛摘要。

### A1 人物设定

| 问题 | 记什么 |
|---|---|
| 身份 | 年龄带、职业、与用户的关系、社会位置 |
| 性格 | 3–5 个可观察的形容词（不是“善良”“复杂”） |
| 价值观 | 他认为“人应该怎样”，最不能接受什么 |
| 表面诉求 | 他嘴上要什么（一句话） |
| 深层动机 | 他真正怕什么、想保住什么 |
| 性格矛盾 | 哪两件事同时成立（如“要强又怕被抛下”） |
| 情绪触发点 | 哪句话会让他更用力，哪句会让他松 |

产出示例（F 行 + A 行分开）：

```text
F：原文中母亲三次提到“别人家孩子”，两次在女儿沉默后提高音量。
A：她的压力源可能是“被亲戚比较”，而不是女儿的婚否本身。
```

### A2 语言风格

句子长度（字数区间）、口语化程度（书面/家常/方言）、常用表达（≤5 个）、语气变化（何时变短、何时反问）、情绪表达（直接/压抑/转移）、语言习惯（口头禅、叹词）、不同场景下的变化（对谁软、对谁硬）。

要求：给出**可执行的参数**，例如“短句为主，平均 12 字，反问句占 1/3”，而不是“说话很生活化”。

### A3 对话机制

| 问题 | 记什么 |
|---|---|
| 如何开始 | 第一句是陈述、提问还是动作带话 |
| 如何接续 | 抓用户哪个词、是否复述 |
| 如何理解回应 | 有没有确认、会不会误读 |
| 如何动态调整 | 下一轮依据什么变（情绪、让步、施压） |
| 如何避免重复 | 换说法、换角度、还是换话题 |
| 如何结束 | 谁先收、收尾句长什么样 |

### A4 情绪机制

初始状态（标签 + 强度 1–5）、变化条件（什么话升、什么话降）、强度上限、恢复方式（时间、台阶、具体事）、对不同用户表达的反应（示弱/强硬/沉默分别怎样）。

### A5 情景模拟

现实背景（地点、时刻、前情）、人物关系（权力差、依赖关系）、冲突原因（表层/深层）、升级路径（3 步以内）、缓和路径（3 步以内）、分支点（在哪一轮分叉，分到哪）。

### A6 辅助回应

| 问题 | 记什么 |
|---|---|
| 如何理解用户意图 | 用户这句话是想拒绝、解释、拖延还是求认同 |
| 如何给不同语气 | 软/中/硬三档的差别在哪（用词、句长、是否给替代） |
| 如何避免标准答案腔 | 哪些词一出现就像客服/教科书 |
| 如何贴近现实 | 有没有保留用户原词、有没有具体到时间地点 |

### A7 心理安全

人物扮演边界（能演到什么程度）、敏感话题处理（自伤、暴力、性、医疗）、高风险退出（触发词、退出动作、去处）、对用户自主选择的尊重（不劝和、不劝分、不替决定）。

### A8 可复用方法

三条以内，每条写：**机制名 + 适用条件 + 不适用条件**。
例：“先接住再提请求”适用于权力差场景，不适用于对方已经越界的场景。

## 3. 拆解笔记格式

存 `RAW_RESEARCH/notes/<SRC-ID>.md`（Phase 3 建目录），骨架：

```markdown
# SRC-XXX-001 · 拆解

- 对应编号：FAM-001 / WRK-003
- 拆解人：ChatGPT
- 日期：
- 许可桶：research_only（只可提炼，不可复制）

## F 事实
- （逐条，带位置）

## A 分析
- （逐条，写推断依据）

## A1–A8 八维
（按第 2 节填，F/A 混排时逐句标注）

## O 可复用方法（候选）
1. 机制名：
   - 适用：
   - 不适用：
   - 验证方式：
```

## 4. Stage B：蒸馏成方法卡

### 4.1 三去

1. **去身份**：把“妈妈”换成“长辈”“领导”，机制还成立吗？
2. **去剧情**：去掉具体事件（催婚、裁员），只剩结构，还能用吗？
3. **去作品**：去掉原作的专有名词、金句、设定，不能有任何可识别痕迹。

三去之后仍成立的，才是方法；否则只是这个案例的细节。

### 4.2 三问

| 问题 | 不过关的信号 |
|---|---|
| 能跨情景用吗？ | 只能用在 FAM-001 |
| 能被验证吗？ | 无法设计对照或评估 |
| 安全吗？ | 依赖施压、羞辱、制造焦虑 |

### 4.3 方法卡模板

```markdown
# M-012 · 先接住再给具体安排

- 类型：情绪降级 / 边界表达 / 开场 / 分支 …
- 来源：SRC-RES-003（A）、SRC-GHB-007（A）
- 适用：对方以“担心”为外壳施压时
- 不适用：对方已经越界或正在威胁时
- 机制：先承认对方的担心（1 句）→ 给一个可执行的小安排（1 句）→ 留退路（半句）
- 反例：直接说“你别管”，或一口气解释三条理由
- 与现有提示词的关系：补充 `standInPrompt` 的“圆滑公式”，不替换
- 验证：用 10 条催婚/催生输入盲评“是否像人说的”
```

方法卡存 `docs/methods/`（Phase 4 建），编号 `M-001` 起。**方法卡不是提示词**，不直接进代码。

## 5. Stage C：原创语料生产（8 步）

以 `templates/scenario-template-v1.json` 为骨架，顺序不要乱。

| 步 | 做什么 | 对应字段 |
|---|---|---|
| 1 | 选题并认领编号（对照 `INDEX.json`） | `id` `category` |
| 2 | 写背景与一句话目标 | `basic` |
| 3 | 写人物身份、关系、权力差 | `counterpart` |
| 4 | 写表面诉求、深层动机、触发与降温 | `persona` |
| 5 | 写语言参数与口头禅 | `voice` |
| 6 | 写三档开场白与三档行为 | `opening` |
| 7 | 写 10 轮对话（对方 ↔ 用户表达示例） | `dialogue` |
| 8 | 写分支、情绪曲线、冲突强度、策略、安全 | `branches` `emotionalState` `conflict` `strategies` `safety` |

### 5.1 对话节奏模板（10 轮）

```text
1 对方试探（强度 2）
2 用户/替身接住 + 说节奏
3 对方追问（3）
4 用户说清立场
5 对方比较/施压（4）
6 用户不接比较
7 对方转成“担忧式逼问”（4）
8 用户承认担心 + 给具体安排
9 对方泄气/半信（2）
10 收尾（给一个可执行的小承诺，或允许今天不谈）
```

不是每条都要 10 轮，但**必须有升有降**；全程一个强度 = 没有情绪机制。

### 5.2 分支写法

至少 4 条，且至少一条 `leadsTo` 不是 `continue`：

- 一条 `deescalate`（用户接住了）；
- 一条 `escalate`（用户被带走）；
- 一条 `exit`（用户想停）；
- 可选 `continue`（话题平移）。

### 5.3 策略写法

2–4 条，每条必须有 `avoid`。没有 `avoid` 的策略等于“标准答案”，会退化成话术库。

## 6. 辅助回应专章

这是产品的核心交互（AI 演对方，用户点「辅助回应」拿一句自己的话）。规则如下。

### 6.0 先分清：求助 ≠ 辅助回应

| 维度 | 求助 | 辅助回应 |
|---|---|---|
| 产出 | 方向、策略、一句提示 | **一句**第一人称、可直接发送的表达 |
| 是否进输入框 | 不进 | **填入输入框** |
| 用户动作 | 看完自己想 | 可编辑、可重新生成、可不用 |
| 是否自动发送 | 否 | **否**（任何情况下都不得自动发送） |
| 语气档 | 不涉及 | 软 / 中 / 硬，对应 `strategies.intensity` |

两者**不得合并成同一个按钮或同一个接口**。求助回答“往哪个方向说”，辅助回应回答“这句话怎么说”。

### 6.1 输入

用户最近的 1–3 句 + 当前情景 + 对方最后一句话 + 用户想达到的目标（默认取 `opening.userGoalDefault`）。

### 6.2 输出

- **一句话**，最多两句；不列点、不加解释、不写“你可以这样说：”；
- 直接可发送，口语，保留用户原词（用户说过“稳一稳”，就别换成“从容”）；
- 一次给 1 个版本；用户点「换一句」时换**语气档**，不是同义改写。

### 6.3 三档语气（与 `strategies.intensity` 对齐）

| 档 | 特征 | 例（催婚） |
|---|---|---|
| soft | 先接住，少断言，留退路 | “我知道你着急。我这两年先把工作稳住，这事我在认真想。” |
| medium | 说事实 + 一个请求 | “我不是不想，是不想赶时间随便找。这个我得自己看准。” |
| firm | 说边界 + 给替代 | “今天先不聊这个了。明天我陪你去买菜。” |

### 6.4 禁止

- “你应该……”“你可以尝试……”（建议腔）；
- “我理解你的感受”“你的感受是合理的”（咨询腔）；
- 一次给三个选项；
- 替用户答应事情（“行，我明年就结”）；
- 编造用户没说过的经历；
- 超过两句、带书面连接词（“此外”“综上”）。

### 6.5 与语料的关系

`strategies[].example` 是**写作期的参考**，不是运行时直接返回的句子。运行时由模型基于策略现场生成，避免所有用户拿到同一句。

## 7. 写作规范（13 条）

1. 对方不是反派：写清他为什么只能这么说。
2. 允许没谈拢：不是每条都要“说服成功”。
3. 不替用户决定：不劝和、不劝分、不诊断。
4. 短句优先：一句里最多一个转折。
5. 具体优先：“明天陪你去买菜”优于“多陪陪家人”。
6. 不写创伤现场：暴力、性侵、自伤只走安全流程。
7. 不制造依赖：不写“只有我懂你”。
8. 不刻板：不写“女人都……”“老一辈都……”。
9. 不复述用户原话当回应（像复读机）。
10. 每轮只推进一个点，不一次解决三个问题。
11. 情绪要有曲线，强度要有升有降。
12. 引用外部资料必须能追到 `SRC-*`；连续 8 字以上不得与原文重合。
13. 按 **B 模式**写：`counterpart` 是 AI 扮演的那个人说的话；`user_stand_in` 是用户可能怎么回；不写“替你说”的替身口吻。

## 8. 自检与提审

### 8.1 作者自检（11 项，逐项打勾）

- [ ] 人物是否真实（有矛盾、有软肋）
- [ ] 对话是否自然（能读出声）
- [ ] 情绪变化是否合理（有触发、有恢复）
- [ ] 冲突发展是否符合现实（不靠巧合）
- [ ] 辅助回应是否实用（愿意说出口）
- [ ] 是否有刻板印象
- [ ] 是否尊重用户自主选择
- [ ] 安全机制是否可执行（退出有去处）
- [ ] 来源许可是否合规（能追到 `SRC-*`）
- [ ] 数据结构是否正确（校验器通过）
- [ ] **角色语义是否正确（B 模式：`counterpart` 是 AI 说的，`user_stand_in` 是用户可能说的，没有“替身”口吻）**

### 8.2 独立审核

按 `docs/05` 与审核单执行：五项 `pass`、至少一位非作者、`commercial_ok`、校验通过，才可移入 `PRODUCTION_APPROVED/`。
**作者不得自批；IDE 不得代替产品负责人签字。**

### 8.3 质量测试

- 结构：`validate-corpus.mjs`；
- 语言：朗读测试（读不顺就是不合格）；
- 盲评：同批 3 条混在一起，让非作者猜“哪条最像真的”；
- 安全：用固定 10 条高风险输入试退出流程；
- 角色语义：把 `dialogue` 按 B 读一遍，确认 `counterpart` 全是 AI 说的、`user_stand_in` 全是用户可能说的；
- 辅助回应：从 `strategies[].example` 出发改写 3 句，确认不像标准答案、可直接说出口。

## 9. 批次节奏

| 批次 | 数量 | 目标 |
|---|---|---|
| 试产 | 3 条（不同类目） | 打通流程，找问题 |
| 第二批 | 5 条 | 稳定质量，补齐 P0 |
| 之后 | 每批 ≤ 5 条 | 质量优先，不追数量 |

每批结束写 5 行复盘：最难写的字段、最常见的退回原因、下次改什么。

## 10. 版本与废弃

- 改台词：`1.0.1`；加分支/策略：`1.1.0`；改定位：`2.0.0` + 新文件；
- 下线：`deprecated`，移回 `ORIGINAL_CORPUS/`，`notes` 写原因；
- 不覆盖历史版本，不删除审核记录。
