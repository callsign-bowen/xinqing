## 1. 裁决要点（Mode B）

- 用户扮演现实中的自己；AI 扮演情景中的另一方。
- AI 依据人物设定、情景背景、用户实际回应、当前情绪动态生成下一轮。
- 「辅助回应」生成一句第一人称、可直接使用的表达，**填入输入框**；可编辑、可重生成、**不得自动发送**。
- 「求助」只给方向、策略、提示，不产出可发送的句子。
- 用户可随时结束并进入复盘。
- 不采用双模式；原角色反转仅作历史参考，不得作为默认方向。

## 3. 逐块语义对照

### 3.1 前端 `Scenario` 类型（`scenarios.ts`）

| 字段 | MVP 语义 | Mode B 语义 | 兼容性 |
|---|---|---|---|
| `counterpartRole` | 用户扮演的角色 | **AI 扮演的角色** | 值不变，语义对调 |
| `openings` | 对方的第一句话 | 同左（AI 的开场） | 完全兼容 |
| `styles` | 对方三档行为 | 同左（AI 的行为约束） | 完全兼容 |
| `avoid` | 对方禁区 | 同左（AI 不得越界） | 完全兼容 |
| `debriefFocus` | 复盘关注点 | 同左 | 完全兼容 |
| `context` / `goal` / `oneLine` | 背景与目标 | 同左 | 完全兼容 |

结论：`scenarios.ts` 的字段设计本来就站在“对方是一个角色”的角度，**比 MVP 的角色反转更贴合 B**。

### 3.3 `dialogue.turns` 的语义（重点）

在 Mode B 下：

| speaker | MVP 读法 | Mode B 正确读法 |
|---|---|---|
| `counterpart` | 用户打的“对方台词”（其实由用户扮演） | **AI 说的台词**（角色本人发言） |
| `user_stand_in` | AI 替用户说的版本 | **示例用户表达**：用户可能怎么说，供写作与辅助回应参考 |

结构完全一致（交替、对方先开口），只是**标签从“替身”改成“示例”**。
这也是为什么 Schema 不用改：`user_stand_in` 这个名字本身是中性的（“用户一侧的示范表达”），不是“AI 替身”。

**建议**：在 `docs/02` 与 `docs/10` 中把 `user_stand_in` 统一解释为“用户侧示例表达”，并在 Phase 5 写作规范里写明“不要按‘AI 替身’写，要按‘一个真实的人会怎么回’写”。**不改字段名**（改名会破坏 Schema 与已有文件）。

### 3.4 `strategies` 的语义

| 项 | Mode B 下的用途 |
|---|---|
| `when` | 什么时候用这个策略（意图 + 情境） |
| `example` | 辅助回应的**参考句**，不是直接返回给用户的固定句 |
| `avoid` | 反例：哪种接法会失败 |
| `intensity` | 对应辅助回应的软/中/硬三档 |

结论：`strategies` 天然就是“辅助回应的策略池”。**不需要新增字段**；运行时由模型基于策略生成，避免所有用户拿到同一句。

### 3.5 复盘引用对象（重点）

现状：

- `debriefPrompt()` 把对话按“用户演的X / AI替用户说”标注后交给模型；
- `parseDebrief()` 的兜底用 `lastStandInLine(messages)`，即 **assistant 消息**；
- 产品文档写“复盘只引用 AI 替用户说的原话”。

Mode B 必须改为：**引用用户实际发送的消息**（包括用户编辑过的辅助回应），并区分：

- 用户自己写的；
- 从辅助回应改出来的（可选，标注“在建议基础上改的”）。

这是语义层面的破坏性变化，但**不涉及 Schema**。

### 3.6 安全语义（重点）

| 机制 | 现状 | Mode B 应改为 |
|---|---|---|
| `riskOfText()` 作用对象 | 用户输入的“对方台词” | **用户自己的话**（更符合“用户在求助 / 在受伤害”） |
| AI 生成内容的风险 | 靠提示词约束 | 仍需提示词 + 输出兜底：AI 不得辱骂、威胁、施压到越界 |
| `safety.stopSignals` | 由用户扮演的对方说出 | 由用户说出，或由 AI 角色说出后触发退出 |
| “对方以死相逼” | 用户（扮演对方）说 | AI 角色说 → 必须退出角色、转安全流程 |
| 家暴 / 性侵 / 自伤 | 不角色扮演 | 不变，且更严格：AI 不得演出施害者 |

结论：`safety` 字段结构不用改，但**检测对象与“谁能说哪句话”必须重写**。这属于 Phase 7 的实现约束，本阶段只记录。

### 3.7 FAM-001 逐项检查

| 部分 | 在 Mode B 下 | 结论 |
|---|---|---|
| `opening.openings` | 妈妈的三档开场 | 直接可用 |
| `dialogue` 10 轮 | 妈妈 ↔ 女儿示例 | 直接可用；`user_stand_in` 改读作“女儿可能的回应” |
| `strategies[].example` | 女儿可说的一句话 | 正是辅助回应的参考 |
| `debriefFocus` | 是否说出打算 / 是否被“为你好”带走 | 直接可用 |
| `safety` | 高风险退出 | 结构可用，检测对象需按 3.6 调整 |
| `review.status` | draft | 不变 |

**FAM-001 不需要修改。** 唯一风险是：如果按 MVP 的“替身”去读它的 `dialogue`，会误以为那是 AI 要说的话；文档层面纠正即可。
