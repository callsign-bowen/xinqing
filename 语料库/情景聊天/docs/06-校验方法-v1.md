# 校验方法 v1

脚本：`scripts/validate-corpus.mjs`
依赖：**零依赖**，只用 Node 内置模块（建议 Node 20+，项目本身是 Node 24）。
不联网、不读 `.env`、不调用模型。

---

## 1. 怎么跑

```powershell
cd C:\Users\汪晨\Desktop\心晴
node "语料库\情景聊天\scripts\validate-corpus.mjs"
```

加 `--verbose` 看全部警告：

```powershell
node "语料库\情景聊天\scripts\validate-corpus.mjs" --verbose
```

退出码：`0` 通过；`1` 有错误（可直接用于 CI / pre-commit）。

## 3. 它到底查了什么

### 3.1 格式层

| 检查 | 说明 |
|---|---|
| JSON 可解析 | 所有 `.json` / `.jsonl`，失败直接报行号 |
| JSON Schema | 情景、来源、索引三个 schema，手写校验器支持 `$ref` / `type` / `enum` / `pattern` / `required` / `additionalProperties` 等 |
| 未知字段 | `additionalProperties: false`，写错字段名会报错，而不是被静默忽略 |

### 3.2 结构层

| 检查 | 说明 |
|---|---|
| 编号格式 | `^[A-Z]{3,4}-\d{3}$` |
| 编号与目录 | `FAM-001` 必须在 `FAM/` 下 |
| 编号与文件名 | 文件名必须以 `FAM-001-` 开头 |
| 编号与 INDEX | 必须登记，且 `file` / `status` / 类目三处一致 |
| 64 个编号位 | 8 类 × 8 个，序号连续、不重复 |
| 对话轮次 | 从第 1 轮开始连续递增，说话人交替，且由对方先开口 |
| 策略引用 | `turn.strategy` 必须指向已定义的 `S*` |
| 分支 | `afterTurn` 不超出总轮数；不能全是 `continue` |
| 冲突 | `initial <= peak` |
| 状态一致 | 顶层 `status` 必须等于 `review.status` |

### 3.3 许可与上线

| 检查 | 说明 |
|---|---|
| 来源可解析 | `sourceIds` 必须能在三个桶里查到 |
| 分桶正确 | 文件里的 `licenseClass` 必须与文件所在桶一致 |
| 商用证据 | 商用桶必须 `commercialUse` / `modification` 为 `true`、`verification` 为 `verified`、许可证不含 unknown / copyright / NC |
| 研究资料降级 | `research_only` 必须 `commercialUse: false`；`restricted` 还必须 `modification: false` |
| 未审不上线 | `PRODUCTION_APPROVED/` 里只能有 `approved`；`ORIGINAL_CORPUS/` 里不能有 `approved` |
| 上线门槛 | `approved` 需要五项全 `pass`、至少一位非作者审核人、`commercial_ok` |
| 交叉引用 | 标 `commercial_ok` 的语料不能引用研究/受限来源 |

### 3.4 安全层

| 检查 | 说明 |
|---|---|
| 密钥泄漏 | 扫描 `sk-` 长串、`AI_API_KEY=` 赋值、私钥头 |
| 文件覆盖 | 只读校验，不写任何文件 |

## 4. 常见报错怎么修

| 报错 | 原因 | 修法 |
|---|---|---|
| `缺少必填字段 safety` | 结构不完整 | 按 `templates/scenario-template-v1.json` 补齐 |
| `编号与目录不匹配` | 文件放错类目 | 移到 `ORIGINAL_CORPUS/<正确代码>/` |
| `引用了未登记的来源 SRC-XXX-001` | 来源没登记 | 在 `REFERENCE_LIBRARY` 对应桶加一行 |
| `语料标记为 commercial_ok，但引用了 research_only 来源` | 许可越级 | 换来源，或把语料降为 `draft` 并改 `licenseClass` |
| `approved 文件必须移到 PRODUCTION_APPROVED/` | 状态与位置不一致 | 移动文件，或把状态改回 `in_review` |
| `第 3 轮说话人应为 user_stand_in` | 对话没交替 | 调整 `dialogue.turns` |
| `疑似包含疑似 API Key` | 误把密钥写进语料 | 立刻删除，并从 Git 历史清理 |

## 5. 负向测试（已实测，证明它真的会拦）

把整个语料库复制到临时目录再改坏，四个用例都应退出码 1：

```powershell
$src = '语料库\情景聊天'
$tmp = Join-Path $env:TEMP 'corpus-selftest'
Copy-Item $src $tmp -Recurse -Force
$fam = Join-Path $tmp 'ORIGINAL_CORPUS\FAM\FAM-001-父母催婚-v1.json'

# A. 改错编号
(Get-Content $fam -Raw) -replace '"id": "FAM-001"', '"id": "WRK-001"' | Set-Content $fam -Encoding UTF8
node (Join-Path $tmp 'scripts\validate-corpus.mjs')
```

实测结果：

| 用例 | 改法 | 实际报错 | 退出码 |
|---|---|---|---|
| A 编号错配 | `id` 改成 `WRK-001` | 编号与目录不匹配 / 文件名必须以…开头 / INDEX 类目不一致 | 1 |
| B 缺安全字段 | 删掉 `safety` 块 | `缺少必填字段 safety` | 1 |
| C 许可越级 | 商用语料引用 `SRC-RES-001` | `语料标记为 commercial_ok，但引用了 research_only 来源` | 1 |
| D 密钥泄漏 | 放一个含假 Key 的 md | `检测到API Key 形态的字符串` / `检测到密钥赋值` | 1 |

B / C / D 的改法分别是：用 `ConvertFrom-Json` 删字段、改 `sources.sourceIds`、写一个含 `sk-` 假串的文本文件。

> 注意：临时副本里的 `CON` 目录问题已经不存在了——类目代码已从 `CON` 改为 `CNS`，因为 `CON` 是 Windows 保留设备名，复制和删除都会失败。这条是实测发现并修掉的。

## 6. 接到 CI / npm（建议，本次未改 package.json）

```json
"scripts": {
  "corpus:check": "node \"语料库/情景聊天/scripts/validate-corpus.mjs\""
}
```

建议**不要**塞进现有 `npm test`：语料校验是内容质量门，和前端单测失败原因不同，混在一起会让 `npm test` 变慢且难定位。单独一条命令、单独一个 CI step 更清楚。

## 7. 什么时候该跑

- 每次新增 / 修改情景文件后；
- 每次在 `REFERENCE_LIBRARY` 加来源后；
- 每次把文件移进 `PRODUCTION_APPROVED/` 之前（必须）；
- 提交前（可以自己加 pre-commit）。
