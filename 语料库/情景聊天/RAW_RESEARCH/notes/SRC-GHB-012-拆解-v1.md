## 2. F：来源明确支持的事实

- F1：数据集从**电视剧剧本**采集，对每条话语标注情绪与人际关系（README「Introduction」）。
- F2：规模为 **25,548 条话语、4,142 段对话**。
- F3：`dialogue.json` 的结构是“case index → 按说话顺序排列的话语列表”，每条话语包含 `speaker`、`utterance`、`listener` 列表、`emotion`。
- F4：`listener` 列表中的每一项含 `name` 与 `relation`；即**一条话语可以同时有多个听者**，并分别标注关系。
- F5：`metadata.json` 定义情绪、关系类型，以及 `position`（superior / peer / inferior）与 `field`（family / school / company / others）两个视角的子类。
- F6：关系类型包含 parent、teacher、boss、couple、child、spouse 等（README 示例，非完整列表）。
- F7：论文发表于 LREC 2020；实验观察“被回应话语对当前话语的影响”以及“情绪与关系类型的相关性”。

## 3. A：对资源设计方法的分析

- A1：MPDD 的核心贡献不是台词，而是**把“关系”做成每句话上的显式字段**：说话人 → 听者（可多个）→ 关系类型 → 权力位置。这比“整段对话写一个关系”精细得多。
- A2：`position`（上级/平级/下级）+ `field`（家庭/学校/公司/其他）构成**权力距离的两维建模**；本库 `counterpart.powerDistance` 目前是一句自然语言，MPDD 提供了可枚举的替代思路。
- A3：多听者设计对“多人场景”有价值（父母同时在场、家庭群聊），本库目前只支持单一人设，可作为二期扩展参考。
- A4：情绪与关系**同时标注**，说明同一句话在不同关系里含义不同；这支持“先定关系，再定情绪”的写作顺序。
- A5：README 未给出标注者数量、一致性指标与标注手册；质量只能作为待核项。
- A6：多党对话（multi-party）意味着轮流发言不严格交替，与本库 `dialogue.turns` 的“对方↔用户交替”不完全一致；迁移时要简化。

## 4. O：对本产品的原创借鉴建议

- O1：把 `counterpart.powerDistance` 从自由文本升级为**三档结构化写法**（上级/平级/下级 + 一句解释），但不改 Schema——写进写作规范与方法卡。
- O2：在 `persona.triggers` 里区分“对上级说”和“对平级说”的触发差异，避免一套话术打天下。
- O3：为多人场景预留“听者集合”的概念；一期仍单角色，二期再评估是否扩展 Schema。
- O4：写作时先写“关系 + 权力”，再写“这句话的情绪”，最后写“这句在做什么”（对应 CPED 的 DA）；顺序反过来容易写出“没有对象的情绪”。
- O5：**不**从 MPDD 学台词；只学关系建模与权力距离。

## 5. 八维拆解

### A1 人物设定

- F：人物以 speaker / listener 的姓名出现，关系类型显式标注。
- A：人物只有“关系位置”，没有性格与语言习惯；适合做关系网络，不适合做 persona。
- O：本库 `counterpart` 可借“关系 + 权力位置”，`persona` 仍需自写。

### A2 语言风格

- F：无语言风格标注；台词来自电视剧。
- A：无法从 MPDD 推出句长、口头禅、称呼习惯。
- O：风格仍靠 `voice` 手写，不能指望数据集给。

### A3 对话机制

- F：按说话顺序记录，支持多听者；没有分支或回应规则。
- A：它能告诉你“谁对谁说”，不能告诉你“下一句该怎么接”。
- O：把“对谁说”写进 `branches.condition`，例如“当妈妈当着亲戚的面说”。

### A4 情绪机制

- F：逐话语情绪标签；论文分析情绪与关系的相关性。
- A：关系影响情绪解释，但数据没有“情绪如何升级”的规则。
- O：`emotionalState` 的升降条件要写“在谁面前、被哪句话触发”，而不是只有强度数字。

### A5 情景模拟

- F：`field` 提供家庭/学校/公司/其他四类场景域。
- A：场景域比 CPED 的 11 类地点更粗，但更贴近“关系场”。
- O：本库分类（FAM/WRK/REL…）与 `field` 可做一级映射，用于检索。

### A6 辅助回应

- F：无辅助回应或建议生成任务。
- A：与产品核心交互无直接对应。
- O：只能借用“关系决定语气”的原则，不能借用生成方法。

### A7 心理安全

- F：无安全标注或风险处理。
- A：电视剧冲突可能含辱骂、威胁；数据本身不区分“可演练”与“不可演练”。
- O：安全边界必须由本库 `safety` 独立定义。

### A8 可复用方法

- F：关系类型 + 权力位置 + 多听者 + 情绪。
- A：可复用的是“关系建模”，不是“对话内容”。
- O：落成两张方法卡（见第 10 节）。

## 6. 值得吸收的设计方法

| 方法 | 解决什么 | 风险 |
|---|---|---|
| 关系 + 权力位置两维 | 说话分寸有依据 | 三档过粗，需一句解释补足 |
| 听者集合 | 多人场景不丢人 | 本库一期单角色，暂不实现 |
| 情绪与关系联合标注 | 同一句话在不同关系里含义不同 | 易过度解释，需作者判断 |
| “被回应话语”作为上下文 | 接话要接住上一句 | 数据未公开该字段细节，待核 |

## 7. 不适合直接迁移的部分

1. **电视剧台词**：无许可、非自然口语。
2. **多党轮流结构**：与本库“对方↔用户”交替模型不一致。
3. **关系类型枚举**：家庭/学校/公司/其他过粗，无法覆盖 64 编号的子类。
4. **情绪标签**：没有强度与转移，不能当状态机。

## 9. 与现有产品架构的衔接

| 本库字段 | MPDD 对应 | 衔接方式 |
|---|---|---|
| `counterpart.relation` | `relation` | 直接参考，补“关系类型”枚举 |
| `counterpart.powerDistance` | `position` + `field` | 三档 + 一句解释 |
| `persona.triggers` | 情绪 × 关系 | 触发点写清“在谁面前” |
| `branches.condition` | 听者集合 | 多人场景的分支条件 |
| `dialogue.turns` | 多党发言 | 一期仍交替，二期再评估 |

- 与 C-001 方案 B 的关系：AI 扮演对方时，“对谁说、什么关系”决定称呼与语气；MPDD 的关系建模可直接支撑 `counterpart` 的写作质量。
- 检索键：`category` + `relation` + 权力档；本阶段不实现。
