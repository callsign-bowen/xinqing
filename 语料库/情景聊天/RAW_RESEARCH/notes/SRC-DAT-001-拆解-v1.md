## 2. F：来源明确支持的事实

- F1：语料为**日英商务对话平行语料**，构建分三步：选商务场景 → 按场景写单语对话脚本 → 译成另一语言（README「Corpus Description」）。
- F2：构建过程由具备商务沟通经验的人监督，以保证对话自然。
- F3：训练集 670 段情景 / 20,000 句，开发集 69 段 / 2,051 句，评测集 69 段 / 2,120 句（README 统计表）。
- F4：仓库公开开发集与评测集全文，训练集只公开一部分。
- F5：场景标签（tag）包含 **face-to-face、phone call、general chatting、meeting、training、presentation** 六类。
- F6：JSON 以“文档”为单位，每条文档含 `id`、`tag`、`title`、`original_language`、`conversation` 数组；数组每项含 `no`、`en_speaker`、`ja_speaker`、`en_sentence`、`ja_sentence`（README「Corpus Structure」示例结构）。
- F7：README 声明数据以 **CC BY-NC-SA 4.0** 发布；manythings 分发页同样写明 “License: CC BY-NC-SA”，版权属东京大学。
- F8：manythings 页注明共 808 段对话、约 24,000 句，并说明做过若干订正、尚未完成全部校对。

## 3. A：对资源设计方法的分析

- A1：这是**翻译平行语料**，不是自然发生的对话录音；语句为“写出来再翻译”，因此比真实口语更完整、更礼貌。
- A2：`tag` 是场景类型而非冲突类型：face-to-face / phone / meeting 等描述“怎么谈”，不描述“为什么难谈”。
- A3：每条对话有 `title`（如 “Training: How to do research”），标题承担了“这场谈话在做什么”的功能，可直接借鉴为 `basic.title` 的写法。
- A4：说话人以姓名标注（`en_speaker` / `ja_speaker`），可追踪“谁在说”；但同一个人在不同对话里不连续，没有人设。
- A5：日语侧含敬语层级，英语侧相对中性；这提醒我们：**同一场景在不同语言里的礼貌策略不同**，不能直接搬中文。
- A6：语料没有情绪、冲突强度、分支或安全标注；它擅长“场景 + 结构”，不擅长“情绪 + 动态”。
- A7：CC BY-NC-SA 的 SA 条款要求衍生作品相同方式共享，对产品化极不友好；只能做结构参考。

## 4. O：对本产品的原创借鉴建议

- O1：借“文档级 JSON”组织方式：一个情景一个文件，顶层放 `id` / `category` / `title` / `language` / `turns`，与本库现有 Schema 一致，不需要改结构。
- O2：借六类场景标签，做职场子类的**二级标签**（面谈 / 电话 / 会议 / 培训 / 演示 / 闲聊），用于检索与选题覆盖检查。
- O3：借 `title` 的写法——“场景类型：这件事在做什么”，让 `basic.title` 一眼能懂。
- O4：借“说话人显式标注”的做法，在 `dialogue.turns` 中始终写清 speaker，不靠上下文猜。
- O5：**不**借语言：日语敬语与英语商务套话都不能直接转成中文家庭/职场表达。

## 5. 八维拆解

### A1 人物设定

- F：有说话人姓名，无性格、动机、关系描述。
- A：人物是“功能位”（经理、客户、新人），不是 persona。
- O：本库 `counterpart` 已足够；BSD 只能提供“角色称谓”的命名参考。

### A2 语言风格

- F：商务场景、书面化程度较高；日英对照。
- A：适合学“礼貌层级”，不适合学“中文口语节奏”。
- O：可提炼“请求—缓冲—理由—落点”的商务句式结构，但要用中文重写。

### A3 对话机制

- F：按 `conversation` 数组顺序推进，有 `no` 编号。
- A：线性对话，没有分支；没有“对方不配合”的情况。
- O：本库 `branches` 要自行设计，不能从 BSD 获得。

### A4 情绪机制

- F：无情绪标注。
- A：商务语料默认“合作前提”，冲突强度低。
- O：情绪曲线仍靠 `emotionalState` 手写。

### A5 情景模拟

- F：六类场景标签 + 标题 + 完整多轮对话。
- A：场景覆盖广（会议、电话、演示、培训），但都是“顺利完成”的对话。
- O：可用于检查 WRK 子类覆盖是否漏掉“电话/会议”这类形态。

### A6 辅助回应

- F：无建议或辅助回应机制。
- A：无对应。
- O：不借鉴。

### A7 心理安全

- F：无安全标注。
- A：商务语料风险低，但也不提供冲突处理范例。
- O：安全仍以本库 `safety` 为准。

### A8 可复用方法

- F：文档级 JSON、场景标签、标题、说话人字段。
- A：可复用的是**数据组织**与**场景分类**。
- O：落成两张方法卡（见第 10 节）。

## 6. 值得吸收的设计方法

| 方法 | 解决什么 | 风险 |
|---|---|---|
| 文档级 JSON（id/tag/title/language/conversation） | 一情景一文件、可检索 | 容易只学格式不学内容 |
| 六类场景标签 | 检查场景形态覆盖 | 标签描述“怎么谈”，不描述“为什么难” |
| 标题写法“场景：做什么” | 用户一眼看懂 | 中文标题要更口语 |
| 说话人显式标注 | 多轮不混淆 | 本库已具备，无需新增 |

## 7. 不适合直接迁移的部分

1. **原始对话与译文**：CC BY-NC-SA，不能进产品，也不能改写后进产品。
2. **日语敬语 / 英语商务套话**：文化与语言差异大，直接迁移会“翻译腔”。
3. **无冲突的线性对话**：缺少施压、拒绝、打断，不能作为演练脚本。
4. **翻译语料的“完整句”**：真实口语更碎，不能照搬句长。

## 8. 版权、许可与第三方风险

- CC BY-NC-SA 4.0 已核实（仓库 README + manythings 页面）；**NC 禁止商业使用，SA 要求衍生作品同许可**。
