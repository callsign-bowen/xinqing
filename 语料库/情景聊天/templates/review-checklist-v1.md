# 语料审核单 v1

> 用途：任何一条情景语料从 `draft` 走到 `approved`，都要过这五关。
> 五关不是打分，是**一票否决**：任何一项 `fail`，就不进 `PRODUCTION_APPROVED`。

---

## 0. 基本信息

| 字段 | 填写 |
|---|---|
| 情景编号 | 例：FAM-001 |
| 版本 | 例：1.0.0 |
| 文件 | `ORIGINAL_CORPUS/FAM/FAM-001-父母催婚-v1.json` |
| 作者 | |
| 审核人（非作者） | |
| 审核日期 | |
| 数据来源 | `original` / `adapted` / `licensed`，附 sourceIds |

## 1. 五关

### 1.1 安全（safety）

| 检查 | 通过标准 |
|---|---|
| 是否出现自伤、自杀、家暴、性侵、虐待细节 | 一处都不允许；这类情境只能走 `route: no_roleplay` 或 `high_risk_protocol` |
| “难缠”档是否只到施压、打断、否定、转移责任 | 不出现辱骂、威胁、断绝关系、拿病或死施压 |
| `safety.exitConditions` 是否可执行 | 至少 2 条，且都是用户能直接触发的话 |
| `hardStop` 是否覆盖最危险的情况 | 正在发生的暴力、人身威胁、自伤计划必须在内 |
| 退出后是否有去处 | `exitLine` + `afterExit` 写清热线 / 报警 / 转介，不能只说“退出” |
| 是否鼓励对抗 | 目标必须是“说清 / 守住边界”，不是“吵赢” |

判 `fail` 的例子：把家暴写成“他只是脾气急”；让 AI 演一个正在施暴的人；用“我死了你就满意了”当施压台词。

### 1.2 许可（license）

| 检查 | 通过标准 |
|---|---|
| `sources.sourceIds` 是否都能在 `REFERENCE_LIBRARY` 查到 | 查不到就是 `fail` |
| 引用了 `research_only` / `restricted` 的资料吗 | 可以有，但产物必须是重新写作，不得整段复制 |
| `licenseClass` 与来源桶是否一致 | `commercial_ok` 只能引用 `commercial_ok` 桶 |
| 是否出现整段原文 | 影视字幕、论坛原帖、书籍段落一律不得逐字搬入 |
| 商用与修改权限 | 进 `PRODUCTION_APPROVED` 必须 `commercialUse: true` 且 `modification: true` |

判 `fail` 的例子：把知乎回答整段贴进 `dialogue.turns`；来源许可证写“未知”，却标 `commercial_ok`。

### 1.3 语言（language）

| 检查 | 通过标准 |
|---|---|
| 像不像这个人会说的话 | 用词、句长、口头禅与 `voice` 一致 |
| 能不能直接说出口 | 替身示例 ≤ 3 句、无书面语、无“首先其次最后” |
| 有没有心理咨询腔 | 不出现“你的感受是合理的”“允许自己”这类模板句 |
| 有没有替用户加戏 | 不编造用户没说过的经历、关系、期限 |
| 有没有把话说太满 | 允许这次没谈拢；不承诺“练完他就会答应” |

### 1.4 真实感（realism）

| 检查 | 通过标准 |
|---|---|
| 对方是不是一个具体的人 | 有身份、关系、权力差、此刻的处境 |
| 压力是不是来自“在意”而不是“恶意” | 大多数日常冲突里，对方不是反派 |
| 难度三档是否有区分 | 温和只转移一次话题；真实会打断、给模糊承诺；难缠会施压但不越界 |
| 分支是否真的会分叉 | 至少一条 `leadsTo` 不是 `continue` |
| 是否只有一种“标准答案” | 策略 ≥ 2 条，且 `avoid` 写清另一种错误接法 |

### 1.5 偏见（bias）

| 检查 | 通过标准 |
|---|---|
| 有没有把某一性别、年龄、地域、职业写成刻板印象 | 不写“女人就是……”“老一辈都……” |
| 有没有暗示“忍一忍就过去了” | 不美化控制、冷暴力、经济索取 |
| 有没有把“和解”当成唯一正确结局 | 允许用户选择不原谅、不断绝，也允许暂时不处理 |
| 有没有制造依赖 | 不写“只有我懂你”“你只有在这里才安全” |
| 有没有替用户做人生决定 | 只给选项和判断标准，选择权在用户 |

## 2. 状态流转

```text
reserved → outline → draft → in_review → approved
                                 ↓
                            rejected / blocked
approved → deprecated（内容过期、被替换）
```

| 状态 | 含义 | 谁能改 |
|---|---|---|
| `reserved` | 只有编号，没有内容 | 任何人 |
| `outline` | 只有标题、目标、风险等级 | 作者 |
| `draft` | 有完整结构，未过审 | 作者 |
| `in_review` | 已提交，等待非作者复核 | 作者提交，审核人处理 |
| `approved` | 五关全过，进入 `PRODUCTION_APPROVED` | 审核人 |
| `rejected` | 明确不采用，保留记录 | 审核人 |
| `blocked` | 高风险，必须过安全评审才能开写 | 审核人 |
| `deprecated` | 曾上线，现已下线 | 审核人 |

---

## 3. 进正式库的门槛

一条语料要进 `PRODUCTION_APPROVED`，必须同时满足：

1. `review.status === "approved"`；
2. `checklist` 五项全部 `pass`；
3. `reviewers` 里至少有一个 `role` 不是 `author` 的人；
4. `sources.licenseClass === "commercial_ok"`，或 `origin === "original"` 且自有版权；
5. 文件名与 `id` 一致，且在 `INDEX.json` 里的状态也是 `approved`；
6. 校验脚本 `validate-corpus.mjs` 通过。

少一条就不许进。**“先上线再说”不是理由。**

---

## 4. 复审

| 触发条件 | 动作 |
|---|---|
| 语料上线满 6 个月 | 复审一次，看是否仍符合产品口径 |
| 新增了外部来源 | 重新过 1.2 许可 |
| 用户反馈“这句话说不出口” | 回到 `draft`，改语言 |
| 出现安全事故 | 立即 `deprecated`，全量排查同类情境 |
